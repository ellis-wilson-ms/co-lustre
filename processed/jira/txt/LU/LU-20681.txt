--- Description ---
A client hung for 26h with 75 CPUs spinning in __d_lookup() on a dcache bucket corrupted into a self-loop (d_hash.next == &self); RCU then stalls and wedges umount/lsof, forcing a reboot.

Such a self-loop can only arise one way: hashing a dentry that is already the head of its bucket (__d_rehash does n->next = bucket->first while bucket->first == &n). Every dcache inserter in the kernel guards against this (d_splice_alias BUG_ONs, __d_move drops before rehashing), and a full drgn census (2.3M dentries, 33M buckets) found exactly one self-loop and no other damage. The sole inserter missing a d_unhashed() check is d_add() in

ll_splice_alias() (llite/namei.c): the comment above it still states the invariant, but the check was removed by LU-8371 (2016), making it an unstated precondition on every caller. No other path can create this corruption.

 

crash> struct dentry.d_hash 0xff38e06f48239bc0
  d_hash = {
    next = 0xff38e06f48239bc8, // The next is self...
    pprev = 0x0
  },
crash> struct dentry.d_hash -x
struct dentry {
   [0x8] struct hlist_bl_node d_hash;
}
