--- Description ---
In `ldlm_process_flock_lock()`, when a lock split is required during a partial

unlock operation and `ldlm_lock_create()` fails, the code returns without

calling `unlock_res_and_lock(req)`. This leaves the resource lock held

indefinitely, causing a server deadlock.

--- Comment (JIRAUSER19474, Wed, 8 Jul 2026 21:18:11 +0000) ---
Code Analysis

In `lustre/ldlm/ldlm_flock.c`, the lock split code path:

if (new2 == NULL) {

    unlock_res_and_lock(req);           // Release lock for allocation

    new2 = ldlm_lock_create(...);       // May fail with -ENOMEM

    lock_res_and_lock(req);             // Re-acquire lock

    if (IS_ERR(new2)) 

{

        ldlm_flock_destroy(req, lock->l_granted_mode, *flags);

        *err = PTR_ERR(new2);

        RETURN(LDLM_ITER_STOP);         // BUG: Returns with lock held!

    }

    goto reprocess;

}

This occurs when:

1. A process holds a byte-range flock (e.g., bytes 0-999)

2. It unlocks a middle portion (e.g., bytes 100-199)

3. Server needs to split the lock into two separate locks

4. `ldlm_lock_create()` fails due to memory pressure (-ENOMEM)

5. Error path returns without releasing the resource lock
