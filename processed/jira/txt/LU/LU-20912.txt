--- Description ---
LFSCK repairs a dangling LOV-EA reference by creating an all-zero OST object. This is wrong for EC components:

1. Missing data stripe: the object then "exists" and reads as zeros, so the client's read-time EC recovery is never triggered,

    but if left absent, the read fails and EC reconstructs the real data from parity.

2. Missing parity stripe: all-zero is an invalid parity value and corrupts later recovery.

 For any EC component, do not create the missing object and leave a missing data stripe absent (let CIT_EC_RD recover it);

for a missing parity stripe set LCME_FL_STALE so lfs mirror resync recomputes it. If lost stripes in a raid set exceed cstripe_count, report only.  LFSCK must not do the data reconstruction itself (metadata-only). Non-EC files keep the current zero-fill behavior.
