AI analysis

The trace shows that np.save() writes the 128-byte .npy header and then hybrid I/O switches the following large write to unaligned DIO. Lustre attempts to allocate a single unaligned DIO buffer for 959,995,904 bytes (14,649 64K pages). obd_pool_get_pages_array() rejects this request with -EINVAL because it exceeds the maximum number of objects allowed in the OBD page pool.

The existing drain-and-retry logic only handles -ENOMEM after in-flight sub-DIOs have consumed the pool. It is not reached for this oversized single allocation, which fails immediately with -EINVAL.

Conclusion: the LU-19536 fixes remove the kernel crash, but they do not yet make the original large unaligned hybrid-DIO NumPy write succeed on an aarch64/64K-page client. A further fix is needed to split or cap each unaligned DIO sub-request to the OBD page-pool maximum, allowing the drain-and-retry path to make progress.
