--- Comment (green, Thu, 23 Jul 2026 06:39:14 +0000) ---
I think this python regexp stuff is terribly fragile and might create more problems than it solves.

--- Comment (stancheff, Fri, 24 Jul 2026 10:36:04 +0000) ---
I am a bit biased.

The Linux kernel headers are very stable, however ports done by distros can be a bit more random (functions converting to #define macros when porting patches, rhel9 for example has a few cases of this). Once done those ports are also quite stable. There is general pushback against trivial changes which helps keep things stable.

Both the build snippet checks with configure and the regex checking python snippets have weaknesses.

The configure compile checks are slower and bit harder to debug, although the parallel version is a bit easier to iterate over quickly now with PARALLEL_BUILD_OPT=debug.

Some of the regex style checks got a little sloppy (I just did builds against everything to be satisfied that they were working but that probably is not enough to catch some dumb errors)

I think maybe adding more detail into the final config header and/or output during configure will help catch unexpected behaviour such as failed matches and/or incorrect matches.
