--- Comment (JIRAUSER19208, Sat, 10 Oct 2026 16:21:29 +0000) ---
I reproduced this on 2.17.59 over TCP. No restart needed, so this doesn't seem specific to o2ib.

The exported UDSP rule is:

 

udsp:
  - idx: 0
    src: tcp
    action:
      priority: 0

Repro with no existing UDSP rules, using the unpatched binary:

 

sudo lnetctl udsp add --src tcp --priority 0
sudo lnetctl export --backup /tmp/lu-20683-prio0.yaml
sed -n '/^udsp:/,$p' /tmp/lu-20683-prio0.yaml > /tmp/lu-20683-udsp0.yaml
sudo lnetctl udsp del --idx 0

sudo lnetctl import /tmp/lu-20683-udsp0.yaml; printf 'import rc=%s\n' "$?"
# Output: import rc=234

sed 's/priority: 0/priority: 1/' /tmp/lu-20683-udsp0.yaml > /tmp/lu-20683-udsp1.yaml
sudo lnetctl import /tmp/lu-20683-udsp1.yaml; printf 'import rc=%s\n' "$?"
# Output: import rc=0

sudo lnetctl udsp del --idx 0

Changing only the priority to 1 works. The same priority-0 file also imports fine with --old-api, and adding priority 0 directly works.

Looking at handle_udsp_sequences() in lnet/utils/lnetctl.c:4761, this seems to be the problem:

 

prio ? "priority" : ""

Since prio is numeric here, 0 passes an empty action type to lustre_lnet_add_udsp(), which rejects it.

I changed it locally to:

prio != -1 ? "priority" : ""

Rebuilt and tested src/dst rules with both TCP network and NID selectors, at priorities 0 and 1. All eight cases passed: add, show, delete, import, then compare the restored rule.

I've also extended sanity-lnet test 403 locally, but haven't run the full harness yet. Nothing submitted to Gerrit at this point.
