--- Description ---
Currently 'lfs project' only prints the project id followed by the file name, it could be useful to print the project name instead of the id (if available, otherwise still print the numeric projid).  A new "-n" option can print the numeric value in all cases, similar to "ls -ln".  Something like:

$ lfs project -p quota_usr /mnt/lfs1/tfile 
$ lfs project /mnt/lfs1/tfile 
quota_prj - /mnt/lfs1/tfile
$ lfs project -n /mnt/lfs1/tfile 
1000 - /mnt/lfs1/tfile

--- Comment (adilger, Wed, 15 Jan 2025 18:58:34 +0000) ---
For commands like "ls" they will default to printing the name, if it can be looked up, and print the number of the lookup fails.  "ls -n" will only print the number, for cases where that is important, or if the name lookup is slow/broken (eg. using a network LDAP database that is overloaded or offline).

I think "lfs quota" is doing the same (prefer name, fall back to number).

--- Comment (adilger, Mon, 4 May 2026 19:59:20 +0000) ---
I was wondering about that as well, but if lfs project is printing out the project name, then it should also accept the project name as input to the various commands (lfs project, lfs quota, lfs find, etc.) so I think it should be OK.  Printing out both the number and the name is definitely going to cause problems.  Also, it will only print the name if /etc/projid contains the name:number mapping, which will not be true for most systems, so the transition will be gradual and under the control of the sysadmin.
