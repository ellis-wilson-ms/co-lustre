--- Description ---
manipulations with ldiskfs's orphan list are found to be tricky with number of drawbacks and complications (e.g. a single inode can be represented by few LU objects in a corner case and then discarding preallocated blocks becomes a problem).

Andreas suggested to use fallocate and unwritten extents to get rid of this complexity.

I made a prototype which allocates few blocks as an unwritten extent, then call ldiskfs_bread() to convert a block into a regular one.

so here is a  benchmark:

 256K 32-byte records are appended in 6 threads (real cores), each write is measured in usec – this was repeated 10 times for every "approach".

1) good old getblk, no optimizations: 6.3 usec / write

2) brm : 2.8 usec / write – 2x improvement

3) brm + fallocate : 1.5 usec / write – 4x improvement

4) brm + current prealloc: 0.8 usec / write – almost 8x improvement

terms:

	brm is a 4-slots cache telling whether specific block is allocated or not, if block is allocated, then we can omit per-object semaphore (which is to protect extent tree manipulations).

	line #4 is for current master: ldiskfs_map_blocks(), orphan list, late i_size and all the problems observed so far.

the most significant improvement is brought by brm. so probably brm + unwritten extents is good enough for a while (4x improvement)
