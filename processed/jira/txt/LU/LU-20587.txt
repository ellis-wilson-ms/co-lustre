--- Comment (JIRAUSER19323, Thu, 13 Aug 2026 12:38:38 +0000) ---
Root cause:

The LNET_CMD_PEERS generic-netlink dump handler serializes each peer and peer-NI into nested netlink attributes. For lnetctl peer show -v 2, each peer-NI includes credits, aggregate statistics, send/receive/drop statistics, and health statistics. When the current generic-netlink reply skb has insufficient remaining space, nla_nest_start() returns NULL. lnet_peer_ni_show_dump() does not check every nla_nest_start() result before subsequently calling nla_nest_end().

The original faulting instruction was mapped to the equivalent of:

nla_nest_end(msg, peer_nid);

where peer_nid was returned by:

struct nlattr *peer_nid = nla_nest_start(msg, count++);

nla_nest_end() writes start->nla_len; therefore, when peer_nid == NULL, it performs a NULL-pointer write and causes the oops.

The issue is capacity-dependent. It is encountered while dumping a large all-peer verbose response, rather than during Lustre file I/O or LNet transport communication.

Introduction:

This generic-netlink peer information path was introduced by:

{{LU-9680 lnet: collect data about peer_ni by using Netlink

commit f0be00678cc8005ec122fa1982d3aa432f6e3cbd}}

LU-9680 added lnet_peer_ni_show_dump() and the LNET_CMD_PEERS generic-netlink dump operation used by modern lnetctl peer show.

The path is absent from upstream 2.15.8, but present in upstream 2.15.90 and 2.17.x/2.16.x
