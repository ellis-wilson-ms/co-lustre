--- Comment (adilger, Wed, 23 Sep 2026 10:49:48 +0000) ---
Root cause: patch https://review.whamcloud.com/60202 ("LU-19139 lnet: add accept_port_bulk module parameter") (commit ce7611a495, v2_16_57-74) added accept_port_bulk with a fixed default of 988 that does not follow accept_port. Autotest sets accept_port=7988, so a master client connects its socklnd BULK_IN/BULK_OUT sockets to port 988, which 2.15/2.16 servers never listen on. The client silently runs with only a CONTROL conn to each server. Patch https://review.whamcloud.com/63266 ("LU-19763 socklnd: Check sendpage_ok for ZC") (commit bf67df3212, v2_17_50-65) then enabled zero-copy for >=16KiB sends on VMs; the server must send the ZC-ACK on its BULK_IN conn (the client's BULK_OUT, since nonblk_zcack=1), which doesn't exist, so ksocknal_launch_packet() fails with -EHOSTUNREACH, all conns to the client are closed, and the client is evicted. LU-19763 is only the trigger; reverting it (patch https://review.whamcloud.com/65658 ("LU-20213 dbg: revert patch")), or restoring the VM zc_min_payload default (patch https://review.whamcloud.com/69014 ("LU-20770 dbg: disable socklnd zero-copy for 2.16 interop test")), hides the problem but the client still has no bulk conns.

Evidence, from sanity test_27cg https://testing.whamcloud.com/test_sets/df2265f8-c35f-4596-9a0c-b53345f620b8 (client 2.17.56.51, servers 2.16.1.2), subtest debug logs:

(The console "Connection to ... at host 10.240.26.124:7988 was refused" message is misleading: lnet_connect() prints the control port, but the refused connect was to 988.)

b2_17/master servers open a second listener on 988 whenever accept_port_bulk != accept_port (lnet_acceptor_add_sockets()), so the client's bulk connects succeed there.

Same failure also seen as OST bulk evictions (server_bulk_callback() event type 3, status -113) in sanity-pfl test_0a, and in sanity-pfl test_16b (see also LU-20673, LU-19868, LU-20213). Sites using the default accept_port=988 are not affected, since both ports are then the same.

Fix (patch to follow): default accept_port_bulk to accept_port, and retry a refused bulk connect on accept_port for older peers. Workaround until then: options lnet accept_port_bulk=7988 on master nodes in interop testing.
