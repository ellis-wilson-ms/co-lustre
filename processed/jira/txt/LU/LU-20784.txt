--- Description ---
sanity test_154C failed on el8.10 ldiskfs DNE in its cleanup stack_trap, not

in the fid2path lookup it tests.

Failure message:

  Delete is not completed in 83 seconds

  test_154C returned 1

Both fid2path lookups had already returned the expected path:

  ost_fid=0x30000040b:0x3f2:0x0 with outpath=/mnt/lustre/f154C.sanity

  ost_fid=0x34000040b:0x1f1:0x0 with outpath=/mnt/lustre/f154C.sanity

The test then runs stack_trap "rm -rf $tf; wait_delete_completed".

wait_delete_completed_mds() polled osc.MDT.sync_* for 83 seconds and gave

up with one osc still syncing:

  osc.lustre-OST0007-osc-MDT0000.sync_in_progress=1

Every other osc had sync_changes=0 and sync_in_flight=0. No crash, LBUG or

Lustre error appeared on any node console during the test.

Test session: https://testing.whamcloud.com/test_sessions/54deafed-c3a0-49b8-9762-1109f4dd5524

Test set: https://testing.whamcloud.com/test_sets/3f7e81a0-01b8-4fcf-a484-ec3c2adbc063

clients and servers: https://build.whamcloud.com/job/lustre-reviews/131931 - el8.10 x86_64

Evidence that this is not caused by the change under test (review 68763,

"LU-20724 tests: add fsx burst mode for multiple mounts"):

	The change touches only lustre/tests/fsx.c and lustre/tests/sanityn.sh.

  Every new fsx.c code path is gated on the new "-I burst" policy; sanity's

  only fsx call (test_150id) passes a single path and the default policy,

  and test_154C does not use fsx at all.

	The same build passed the same test group, sanity included, on el9.8

  (https://testing.whamcloud.com/test_sessions/c589e8f3-bb4e-4b85-8ba0-26bad779984c)

  and on aarch64

  (https://testing.whamcloud.com/test_sessions/9ec09283-3b8f-4bc8-b13c-76371668dcf8).

	sanity test_154C was run 10 times on a 2 MDT / 4 OST ldiskfs DNE VM with

  this change built and mounted: 10/10 PASS.

	Maloo test history for test_154C on lustre-reviews over the last 60 days:

  32 PASS, 1 FAIL, the failure being this one.

A wait_delete_completed timeout is a known failure mode on other subtests –

LU-17106 (sanity test_59), LU-19785 (sanity test_24A), LU-15386 (sanity

test_150bb) – but no ticket covers test_154C.
