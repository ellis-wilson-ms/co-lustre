--- Description ---
sanity test_65n saves the default LMV of the filesystem root directory by its stripe count, index and hash type, and restores it at exit with a stack_trap.  Since LU-13417 ("mdd: set default LMV on ROOT"), MDT0000 sets a default LMV on ROOT with no hash type:

lmv_stripe_count: 1 lmv_stripe_offset: -1 lmv_hash_type: none lmv_max_inherit: -1 lmv_max_inherit_rr: 3

Because the hash type is "none", test_65n takes its "no default LMV" branch and runs "lfs setdirstripe -D -d $MOUNT", which deletes the ROOT default LMV instead of restoring it.  After test_65n the root directory shows:

lmv_stripe_count: 0 lmv_stripe_offset: -1 lmv_hash_type: none lmv_max_inherit: -1 lmv_max_inherit_rr: 0

Later subtests no longer get new directories spread over the MDTs by max-inherit-rr.  sanity test_413d ("inherit ROOT default LMV") then fails on a DNE system when run after test_65n:

sanity test_413d: @@@@@@ FAIL: 400 subdirs on MDT0

This is reproducible on a single-node 4-MDT test system with "ONLY='65n 413d' sanity.sh"; test_413d passes when run on its own.

test_65n should check for a default LMV by its stripe count, and restore max-inherit and max-inherit-rr as well, and the hash type only if one is set.
