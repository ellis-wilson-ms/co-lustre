--- Description ---
mgs_modify_param() at lustre/mgs/mgs_llog.c:1316 returns positive EINVAL (+22) instead of -EINVAL when a non-delete set arrives with no parsable value. The caller in mgs_wlp_lcfg() checks rc Reachability: This path is currently unreachable through the normal mgs_set_param() ioctl flow because mgs_param_empty() upstream maps the trigger conditions (no =, or = with empty RHS) to del=true, which sends control into the MPM_DELETE branch instead. So no user-visible bug today.

Why fix it anyway: The non-reachability is a non-local invariant that depends on every caller of mgs_modify_param() doing the right empty-value mapping first. Totality over defaults — the function should reject bad input on its own terms. If a future caller invokes mgs_modify_param() directly with del=false and a value-less param, the sign error becomes a real silent-write bug.

Fix: One-character change — rc = EINVAL → rc = -EINVAL.
