--- Description ---
The rpm and deb packaging don't use the o2ib (OFED) configuration detected by ./configure, but determine it again on their own, which is unreliable: lustre.spec searches /usr/src/ofa_kernel/ with find -H, which misses the symlinked OFED directories of DOCA-OFED DKMS packages, and the deb ext_o2ib/int_o2ib build profiles depend on DPKG_EXT_O2IB and DPKG_INT_O2IB, which configure never substitutes.

For example, on Rocky Linux 10.1 with DOCA-OFED 3.5.0 (mlnx-ofa_kernel-dkms), ./configure without --with-o2ib (or with --with-o2ib=yes) detects the external OFED correctly, but make rpms fails:

Also, make dkms-debs builds all kernel modules on the build host, which are never used, as DKMS rebuilds them on the target, and it never generates lustre-tests.install, so lustre-tests is empty on a clean tree. Skip the kernel modules for dkms-debs and generate lustre-tests.install without the test modules, which are left to DKMS as for dkms-rpm.
