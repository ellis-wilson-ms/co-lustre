adilger, arshad512 I would like to share my thoughts on how to fix LU-19944, LU-19945 and LU-19740. I hope we can reach an agreement on the approach and then move forward.

Current logic about the process of arguments:

1) Process --version argument and check if the last argument is really a device by calling chk_args().

2) Get the device by reading the value of argv[argc - 1].

3) Process --erase-params argument in advance by calling getopt_long() for the first time.

4) Process other arguments by caling getopt_long() for the second time.

I agreed that Andreas's patch is simpler to fix LU-19944, but I think it is better to refactor the process of arguments before fixing LU-19945 and LU-19740.  For example, without refactoring, 1) we have to move `-q` argument into chk_args() and pick up it by doing a loop when fixing LU-19945 because tunefs.lustre needs to supress the output of "Read previous values". 2) we also have to check if muplite devices are specified by doing a loop when fixing LU-19740 because tunefs.lustre should get the device in advance.

I hope we can simple the current logic like this:

a) Merge 1), 2) and 3) into simple_parse_opt() and make simple_parse_opt() can process any arguments which should be processed in advance.

b) It seems easier to maintain in the future if only getopt_long() is used to process all arguments.
