--- Description ---
If move a file from one MDT to another, it causes to create a remote inode. This inode inherits project id, but UID and GID are to 0. Agent inode UID, GID and PROJID remain unchanged. That said each file moved between MDTs causes creating a new inode that increments project ID usage(if agent ahs project ID set on it).

I think agents inode UID and GID should be also set to the remote inode as well as PROJID to be considered by account by quota accounting subsystem. I don't have a good example, but probably it also makes sense from the security point of view(inode has ROOT UID and GID).

Below is a simple example with the details:

[root@vm3 ~]# cat repro3.sh 
#!/bin/bash

cd /mnt/lustre
mkdir my_project
chattr +P -p 32 my_project
lsattr -dp my_project/
#   32 -------------------P-- my_project/
cd my_project/
#mkdir p{1..3}
lfs mkdir -i 1 p1
lfs mkdir -i 2 p2
lfs mkdir -i 3 p3
touch p1/truc
chown 64030:112 p1/truc
mv p1/truc p2/truc
lsattr -dp *

--- Comment (JIRAUSER19803, Thu, 17 Sep 2026 14:13:18 +0000) ---
I would like to add that fixing this will need to add a way for users to easily identify those agent files. They are invisible with lfs find and in lfs quota, so it leads to have an inodes count that will be bigger than the actual file/directory count.

One idea is to add an option to lfs quota to show files/directories count without agent files, this way users will see the gap between their inode quota and files/directories count.

Another one that would probably be handy is to add an lfs find option to list files having an agent file, this will help to identify files that are not one the same directory than their parent.

Agree that such option for lfs find also makes sense. Probably, there could be another cases that I’m not taking into account, but we could at least find such inodes and put a note to the manual that new option (--agent-inode) is to find files which indexes are different from the parents:

--agent-inode Find namespace objects whose MDT differs from the MDT of their parent directory. Generally, such files occupy 2 inodes affecting project quota usage.
