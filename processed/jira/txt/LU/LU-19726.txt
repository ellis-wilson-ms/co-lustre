--- Description ---
I have seen a few cases of rare test failures that are hard to reproduce locally. The goal of this patch it to add more verbose output to select methods inside test-framework.sh related to shutdown / rebooting of nodes. 

While this proposed fix doesn't directly fix any of the unique failures or examples given below, it should assist with debugging if they arise again in the future.

--- Comment (JIRAUSER19234, Tue, 24 Mar 2026 22:44:45 +0000) ---
I think I see the issue. The debug info was useful here.

 

	20:18:51 — node onyx-157vm144 is confirmed powered off (100% ping loss)

	20:34:47 — "rebooted" message prints (~16 minutes later)

 

This is one of the only test to use FAILURE_MODE=HARD. The log printing tries to get the uptime info from the powered off node and hangs when it can't make the connection, until it finally times out and continues along. This should be easy enough to fix by adding earlier forced timeout to the uptime_info call.
