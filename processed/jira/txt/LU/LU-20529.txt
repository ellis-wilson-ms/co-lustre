--- Description ---
Lustre version : lfs 2.14.0_ddn246

Based on the log, the problem is linked to the current index value and the user index value not updating correctly.

Jun 17 20:45:54 prj-mds01 kernel: Lustre: 2862542:0:(mdd_trans.c:180:mdd_chlg_garbage_collect()) tier2-MDD0000: force deregister of changelog user cl2 idle for 1158s with 2098261127 unprocessed records

The number of unprocessed events is equal to 2.098 billion during a changelog idle timeout equal to 19min (that is very small !!!! ).

The cl2 was stopped for only ~20 minutes (1158s in the log), the implied generation rate would be:

2098261127/1158 ≈ 1.8 million changelog records per second

But based on the measurement done by the customer, the rate between two current index with timeout equal to 60s is only 64 changelog records per second.

Mon Jul 13 15:00:20 CEST 2026 => lag=121971118 idle=1609s user_index=6412160230 current_index=6534131348

Mon Jul 13 15:01:20 CEST 2026 => lag=121974919 idle=1669s user_index=6412160230 current_index=6534135149

(6534135149 - 6534131348)/ 60 = 3801/60 ≈ 64 changelog records per second

	This the reason why we suspect a bug in the computation of the unprocessed changelogs during the start of garbage collector.
