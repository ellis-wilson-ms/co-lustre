--- Description ---
Description

lnet_legacy2yaml blocks forever reading standard input when it is

invoked with file-based inputs (-i, -r, -n, -m) and no

inline positional argument. Under a test harness or any other caller

that does not give the process a TTY, this hangs indefinitely.

In main():

    if args.inline is not None:
        inline_raw = args.inline
    else:
        # If no inline and no files, read stdin (heuristic: data piped in)
        if not sys.stdin.isatty():
            inline_raw = sys.stdin.read()

The comment states the intended condition – "no inline and no files"

– but the code only tests args.inline. When file sources are

supplied the script still falls through to sys.stdin.read().

Interactively the bug is invisible: isatty() is true and the read is

skipped. Under auster, stdin is an inherited pipe whose write end is

never closed, so read() never sees EOF and the script hangs forever.

Impact

The sanity-lnet tests added by the same patch cannot complete. Ten

of them pass file flags with no positional argument and hang:

606, 615, 616, 617, 618, 619, 620, 621, 622, 626

Note that 618, 621 and 622 use process substitution ({{-r -r argument but still leaves fd 0 as

the inherited pipe, so they hang the same way.

Observed on a cluster run: sanity-lnet test_606 sat for 4h25m with

the suite making no progress, blocked in read() on fd 0:

/usr/bin/python3 /sbin/lnet_legacy2yaml -i /tmp/sanity-lnet-606-ip.rules \
    -r /tmp/sanity-lnet-606-routes.rules

  fd 0 -> pipe:[19007]

  [] pipe_read+0x3e8/0x450
  [] vfs_read+0x2ec/0x330
  [] ksys_read+0xf8/0x120
  [] __arm64_sys_read+0x24/0x38
  [] invoke_syscall.constprop.0+0x74/0xd0
  [] do_el0_svc+0xb0/0xf0
  [] el0_svc+0x44/0x1b8

Tests 600-605, 607, 608, 611-614, 623-625 and 627-629 pass an inline

string and are unaffected; 609 pipes empty stdin with no file flags and

is unaffected; 610 passes both files and an inline string and is

unaffected.

Reproducer

Give the script an stdin pipe whose write end stays open – the shape a

test harness creates:

mkfifo /tmp/f1
sleep 60 > /tmp/f1 &
echo 'tcp0 10.1.0.*'            > /tmp/ip.rules
echo 'tcp0 1 10.1.0.1@o2ib0:9'  > /tmp/routes.rules

lnet_legacy2yaml -i /tmp/ip.rules -r /tmp/routes.rules 

Proposed fix

Gate the stdin read on the absence of file sources, matching the

documented intent. All four file options are declared

action='append', so each is None when unused:

    else:
        # If no inline and no files, read stdin (heuristic: data piped in).
        # With file sources given, stdin is not a data source: reading it
        # would block forever on an inherited pipe that is never closed.
        have_files = any((args.ip2nets, args.routes, args.networks,
                          args.modprobe))
        if not have_files and not sys.stdin.isatty():
            inline_raw = sys.stdin.read()

The file sources are consumed earlier and accumulate into the same

lists, so gating only the stdin read cannot lose file-supplied data.

Documentation/man8/lnet_legacy2yaml.8 needs a matching correction:

DESCRIPTION currently says input may be supplied "through any

combination of positional inline argument, file options, or standard

input", and the NOTES bullet says sources are processed "... then

inline/stdin content". After the fix, stdin is a fallback consulted only

when neither an inline argument nor a file option is given, so

lnet_legacy2yaml -i ip.rules  ignores extra.conf

rather than appending it. The trade seems right – a hang is strictly

worse than an ignored redirect, and "pipe with data pending" is not

reliably distinguishable from "pipe nobody will ever write to" – but

the documented contract should say so.

Verification

Against the fifo reproducer above:

	current master: still running after 5s – hung

	with the fix: rc=0 and correct YAML

	echo -n "" | lnet_legacy2yaml -> rc=1 "no data provided" (test_609 path, unchanged)

	echo 'tcp0 10.1.0.*' | lnet_legacy2yaml -> rc=0 (stdin path, unchanged)

With pyyaml available, the fixed output parses structurally equal to

test_606's expected document, so the test passes rather than merely

ceasing to hang.
