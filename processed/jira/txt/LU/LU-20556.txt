--- Description ---
Several LOD paths decide “is this stripe / mirror usable?” by walking components and calling lod_check_ost_avail() for each OST object (FLD lookup + ltd_active):

	lod_primary_pick() — FLR write-primary selection (hot path on write intent)

	lod_layout_has_unavailable_stripe() — non-FLR trunc(0) unavailable check (LU-20211)

In a healthy cluster these walks almost always find every OST active, so most of the work is wasted—especially on lod_primary_pick(), which can run far more often than trunc(0).

Andreas suggested maintaining a single top-level bit (or bitmask) for “any OST currently unavailable”, so the common all-healthy case can skip the per-object walk. A race between updating that summary and a full check is acceptable and no worse than today (an OST can go offline immediately after a successful check).

Proposal

Track a summary of OST activity on the LOD OST target table. Prefer reusing existing ld_active_tgt_count (updated when ltd_active flips in qos/statfs and related paths); add an explicit bit/bitmask only if needed.

Fast path for both callers:

	All OSTs healthy (ld_active_tgt_count == ld_tgt_count, or summary bit clear) → skip per-stripe lod_check_ost_avail() walks.

	Otherwise → keep the existing per-stripe checks for that object/mirror.

Update the summary in the same places that already change ltd_active (mainly LOD qos/statfs under lod_lock, plus target add / process_config). Consumers are lod_primary_pick and unavailable-layout checks.
