--- Description ---
Description

Since LU-14008 an immediate message sends its payload by reference. kiblnd_fmr_map_tx() registers the payload pages with a FastReg MR and collapses them into one fragment (first page's DMA address, full length, MR key). kiblnd_init_tx_sge() then uses local_dma_lkey for that fragment instead of rd_key, so the HCA reads physical memory linearly from the first page. Any payload that crosses a page boundary into a non-contiguous page sends the wrong bytes for the second page. The sender reports success.

ptlrpc buffers are kmalloc'd and physically contiguous, so this is latent there unless the buffer fell back to vmalloc. It is immediately visible with non-contiguous pages, e.g. lnet-selftest.

 

Impact on Lustre I/O

On 64K-page clients short I/O is always off (OST_MAX_SHORT_IO_BYTES is 0 there, osc.*.short_io_bytes reads 0 and cannot be raised), so every small write is a bulk. When the OSC gets -EDQUOT (project quota near its hard limit), vvp_io_commit_sync() clips the queued pages to the written range, and a small write crossing a page boundary becomes one bulk of two partial pages. The client's REPLY to the OST's LNetGet() takes the immediate send path, and the bytes after the page boundary are replaced by whatever physically follows the first page.

The OST reports "BAD WRITE CHECKSUM" on extents of a few hundred bytes crossing a 64K boundary; the client's recomputed checksum matches its original, fabric counters stay clean, and the client ends with "too many resent retries". Reads are unaffected (RDMA path). Reproduced with a 64K-page client over FastReg o2ib, a project quota set just above current usage, and a non-root process appending log lines in that project. A 4K-page client does not reproduce (short I/O keeps these writes out of bulk).
