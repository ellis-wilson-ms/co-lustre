--- Description ---
There are two classes of incorrectness here, depending on whether the symlink-dir was reached as a path passed directly via the cli or via recursive exploration. As this changes the metadata retrieval paths.

When the symlink-dir path is directly passed via the CLI, ordinary stat metadata directives will show the value for the dir inode itself, not the link. This is inconsistent with how symlink-files are handled, where the value of the link inode is always used.

When a symlink-dir path is reached via recursion, layout directives %L{c,i,o,S} use the directory's child-file default layout if the dir has a default LOV layout, when they should use values from the dir inode itself, matching symlink-file handling.
