--- Description ---
sanity test_160g sometimes fails with:

  mds1: user2 cl9 index  expected 24, but is 25

This is a test race, not a product bug.

The test calls changelog_register twice in a row. Each registration sets the new user's

ndex to the MDT's current changelog index (rec->cur_endrec = mdd->mdd_cl.mc_index in

mdd_changelog_user_register()). Later the test checks that user1 and user2 have

the same index ([ $user_rec1 == $user_rec2 ]).

                                                                                      

This only holds if no changelog record is written between the two register calls. If one

record lands in that window, user2 starts one ahead of user1 and stays one ahead. That's

why the difference is always exactly 1.

 

changelog_user_rec reads the user's own index (cur_endrec), and only a changelog clear

moves it. So the race is in the two registrations, not around __changelog_clear.

Possible fix: read both users' indexes right after registering and compare the changes

(deltas), not the absolute values. Or make sure no changelog activity happens between the

two registrations.

 

Seen on: Gerrit 68095 PS22, Janitor build 70480, sanity2@ldiskfs+DNE. Janitor also listed

it in reviews 67745, 65414, 65183 and 62952, so it doesn't come from one patch.
