--- Description ---
The libcfs debug log (lctl debug / dk) is reliable and always

available, but it is poorly suited to live analysis. Messages can

only be read after they reach the trace buffer, filtering is limited

to debug masks and subsystems, and long runs of continuous logs are

hard to capture because the buffer wraps or is dropped under memory

pressure (see LU-15917).

Add kernel tracepoints (TRACE_EVENT) to libcfs_debug_msg() so that

external tools (bpftrace, bcc/libbpf, perf, ftrace) can capture,

filter and process Lustre debug messages at runtime. The existing

debug log is left as it is. The tracepoints cost almost nothing when

disabled (a static key check).

Three tracepoints are added in trace system "lustre_debug":

	lustre_debug_location: file, function, line, subsystem and mask

   of the message, emitted before formatting

	lustre_debug_msg: the same fields plus the formatted message text

	lustre_debug_msg_raw: subsystem, mask, line and message text

   in a ptldebug_header layout

TP_printk output is YAML/JSON compatible.

An example bcc tool, contrib/eBPF/lustre_debug_msgs.py, streams

messages as JSON and filters them by subsystem (-s), mask (-m),

source file (-f) and message count (-n), e.g.:

python3 lustre_debug_msgs.py -s S_RPC -m D_ERROR

This is also a building block for exporting Lustre debug events to

OpenTelemetry pipelines.

--- Comment (JIRAUSER18021, Tue, 13 Oct 2026 09:58:44 +0000) ---
Alex, thanks for the report. Fix is in https://review.whamcloud.com/c/fs/lustre-release/+/69643

Cause: lustre_debug_vlen() in lustre_debug.h was static inline and uses a va_list. On older kernels built without CONFIG_OPTIMIZE_INLINING the kernel headers define inline as always_inline, and gcc refuses that for a function that uses variable argument lists. Stock el8 kernels set CONFIG_OPTIMIZE_INLINING=y, which is why this was not caught by CI.

The patch moves the function out of line into tracefile.c; nothing else changes.

I reproduced your error with gcc 8.5.0 against el8 4.18 kernel headers with CONFIG_OPTIMIZE_INLINING turned off, and the build passes there with the patch. It also builds with the stock el8 config and on 6.12, where sanity test_60k passes.

I am assuming your kernel has that option off. Could you confirm (grep OPTIMIZE_INLINING in the kernel .config) and check that the patch fixes the build for you?
