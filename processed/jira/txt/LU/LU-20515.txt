Environment

	Lustre master, commit `c088134a8e` (`2.17.54_183_gc088134`), server build, EL8

	Kernel `4.18.0-553.123.1.el8_lustre.ddn17.x86_64`, Rocky Linux 8.10

	Server has 4 multi-rail LNet networks configured simultaneously (`tcp10`, `tcp11`, `o2ib12`, `o2ib13`), each with 2 NIs on VLAN sub-interfaces (`mlxen0.N` + `mlxen1.N`, same `/24` subnet per net) — only `o2ib12` was churned to trigger the crash

	`o2ib12`: 2 NIs on the server, `mlxen0.12` + `mlxen1.12`

	At least one client mounted over `o2ib12` with ordinary I/O in progress

Steps to Reproduce

lnetctl net del --net o2ib12
lnetctl net add --net o2ib12 --if mlxen0.12      # Reduce to a single NI
sleep 3
lnetctl net add --net o2ib12 --if mlxen1.12      # Restore two NIs
sleep 3

On the clients:

Verify that all peers are discovered correctly.

Repeat the above sequence multiple times.

The server occasionally hits an LBUG in lnet_destroy_peer_locked() during peer discovery. The issue occurs intermittently after repeating the above sequence several times.
