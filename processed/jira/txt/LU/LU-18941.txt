It looks like this subtest is failing exclusively on aarch64+64k clients, about 25% of test runs.  However, it appears that it can pass with retesting, so it seems like a race condition.

paf0186 is it possible this test is failing due to PAGE_SIZE=65536 issues?  The test itself is using "dd ... bs=8 count=1" so it would be exactly one page on x86_64, but a partial page on aarch64.  Should be be changed to use "bs=64k" or "bs=$((PAGE_SIZE/1024))k" or similar?

--- Comment (adilger, Mon, 6 Apr 2026 17:43:07 +0000) ---
PS: if someone is pushing a patch for this, note that the (7) (last)error message is inconsistent with the check - it is checking ${rpcs[1]} but printing ${rpcs[0]} in the error:

        [[ ${rpcs[1]} == 1 ]] ||
                 error "(7) ${rpcs[0]} != 1 read RPCs"

That isn't the case that is failing here, but it would be good to fix anyway (along with other test script style issues like using ((...)) instead of [[...]] for numeric comparisons).
