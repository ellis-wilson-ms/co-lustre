--- Description ---
We observed that the C function write() on the Lustre file system (version 2.14.0_ddn205) returns 0 instead of the expected number of bytes written. Below our application log

19:52:15|sebckdatamover1|ADA|sebckcatalog1|2524|2|2|Client|ADA::ADA_SM_Fs_OneOne|1957|35645|ada_agent|fam.c||3642|ERROR|1873260|18446744073545549376|write return 0 "/fsbackup/SOFTWARE_BACKUP_O2O/Project/12/fssmall/lustre/fssmall/software/rd/europlexus/epx-dev/versions/version-20260725-0322/thirdparties/impi_intel/sbtl_95/lib/libSBTL_95.a.adazip", OS error=0, nToWrite = 131072, bytesLeft = 131072|5|1789667535|3|1   

Because the file is a regular file stored on the Lustre file system, it appears that there is an error in Lustre that prevents the corresponding error code from being set when the write() operation fails. On Linux file system, the write() return a value bigger than 0 or -1.

The most plausible explanation, given that the OST is only 8% utilized and there are no messages in dmesg, is a grant-related issue between this client and OST4. In this situation, Lustre may return a short write or zero without setting errno, as in LU-13214. However, this remains a hypothesis: no issue report documents a return value of exactly 0.

Another point to consider is that the client is running a DDN build (2.14.0_ddn205). DDN applies private patches that are not available in the public Jira tracker. Only DDN support can confirm whether this behavior is a known issue or has been fixed in a more recent build.
