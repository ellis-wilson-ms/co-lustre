Forgot to post the RCA here.

This is a latent bug in one of the LU-18812 patches.

When each socklnd NI comes up, lnet_acceptor_add_socket() opens a listening socket and replaces its sk->sk_data_ready with lnet_acceptor_ready.

        /* Setup socket callback properly */
        lnet_acceptor_state.pta_odata = lsock->liss_sock->sk->sk_data_ready;
        lsock->liss_sock->sk->sk_data_ready = lnet_acceptor_ready;

lnet_acceptor_ready() does an unconditional wake_up_interruptible()

        wake_up_interruptible(&lnet_acceptor_state.pta_waitq);

pta_waitq is a field of the file-static lnet_acceptor_state struct, which is zero. The static initializer only sets .pta_shutdown = 1, not pta_waitq. It is only made valid by init_waitqueue_head() inside the acceptor kthread

static struct {
        int                     pta_shutdown;
        struct socket           *pta_sock;
        struct completion       pta_signal;
        struct net              *pta_ns;
        wait_queue_head_t       pta_waitq;
        atomic_t                pta_ready;
#ifdef HAVE_SK_DATA_READY_ONE_ARG
        void                    (*pta_odata)(struct sock *);
#else
        void                    (*pta_odata)(struct sock *, int);
#endif
} lnet_acceptor_state = {
        .pta_shutdown = 1
};

...

static int
lnet_acceptor(void *arg)
{
...
        init_waitqueue_head(&lnet_acceptor_state.pta_waitq);

When LNet is started, all listeners are hooked in lnet_startup_lndnets() before lnet_acceptor_start() spawns the kthread. So there is a window where the listening sockets are live and hooked but pta_waitq.head.next == NULL.

An inbound TCP connection completing its 3-way handshake in that window goes tcp_v4_rcv -> tcp_child_process -> parent->sk_data_ready (=lnet_acceptor_ready) -> wake_up_interruptible(&pta_waitq) and dereferences the NULL list head -> __wake_up_common+0x4c NULL deref in softirq -> panic.
