--- Description ---
As seen in test results of debug patch https://review.whamcloud.com/68576 , running interop testing between master client and 2.16 server hits a number of failures in sanity-sec:

5 45 47 48b 49 64a

As a first pass, it would be good to check if those failures are real bugs, or rather unavoidable problems due to the older server version. In the latter case, adding an interop version check in the tests would be helpful to avoid hitting these failures every time interop tests are triggered.

--- Comment (JIRAUSER19503, Mon, 28 Sep 2026 15:40:02 +0000) ---
test_5 was introduced by "LU-19996 utils: Make l_getidentity produce proper errno", which is not present in the b2_16 branch. As a result, the expected errno is different on b2_16 servers.

	test_64a, on b2_16, setting the project ID with lfs project -p requires the projid_set RBAC role now.

For the master client running against an older 2.16 server, the test must not request the projid_set role. This role is not supported by the older server, so nodemap_modify rejects the entire RBAC value with EINVAL.

	Tests 45, 47, 48b, and 49 are showing timeout failures during interop testing with the 2.16 server.

The failures appear to have some common LNet and bulk I/O errors, including the client being unable to reach the OSS. However, more investigation is needed to confirm whether they share the same root cause and determine the appropriate fix.
