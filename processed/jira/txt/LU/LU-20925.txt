--- Description ---
With the round-robin allocator ordered by failure domain (LU-19823), when the OSTs of each OSS are in several failure domains (e.g. enclosures shared by the OSSs of an HA pair) and a file has FLR mirrors, lod_ost_alloc_rr() takes the OSTs of each domain in turn and prefers one on an OSS that the other mirrors do not use yet.  That keeps mirrors on different OSSs far more often (lod_rr_test -o 4-64 -s 2-8 -d 2-8 -D -M: about 8.5x fewer files with mirrors on one OSS), but skipping OSTs in the domain rotation leaves some OSTs with up to about 1.7x the first stripes of others (2651 of 6537 combinations unbalanced).

Rework the rotation within a failure domain so that it avoids the OSSs of other mirrors without skewing the balance, e.g. by rotating per OSS within each domain, then add lod_rr_test -D -M to sanity test_51g.
