--- Description ---
test_109 in lustre/tests/sanity-lnet.sh creates and removes an interface alias with ifconfig:

	ifconfig "$FAKE_IF_ALIAS" "$FAKE_IP_ALIAS" up ||
		error "Failed to add fake IF alias"
...
	ifconfig "$FAKE_IF_ALIAS" "$FAKE_IP_ALIAS" down ||
		error "Failed to clean up fake IF alias"

ifconfig comes from net-tools, which is deprecated and is not installed on minimal RHEL 9 / Rocky 9 images. On such a node the test fails at setup.

These are the only two ifconfig calls in the suite. setup_fakeif(), which runs immediately before them in the same test, already uses ip(8) throughout, so the dependency is inconsistent as well as unnecessary.

The equivalent ip(8) commands produce the same aliased address:

# ip addr add 10.1.2.31/31 dev test1pg label test1pg:0
# ip -o -4 a s test1pg
5: test1pg    inet 10.1.2.3/31 scope global test1pg
5: test1pg    inet 10.1.2.31/31 scope global test1pg:0

Suggested fix: use ip addr add ... label and ip addr del, matching the rest of the suite.
