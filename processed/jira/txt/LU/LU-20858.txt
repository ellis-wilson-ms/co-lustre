--- Description ---
Description
 

lnetctl route show does not validate the network name passed to --net. The same argument is rejected by lnetctl net show with a parse error. route show returns success and no output, so a typo in the network name looks like a successful query that found no routes.

 

Actual result
 

 

route show exits 0 with no output on stdout and no output on stderr for an unparseable network name. net show with the same value exits 234 and prints cannot parse net.

 

Expected Result
 

 

lnetctl route show rejects a network name that cannot be parsed, with the same parse error that net show reports, and exits non-zero.

 

Steps To Reproduce
 

 

1. Ask route show for a network name that cannot be parsed, and check the exit code and the output:

 

$ lnetctl route show --net nosuchnet
$ echo $?
0
(stdout: 0 bytes, stderr: 0 bytes)

 

2. The same argument passed to net show is rejected:

 

 {{}}

$ lnetctl net show --net nosuchnet
show:
-     net:
      errno: -2
      descr: ! "cannot parse net"
$ echo $?
234

{{}}

3. Repeat run of route show with the same unparseable network name:

 

$ lnetctl route show --net nosuchnet
$ echo $?
0
(stdout: 0 bytes, stderr: 0 bytes)
