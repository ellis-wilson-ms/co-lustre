--- Comment (sebastien, Wed, 6 May 2026 15:58:59 +0000) ---
I think I managed to find the reason for these failures. sanity-sec test_31 adds a new LNet network ${NETTYPE}999 to exercise the '-o network' mount option, so it has to also add it to $MGSNID. But recently we started supporting Infiniband testing in Maloo, and it looks like the function h2name_or_ip to generate a NID list for a host is not designed to filter the addresses based on the nettype currently tested. This ends up using non-existing MGS NIDs, for instance @tcp.

I have pushed a patch to improve h2name_or_ip and allow it to filter on the nettype being used:

https://review.whamcloud.com/65714

Let's see how it goes.
