Dear all, it seems we have run into the same bug at the HU in Berlin.

Weird non-descriptive errors such as LustreError: 9770:0:(osc_cache.c:2226:osc_check_rpcs()) Write request failed with -14 that would only show on the client side (no trace on the Lustre Servers or the lnet statistics).

This was brought to our attention by users using exciting ( exciting-code.org ) as well as orca ( faccts.de/orca/ ) - from physics and chemistry who seem to encounter the issue sporadically.

A shared property of those codes is that they both employ OpenMPI (v4 and v5). - While exciting seems to write one set of files for the calculation, while orca writes files per process (I'm not sure how and when job s synchronize).

Exciting is an open source code, while orca is free for us at universities but not open source.

Following the idea suggested in this thread, disabling hybridIO seems to fix the problem, or at least it cannot be reproduced with orca any more.

(This will remain under observation on our end, but the immediate solution will  be to turn off hybridIO.)

With respect to the system, the lustre servers are running Rocky 9.7 with patchless lustre 2.17.0. (And the actual storage sits on Dell PowerVaults.)

The clients run OpenSUSE Leap 15.5 with lustre 2.17.0 ( kernel 5.14.21-150500.55.52-default ).

Due to past decisions, the network itself is ethernet only without RDMA support (100GBit/s).

Maybe this will add some additional useful information to this bug.
