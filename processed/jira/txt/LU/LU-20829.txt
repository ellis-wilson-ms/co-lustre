--- Description ---
test_230x sets osp.-osp-MDT0001.reserved_ino_low above the current free inode count, sets maxage=1, sleeps 4s, then expects 'lfs migrate -m 1 -c $MDSCOUNT $dir' to fail with ENOSPC. In session c00789de-74d3-46d4-8a74-ba438fd25928 (test set f24423b5-03cd-4e60-b535-51bb4c8bd37d), the review-dne-zfs-subtest-change job, which repeats a patch's changed subtests back to back, ran test_230x 57 times: it passed 56 times (migrate correctly failed with 'No space left on device (28)') and failed once on repeat 57 with 'migrate d230x.sanity should fail'. The osp.lustre-MDT0000-osp-MDT0001.* get_param/set_param calls resolved identically on every repeat, so this is not a parameter-resolution problem; it is a race where the OSP's cached free-inode statfs data (refreshed via maxage=1) had not picked up the lowered reserved_ino_low within the fixed 4s sleep before the migrate ran, letting it succeed when it should not have.

Not caused by the patch under test (change 56384): its only edit to test_230x renames the mdt_name lookup (mdtname_from_index -> ${MDT[0]}) and drops a redundant leading glob from the osp.* parameter path; the reserved_ino_low/maxage/sleep timing this race depends on is unchanged from before the patch. maloo test-history shows 93 test_230x occurrences across 30 lustre-reviews sessions in the last 30 days with only this one failure – ordinary single-run review jobs rarely catch a roughly 1.8% timing flake, and this repeat-testing job type is what exposed it.
