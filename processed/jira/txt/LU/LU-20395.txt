--- Comment (dongyang, Thu, 18 Jun 2026 11:01:22 +0000) ---
So it looks like ubuntu26 is using dd shipped from uutils, and it's not setting O_APPEND on the fd,

as a result the offset calculation is off, looks like the dd succeeded appending to the file but it's actually re-writing the first 1M.

root@ubuntu26:~# dd if=/dev/urandom bs=1M count=1 oflag=direct >> /mnt/lustre/testdir/testfile 
1+0 records in
1+0 records out
1048576 bytes (1.0 MB, 1.0 MiB) copied, 0.0310931 s, 34 MB/s

root@ubuntu26:~# gnudd if=/dev/urandom bs=1M count=1 oflag=direct >> /mnt/lustre/testdir/testfile 
gnudd: error writing 'standard output': No data available
1+0 records in
0+0 records out
0 bytes copied, 0.00399544 s, 0.0 kB/s

using gnudd is fine.

For now I think on the ubuntu26 test environments we should use gnu coreutils:

sudo apt-get remove coreutils-from-uutils --allow-remove-essential
