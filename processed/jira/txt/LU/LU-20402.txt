--- Description ---
lnet_peer_data_present() latches the peer's ping reply in lp_data and then drives the merge under ln_api_mutex with lp_lock dropped. That open window lets an async REPLY or PUSH handler swap in a different buffer mid-merge. So a reply the peer generated before an lnetctl net del/net add cycle, carrying the old shrunk NID set, can arrive and merge after the healed reply and overwrite a good peer table with the broken one. We don't gate against this. The seqno check in lnet_discovery_event_reply() only logs "peer rebooted?" and then stores the seqno unconditionally, and LNET_PEER_NIDS_UPTODATE gets set optimistically before the merge runs, so a concurrent mount or lfs df can observe a half-merged peer flagged up to date. The result is non-deterministic peer-table corruption (dropped or duplicated NIDs, split peers) and mount or lfs df hangs.

Gate the merge on the advertised config seqno. Make lp_peer_seqno a high-water mark so that lnet_discovery_event_reply() no longer lowers it, lnet_peer_merge_data() drops any buffer older than it, and we advance it to the seqno we actually merged. Seed ln_ping_target_seqno from wall-clock seconds in lnet_prepare() so that a node which reloads LNet still advertises a higher seqno than before, which keeps the gate reboot-safe with no wire change. Set NIDS_UPTODATE only after the merge succeeds.
