--- Description ---
LU-16622 unified the lfs find -m/-i/-O handling and dropped param.fp_exclude_mdt = !!neg_opt;.

fp_exclude_mdt is now never set in lfs.c (only fp_exclude_obd), but the MDT matcher still reads it (liblustreapi_pfind.c:724/727).

So ! -m  loses its negation and behaves like -m .

-i/-O (OST) are unaffected.

 

Reproduction (DNE, 2 MDTs):

### lfs find -m 0   (control: files ON MDT0)
.
./dir_on_mdt0
./dir_on_mdt0/f0

### lfs find ! -m 0  (should list files NOT on MDT0 = dir_on_mdt1/f1)
.
./dir_on_mdt0
./dir_on_mdt0/f0

### lfs find -m 1    (control: files ON MDT1 -> expect dir_on_mdt1, f1)
./dir_on_mdt1
./dir_on_mdt1/f1

### lfs find ! -m 1  (should be files NOT on MDT1 -> expect $D, dir_on_mdt0, f0)
./dir_on_mdt1
./dir_on_mdt1/f1
