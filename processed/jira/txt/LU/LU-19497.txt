Hi Keguang, could you please look into this test failure.  The sanity test_908 was added by your patch https://review.whamcloud.com/56691 ("LU-17309 llog: set timestamp on llog objects at creation time"), see test failure reports at:

https://testing.whamcloud.com/search?end_date=2026-04-12&source=sub_tests&start_date=2026-04-06&status=FAIL&sub_test_script_id=1c94eb71-200e-4e5e-95f5-d5ee0c5ad4b2&test_set_script_id=f9516376-32bc-11e0-aaee-52540025f9ae#redirect

It looks like it has been failing intermittently during testing, sometimes during branch testing runs, and sometimes during interop teset runs with 2.16.0 MDS because the tests are checking for "(( MDS1_VERSION >= $(version_code 2.16.0) ))".  In fact, this patch was not landed until commit v2_16_50-161-ge33d196b93, so it wouldn't have been included into a release until 2.17.0.   Please update the test interop checks to use:

        (( MDS1_VERSION >= $(version_code v2_16_50-161-ge33d196b93) )) ||
                skip "need MDS >= 2.16.50.161 for llog timestamps" 

The version_code function can handle the "git describe" format and will consider this to be the same version as "2.16.50.161".

--- Comment (adilger, Mon, 13 Apr 2026 21:33:33 +0000) ---
It looks like these failures are only happening during the "rolling upgrade" tests, where the filesystem formatted with an old release, then upgraded to a new release.  In this case, the params file was initially written with 2.15 or 2.16 and did not get a timestamp set at creation time.

It looks like it is possible to extract the Lustre version used when the params file was written, by adding the following check into the test:

        local format_ver=($(lctl --device MGS llog_print --raw params | awk '/version/ { print $10 }'))
        (( $(version_code $format_ver) > $(version_code v2_16_50-161-ge33d196b93) )) ||
                skip "MDS was formatted with version $format_ver"

I will submit a patch.
