--- Comment (adilger, Thu, 10 Sep 2026 22:16:37 +0000) ---
I think the most important part of any such fix is to not leave uninitialized fields in the layout, for any field, whether it is used or not. Otherwise we can never safely use those fields in the future.

Normally we zero all memory in Lustre before use, so I don't know where the garbage is coming from (userspace or the kernel, or both), but I think that is the first order issue to understand and fix.  Running this against my home filesystem it looks like I have bad timestamps dating back to files created in 2021, which would likely mean 2.14.x or so? So it isn't a newly-introduced problem, just that we never printed this field before.  

It probably makes sense to verify the lcme_time_and_id field for every layout read:

	consider it garbage and zero it if before 2010 or more than 1 year in the future

	this would become permanent if the layout is written (e.g. mirrored or migrated)

	set the timestamp for all mirrors when they are resync'd (regardless of NOSYNC flag) so we know when they were last updated
