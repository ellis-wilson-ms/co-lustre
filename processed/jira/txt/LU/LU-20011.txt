--- Description ---
If a file with a partial PFL layout (i.e. no EOF component) has a mirror added with "lfs mirror extend" it is then impossible to remove the mirror, add a new EOF component, or "lfs mirror split" to return to the original state, receiving the error "lfs mirror: Invalid layout: Incomplete mirror - must go to EOF".

Whatever generates this error should be ignored, and the split or "setstripe --comp-add" command should be allowed to bring the file back into a consistent state.

npapakonstantinou, I was going to write that it isn't permitted to change the function signature for llapi_*() functions, but I now see that the lsa_allow_incomplete_mirrors is in struct llapi_layout_sanity_args which appears local to that function.

It is a bit sad that struct llapi_layout_sanity_args is so poorly laid out, with bool intermixed with pointers and ints of various sizes.  According to pahole:

struct llapi_layout_sanity_args {
        _Bool                      lsa_incomplete;       /*     0     1 */
        _Bool                      lsa_flr;              /*     1     1 */
        _Bool                      lsa_ondisk;           /*     2     1 */

        /* XXX 1 byte hole, try to pack */

        int                        lsa_rc;               /*     4     4 */
        char *                     fsname;               /*     8     8 */
        uint16_t                   lsa_mirror_count;     /*    16     2 */
        _Bool                      lsa_in_parity;        /*    18     1 */

        /* XXX 5 bytes hole, try to pack */

        uint64_t                   lsa_last_parity_end;  /*    24     8 */

        /* size: 32, cachelines: 1, members: 8 */
        /* sum members: 26, holes: 2, sum holes: 6 */
        /* last cacheline: 32 bytes */
};

If there was any danger that this struct was exposed to userspace, the safest course of action would be to add the new bool in the 1-byte hole.
