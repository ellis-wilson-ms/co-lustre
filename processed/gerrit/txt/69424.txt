LU-9 lod: show the round-robin allocator state

The weights of the targets shown by lod.*.qos_ost_weights don't
explain which target the allocator chooses, since that depends on the
order of the round-robin array, its start index and offset, and the
failure domains and servers of the targets.

Add svr_id, tgt_active, failure_domain and rr_slot, the slot of the
target in the round-robin array, to lod.*.qos_ost_weights,
lod.*.qos_mdt_weights and the pool qos_ost_weights files.  Add
lod.*.qos_rr_state, lod.*.mdt_qos_rr_state and the pool qos_rr_state
files to show the round-robin array in allocation order and the start
index, offset and weighted round-robin laps of each allocation stream.
Reading them takes lq_rw_sem so that rr_slot matches the array, and
can wait while QoS allocation holds it.

Also fix writing lod.*.qos_mdt_weights, which reset the MDT penalties
under the OST lq_rw_sem and marked the OST QoS data dirty instead of
the MDT data.

Add a man page for lod.qos_rr_state and sanity test_51j to check the
array slots, the streams and leaving out an inactive OST.
