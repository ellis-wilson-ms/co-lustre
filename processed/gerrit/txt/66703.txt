LU-18941 tests: fix sanity/119j RPC count races

sanity test_119j intermittently fails on aarch64/64K-page clients
(~25% of runs) with both "(3) 1 != 0 read RPCs" and "(5)/(7)
0 != 1 read RPCs".  The landed read-size fix did not help because
the failures are RPC-count races, not read-size mismatches.

LU-19344 ("llite: set read size correctly") reordered
do_file_read_iter() so ll_do_fast_read() now runs before the hybrid
BIO->DIO switch check, unlike the write path where the switch is
evaluated before the (guarded) tiny-write fast path.  As a result,
when OBD_FAIL_LLITE_FORCE_BIO_AS_DIO is set, the forced-DIO read is
only sent to the server if its pages are actually cold; otherwise
fast read serves it from cache and no RPC is generated.  The test
relied on "sysctl -w vm.drop_caches=3" to cool the cache, but that
is best-effort and does not reliably evict pages pinned by OSC DLM
locks, which is racier on large-page clients.

Use cancel_lru_locks osc to deterministically invalidate the file's
cached pages before the forced-DIO read and write, so the IO is a
true cache miss.  Also add a warm-up read before the cached-read
measurement so a first-touch asynchronous readahead RPC cannot race
the stats reset and be miscounted (the "(3) 1 != 0" failure).  Fix
the stale "read RPCs" text in the write check.
