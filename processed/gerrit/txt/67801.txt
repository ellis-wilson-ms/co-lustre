LU-20253 llite: merge attributes after tiny writes

When ll_do_tiny_write() consumes the whole iov,
ll_file_write_iter() returns without calling ll_file_io_generic().
While other writes merge attribute at the end of
ll_file_io_generic(), nothing does this for tiny writes;
ll_tiny_write_end() only updates KMS via cl_page_touch(),
so i_size_read() returns a stale size until a later getattr or
glimpse.

In-kernel i_size_read() users (like overlayfs) observe the stale
size. The wrong size is cached on the overlay inode and is not
refreshed by a later Lustre getattr.

Call ll_merge_attr() from ll_do_tiny_write() once the write has
completed, matching what ll_file_io_generic() does for every other
write. No RPCs are added: cl_object_attr_get() only reads cached
per-stripe attributes.

The merge is done at the end of the write operation rather than in
the per-page ll_tiny_write_end(): that runs with the page lock held,
while ll_merge_attr() sleeps on lli_size_mutex, which
vvp_do_vmtruncate() takes before locking pages in
truncate_pagecache().

A micro-benchmark with fio 8-byte sequential buffered writes
looping over a 64K file (--ioengine=psync --rw=write --bs=8
--size=64k --time_based --runtime=10) show a small performance
regression, which shouldn't appear in real workloads:

  without patch: IOPS=364k, BW=2845KiB/s
  with patch:    IOPS=319k, BW=2492KiB/s
