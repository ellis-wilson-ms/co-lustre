LU-20854 lnet: send peer show header with first peer

"lnetctl peer show" can print a "peer:" key before each
peer. This happens when the 0@lo peer is entry 0 of the
peer list. A YAML parser that rejects duplicate keys then
fails.

The peer dump sends the empty header only for idx == 1.
The loop skips 0@lo after it increments idx. When 0@lo is
entry 0, no message carries the header. lnetctl then
prints the key once for each message.

Send the header in the first message of the dump. The
peer distance dump has the same defect. It also skips
unreachable NIDs, so fix it too.
