LU-18746 flr: allow merge stale mirror

Let a mirror be merged into a file without copying data into it
first, so that mirrors can be appended cheaply and resynced later,
by a data mover or by an EC parity extend that computes the mirror
content in place.

The client asks for it with LL_LEASE_ALLOW_STALE, a modifier on
LL_LEASE_LAYOUT_MERGE. It travels to the MDT as CD_MERGE_STALE in
the new close_data field cd_merge_flags and becomes the
LU_XATTR_MERGE_STALE modifier on LU_XATTR_MERGE, on which
lod_declare_layout_merge() marks every merged component
LCME_FL_STALE. The merge also reloads the striping with
LVF_ALL_STALE now, so a merge that would leave every mirror stale
is refused with -EPERM, as split already does. An MDT without this
change ignores cd_merge_flags and would merge the mirror as up to
date, so the client refuses the request with -EOPNOTSUPP unless
the MDT advertises OBD_CONNECT2_FLR_EC. That flag is only
negotiated with EC enabled on both the client and the MDT, so a
stale merge needs that too.

lfs still merges in sync. The stale path gets its callers in
"LU-19548 lfs: mirror extend support for EC" and "LU-17531 lfs:
add --no-resync option in mirror extend".

Also return the error from the LL_IOC_LEASE unlock argument checks
instead of overwriting it with the lease type from the close.

(5 comments)

I don't like that this flag is added as a separate ID in lil_ids[] instead of a flag of lil_flags.  That could cause problems in the future.

It probably makes sense to add a flag that means "allow stale" and could also be used with "LL_LEASE_LAYOUT_SPLIT" or other operations if needed:

        LL_LEASE_ALLOW_STALE = 0x20,

and then add this to LL_LEASE_LAYOUT_MERGE if needed.

Since lil_flags is only used on the client, there is little concern about interop.

At worst, if a new "lfs" command is run and sets this flag in lil_flags on an old client that doesn't understand it, then the file will be closed without creating the mirror, which is relatively safe in this case since the mirror contains no data.

What if this is run on a new client with an old server that doesn't know understand the "stale" flag?  Would the empty mirror be attached to the file and potentially cause data loss (e.g. the usable mirror could be removed since the empty mirror is not marked stale but has no data)?
