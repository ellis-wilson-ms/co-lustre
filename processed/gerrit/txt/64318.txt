LU-19921 ptlrpc: add GSSIAM security context client

The GSSIAM Security Flavor is a new, lightweight sptlrpc
authentication mechanism (selected by admins via the gssiam
flavor name, e.g. srpc.flavor.*=gssiam or -o sptlrpc=gssiam)
designed to integrate Lustre with external enterprise Identity
and Access Management (IAM) systems.

This patch implements the client-side GSSIAM security
policy and context operations (gssiam_sec_cops in
lustre/ptlrpc/gss/sec_gssiam.c):

- Hybrid Protocol Architecture: Uses GSS framing and a
  SEC_CTX_INIT handshake during initial connection setup
  to authenticate identity, negotiate security handles, and
  install the IAM principal and mount subdirectory onto the
  server export. Subsequent Data and Metadata RPCs use
  lightweight Null framing (sec_null) for high-performance I/O
  without GSS wrapping overhead.

- Context & Session Management: Implements context creation,
  destruction, and lookups (gssiam_create_sec, gssiam_destroy_sec,
  gssiam_lookup_ctx). Uses RCU-protected pointers
  (rcu_dereference_protected / synchronize_rcu) to prevent
  races during concurrent context lookups and teardowns.

- Initialization Handshake: Implements gssiam_send_init_rpc()
  and gssiam_init_pack_request() to transmit IAM principal
  identities, mount subdirectories (lgmi_subdir), and upcall
  tokens to the target server during context establishment.

- RPC Buffer Handling: Implements request and reply buffer
  allocators (gssiam_alloc_reqbuf, gssiam_free_reqbuf,
  gssiam_alloc_repbuf, gssiam_free_repbuf) that handle GSS
  headers for init RPCs while delegating standard traffic to
  null_accept_common().

- Lifetime & Expiration: Integrates with Lustre upcall_cache
  (upcall_cache_invalidate_one) to manage context caching,
  expiration, and invalidation across evictions and remounts.
  Initializes gssiam_upcall_cache in sptlrpc_gssiam_init() using
  the default userspace upcall helper /usr/sbin/l_gssiam_upcall
  (GSSIAM_UPCALL_PATH in sec_gssiam.c).

- Framing & Early Reply Helpers:
  * do_cli_unwrap_reply(): checks rq_repmsg != rq_repdata
    to distinguish wrapped vs unwrapped replies across all
    flavors, ensuring unwrapped replies retain their swab
    mask.
  * sptlrpc_cli_unwrap_early_reply(): propagates rq_ctx_init
    and rq_gss_framed to early_req to allow early replies
    for init and GSS-framed requests to be unwrapped.
  * ptlrpc_server_handle_req_in() & sptlrpc_svc_unwrap_request():
    add SPTLRPC_POLICY_GSSIAM arms for server-side framing
    support.
  * gss_exit_keyring(): drops __exit annotation as it is
    called by sptlrpc_gss_exit.
