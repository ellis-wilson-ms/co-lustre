--- Commit Message ---
LU-20765 osc: avoid RCU stalls during eviction page discard

On eviction osc_page_gang_lookup() walks the object page tree under
osc_object::oo_tree_lock and discards cached pages in batches.  For
a large object this loop can run for a very long time (see LU-14711:
discarding 750GB takes over 170s).  The loop only called
cond_resched() when need_resched() was already set, so on
voluntary-preempt kernels it could monopolise the CPU across many
batches - even though the tree lock is dropped between them - long
enough to trip the soft-lockup / RCU-stall watchdog and, under an
eviction storm, escalate to an NMI hard-LOCKUP.

Reschedule unconditionally between batches.  The tree lock is
already released at that point, so yielding is safe and keeps each
lock hold short.

Also add OBD_FAIL_OSC_EVICT_HOLD_LOCK and recovery-small test_164,
which holds oo_tree_lock across a dirty-page discard to
deterministically exercise this path and guard against
reintroducing a long hold of the page-tree lock during eviction.
