LU-9512 llite: Add O_TMPFILE support

This patch adds VFS tmpfile (O_TMPFILE (nameless))
file support. The file will be automatically deleted
when it is closed.

VFS tmpfile (tmpfile) support which is little different
from standard volatile file creation already present.
While volatile file is either destroyed on close or
swapped (migrate) but never link'ed. The tmpfile
support via inode_operations->tmpfile can be linked
and be brought out of orphan list and can be listed like
regular file

tmpfile uses unique (LUSTRE_VOLATILE_HDR + random) as
name, same as volatile file. This is because, currently
any file with such unique name is already put on
orphan (unlink, yet still open). Therefore tmpfile
piggybacks on this already implemented feature to
implement tmpfiles. However, tmpfile and volatile
files in Lustrefs is not same as mentioned above.

Test is exercised against older 2.16 server also.
New sanity/63d test is added as verification.
New sanity/63e test is added as DNE verification.

Test-Parameters: trivial serverversion=2.17.0 testlist=sanity
Test-Parameters: trivial serverversion=2.16.0 testlist=sanity env=ONLY="63d 63e"
