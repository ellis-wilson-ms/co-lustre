LU-19809 utils: fix lfs migrate to return correct exit code

The `lfs migrate` command does not propagate the correct exit
code when `cb_migrate_mdt_fini()` fails.
`llapi_semantic_traverse()` discarded the return value of its
sem_fini callback, so a `cb_migrate_mdt_fini()` failure was lost
and the command reported success. Capture that result and fold
it into the traversal exit status so the failure is reported.
The two new sem_fini sites do not abort the walk by themselves;
they only record the error. The existing fp_stop_on_error check
in the DT_DIR arm still governs whether the walk continues, and
llapi_migrate_mdt() sets that flag, so lfs migrate stops at the
first failing directory.

The same stricter error handling required a few related changes:

- cb_migrate_mdt_init() no longer overwrites a real migrate
  error with the depth marker at fp_max_depth. The marker
  (ret = 1) is a sentinel for "reached the deepest level, skip
  the fini"; it is now written only when ret == 0. Previously a
  per-entry LL_IOC_MIGRATE failure under `lfs migrate -m N -d DIR`
  was replaced by the marker and dropped, so the command exited
  0; it now aborts on the first failing entry.

- llapi_semantic_traverse() records the first real error using
  `ret >= 0` at each accumulation point. A positive depth marker
  parked in ret (from a max-depth sem_init) previously made the
  `ret == 0` guards false, so a later negative error was dropped
  and `lfs migrate` could abort mid-tree yet still exit 0.
  llapi_semantic_traverse() is shared: cb_find_init() and
  cb_getstripe() also return the depth marker at fp_max_depth, so
  `lfs find -maxdepth N`, non-recursive `lfs getstripe DIR`
  (depth 1, where a child subdir returns the marker) and the
  public llapi_find_with_cb() API get the same change; a previously
  dropped error (such as an -ENOENT for a file unlinked mid-scan)
  is now reported rather than masked behind the marker.
  The parallel-find work queue latches results the same way; its
  fwq_error accumulator now keeps the first negative error and
  never stores the positive depth marker, so the exit status of
  `lfs find -D N` no longer depends on --thread-count.

- cb_migrate_mdt_fini() now reports a close() failure (as -errno)
  before the layout setxattr, instead of silently returning the
  raw close() result.

- sanity test_60h no longer asserts a specific `lfs migrate` exit
  code. With a stripe fault injected, migrate's finalize fails and
  is now reported (LU-19809), but the directory is still
  accessible, which is what the test checks. The finalize failure
  is tracked by LU-20750; the migrate exit code is tolerated until
  that is fixed.

- conf-sanity t32_test now excludes `.fscrypt` from the
  directories it migrates. Migrating `.fscrypt` fails with
  ENOTEMPTY from the layout shrink (setxattr cannot drop a
  stripe that still has entries); that failure is now reported
  and would otherwise fail the test. The find filter is
  rewritten as a `-prune` expression; the pre-existing `.lustre`
  exclusion is carried over unchanged and remains a no-op, since
  a client mount's readdir never returns `.lustre`, so coverage
  is unchanged apart from `.fscrypt`.
