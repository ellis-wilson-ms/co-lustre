--- Commit Message ---
LU-20840 mdt: don't retry terminal auto-split failures

When a directory auto-split fails with -E2BIG (target stripe count
exceeds the available MDT count), retrying is futile until more MDTs
are added. However mdt_getattr_internal() re-queues the directory for
auto-split on every getattr once its dirent count exceeds the split
threshold, so a terminally-failing split repeatedly takes the parent
PW lock and stripe EX locks, blocking clients and wasting CPU.

Use the existing (previously unused) mot_auto_split_disabled flag on
struct mdt_object as a negative cache: set it when a split fails with
-E2BIG, on the object that getattr re-queues (the stripe for a striped
directory, otherwise the plain directory itself), and skip
mdt_auto_split_add() for objects that have it set. The flag is per
in-core object, so it is naturally cleared when the object is evicted
and re-instantiated.
