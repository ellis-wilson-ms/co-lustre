LU-20615 obdclass: bound the jobid_name field width

jobid_interpret_string() reads the width of a "%.N" escape into an
unbounded long and computes min(w + 1, joblen). For w = LONG_MAX the
increment overflows, width goes negative, and the clamp truncates it
to -1 in an int: the cursor steps back and the next literal character
writes one byte in front of the caller's buffer. It also reaches
snprintf() as a huge size_t, tripping vsnprintf()'s WARN_ON_ONCE() - a
panic under panic_on_warn.

Bound w before incrementing, so w + 1 is only evaluated where it
cannot wrap, matching min() for every width that fits. The expansion
then cannot fail, so the -EOVERFLOW the kernel-doc promised and never
produced goes too; that leaves the return value vestigial but not
removable: lustre_get_jobid() returns it directly from all three
sites, so void would re-assert the %0 contract by hand at each and
swallow a future failure. sanity test_205n covers it.
