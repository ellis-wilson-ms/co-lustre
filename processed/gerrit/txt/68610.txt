LU-17000 mdt: bound DoM read-on-open copy by the reply buffer

mdt_dom_read_on_open() grows the NIOBUF_INLINE reply buffer to hold
exactly $len bytes, then copies the local buffers returned by
dt_bufs_get()/dt_read_prep() into it, placing buffer $i at
$i << PAGE_SHIFT and copying lnb_len bytes from the start of
lnb_page.  That is only correct while every descriptor covers a
whole page starting at page offset 0, which the loop only checks
with an assertion that evaluates nothing under
--disable-libcfs-assert.  The only check afterwards is for an
undershoot ("copied < len"); an overshoot, that is a write past the
end of the reply buffer, is not caught at all.

Both assumptions do hold today so no real bug today.

Rather than keep relying on that, bound the copy by its destination:
track the running destination offset instead of assuming a page
stride, require each buffer to continue the requested range, to fit
in what is left of the reply buffer, to stay inside its own page and
to report an lnb_rc no larger than its own length, and honour
lnb_page_offset when reading from the page.  A buffer set failing
that check returns no data along with the open, which is a supported
outcome for this function: it always returns 0, and the client falls
back to a normal read when rnb_len is 0.

An lnb_rc short of lnb_len is not malformed, it is how an OSD reports
a range that ran past i_size, so that only stops the loop and lands
in the existing "copied < len" case, which drops the partial data the
same way it always did.  No buffer can start at or past i_size here
either: an unencrypted range ends at i_size, and an encrypted one
ends at real_dom_size, up to one LUSTRE_ENCRYPTION_UNIT_SIZE beyond
i_size, but PAGE_SIZE is a multiple of that unit, so a page starting
at or past i_size would already be past the end of the range.

The memset() of the page tail past lnb_len is dropped.  Only lnb_len
bytes were ever copied out of the page, so it could not affect the
reply, and it writes to memory the descriptor does not own as soon
as lnb_len is not page aligned.
