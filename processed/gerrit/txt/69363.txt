LU-17240 tests: reduce per-target format overhead

Most of the time formatall() spends on each target is in the test
framework, not in mke2fs: each target costs about 10 remote commands,
several of them repeated.  On a multi-node cluster every remote
command is an ssh round trip.

Skip the "stop" in add() when called from formatall(), since stopall()
already stopped every target.  Check the cheap conditions in stop()
before dm_flakey_supported(), which needs a remote command.  Only load
modules in formatall() if they are not already loaded, as
mount_facet() does, and drop the version check before set_hostid.
When VERBOSE is set, don't send "lctl mark" for each remote command in
formatall() after stopall(), since the modules may not be loaded yet,
and a mark for each format command would add a remote command per
target.  Look up each target's device name only once.

Pass "-E lazy_itable_init" to mke2fs for all test formats, as
conf-sanity already did, since the inode tables are zeroed in the
background after mount.  When mke2fs on all servers supports it,
also pass "-E assume_storage_prezeroed=1" for targets that
__touch_device() finds are regular files, since mkfs.lustre
--reformat recreates the file so it is already zero.

Also fix format_mdt() to use the mds$num facet for facet_fstype().

Serial formatall() (PARALLEL_FORMAT=0) of 2 MDTs and 6 OSTs (500MB
devices, 400MB files) on one 4-CPU VM, 3 runs, and remote commands
logged with VERBOSE:

                  before  after
  block devices   1.33s   0.86s  (-35%)
  loop files      1.23s   0.81s  (-34%)
  remote commands   71      47   (-34%)
