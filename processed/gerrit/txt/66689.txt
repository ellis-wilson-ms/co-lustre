LU-20399 o2iblnd: determine FastReg gaps correctly

kiblnd_setup_rd_kiov() sets tx->tx_gaps when a bulk transfer cannot be
described by a single page-aligned memory region, so the gapped case
can be diverted (or preemptively rejected on devices without FastReg
gaps support) instead of being handed to ib_map_mr_sg(), which would
short-map the scatterlist and fail registration with -EINVAL.

The gap test has been dead since it was introduced. fragnob is
min(bv_len - offset, nob), so "fragnob < bv_len - offset" is true only
when nob is the smaller term, in which case fragnob == nob and
"nob > fragnob" is false. The two conditions are mutually exclusive,
so tx_gaps was never set and every gapped transfer fell through to
ib_map_mr_sg().

Replace the test with the actual gap condition, mirroring the kernel's
ib_sg_to_pages(): a non-first fragment that starts mid-page, or a
non-last fragment that ends mid-page, introduces a gap. The first
fragment's start offset and the last fragment's end offset remain
exempt. This now flags the two-fragment case above, where the first
fragment ends mid-page.

This does not by itself make a gapped transfer succeed on a device
without gaps support; it restores the intended diversion and the
preemptive -EPROTONOSUPPORT path with its actionable message rather
than a bare short-map -EINVAL.
