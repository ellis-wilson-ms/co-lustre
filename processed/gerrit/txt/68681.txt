LU-20876 efalnd: Fix double-free of CQs on init

The CQ cleanup helper frees the queue array and the manager queue but
leaves the stored pointers dangling. On a device initialization failure
the cleanup runs once during the creation helper's own error handling
and then a second time from the device teardown path, which only checks
the pointers for NULL. The dangling pointers pass that check, so the
second pass iterates already freed memory and frees it again, causing a
use-after-free and double free.

Clear the pointers after freeing so the cleanup helper is idempotent and
the second invocation becomes a no-op.
