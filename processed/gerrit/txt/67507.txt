LU-6142 obdclass: add/use OBD_ALLOC_PTR_ARRAY[_LARGE]()

Reimplement OBD_ALLOC_PTR_ARRAY() and
OBD_ALLOC_PTR_ARRAY_LARGE() using the kernel
k[v]malloc_array() functions instead of open-coding
array sizes, and add OBD_ALLOC_ARRAY_GFP() and
OBD_ALLOC_ARRAY_LARGE_GFP() as the underlying array
allocators.  These simplify callers and avoid potential
bugs with overflow of calculations with 32-bit variables.

Convert OBD_ALLOC() and OBD_ALLOC_LARGE() and corresponding
OBD_FREE[_LARGE]() callers to the new macros where possible.
Callers converted to OBD_ALLOC_PTR_ARRAY_LARGE() now get the
vmalloc fallback of kvmalloc_array() rather than the
open-coded kmalloc-then-vmalloc of OBD_ALLOC_LARGE().

Remove OBD_ALLOC_WAIT(), OBD_ALLOC_PTR_WAIT() and
OBD_ALLOC_PTR_ARRAY_WAIT(); their few callers now use
OBD_ALLOC_GFP(..., GFP_KERNEL) directly.  Update
leak_finder.pl to parse the new allocation labels.

Change lds_def_comp_size_cnt to hold the maximum count of
entries in the lds_def_comp_entries array, rather than the
requested number of entries.  This avoids recalculating
the array size on each call so lod_free_def_comp_entries()
and lod_free_comp_buffer() can use OBD_FREE_PTR_ARRAY_LARGE().

Cleanup code style issues in related code.
