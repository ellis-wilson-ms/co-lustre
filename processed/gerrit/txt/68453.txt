LU-12669 ec: create lock placeholder for reconstructed pages

Create client-only ldlm_lock placeholders for sub-locks on
unavailable OSTs (LSS_READ_ERR) during CIT_EC_RD, so reconstructed
pages stay cached and Uptodate across reads instead of being
discarded after each read.  The ldlm_lock is granted locally without
an RPC and attached to the osc_lock via osc_lock_granted.

A stripe is converted only while its target is inactive
(OBDF_INACTIVE).  If the target is already active, an LSS_READ_ERR
recorded before it recovered is stale: lov_lock_sub_init() clears the
flag and enqueues a normal sub-lock instead of publishing a
placeholder for a healthy target, keeping the creation trigger and
the import-level cleanup consistent.

osc_lock_cancel() only detaches the ldlm_lock (osc_lock_detach)
without cancelling it, so the ldlm_lock survives the EC read loop and
keeps pages cached for concurrent readers.  When the OST recovers,
osc_import_event(IMP_EVENT_ACTIVE) cancels the placeholders with
ldlm_cli_cancel_unused_async(LCF_LOCAL | LCF_PLACEHOLDER): every
unreferenced placeholder is queued for the blocking-AST path
(osc_ldlm_blocking_ast -> __osc_dlm_blocking_ast -> osc_lock_flush),
flushing its stale pages.  A placeholder still referenced by an
in-flight EC read cannot be cancelled yet, so
ldlm_prepare_resource_list() marks it LDLM_FL_CBPENDING instead: the
last ldlm_lock_decref() (osc_lock_detach() at cl_io_unlock()) then
queues the same flush, and lock_matches() refuses to hand the
CBPENDING placeholder to a new referencing lookup meanwhile, so no
reader can extend its lifetime.

The async variant is used because IMP_EVENT_ACTIVE runs from the
import RPC reply-interpret context (ptlrpc_connect_interpret() ->
ptlrpc_activate_import()), where osc_lock_flush() must not block: it
takes page locks, and a concurrent degraded read owns those pages
while waiting for a BRW reply that ptlrpcd itself interprets, so
flushing inline there deadlocks the reply path.
ldlm_cli_cancel_unused_async() only prepares the matching locks
(ldlm_prepare_resource_list(), factored out of
ldlm_cancel_resource_local()) and hands them to the ldlm blocking
threads (ldlm_bl_to_thread_list()), where the cancel and blocking AST
run.

Placeholder creation is fenced against the activation sweep so an EC
read that started before or during recovery cannot publish a
placeholder after the sweep has passed its resource.  Add
cl_ec_placeholder_sem and cl_ec_placeholder_gen to client_obd:
osc_lock_init() records the current generation for CIT_EC_RD locks;
osc_lock_to_placeholder() takes the read side of the rwsem and refuses
with -EAGAIN if the generation is odd (an activation is in progress)
or has advanced since the lock was initialized; and
osc_import_event(IMP_EVENT_ACTIVE) holds the write side across gen++,
the cancel scan and OBD_NOTIFY_ACTIVE, then gen++ again.  A refused
conversion leaves the sub-lock normal, and its enqueue failure is
tolerated as an unprotected recovery.

There is deliberately no per-stripe flush from lov_lock_enqueue().  A
successful sub-lock enqueue proves the lock path (LDLM) works, not the
data path: under a BRW-only failure such as OBD_FAIL_OST_BRW_READ_BULK
lock RPCs keep succeeding while the stripe's data path is still
broken, so flushing there tears down a placeholder whose reconstructed
pages are still needed.  A successful enqueue therefore never converts
a stripe, and the flush is driven solely by the import-level
IMP_EVENT_ACTIVE path above.  Conversely, a sub-lock enqueue that
actually fails is data-path evidence, and lov_lock_enqueue() does
retry the conversion on that failure -- which is what covers the
transient case where the import stays FULL.

Placeholders are normal LRU citizens: once detached with no readers
they are added to the LRU, so reclaim (cancel_lru_locks, the shrinker,
memory pressure) can cancel them and drop the reconstructed pages --
they are re-recovered from parity on the next read.  Pinning them
until the OST recovers would hold too much memory.

check_and_discard_cb() must not treat a placeholder as an extra lock
covering a page: a placeholder is client-only state that exists only
to hold reconstructed pages, so counting it as coverage makes the
flush skip exactly the pages it is meant to discard.

That lookup must also be able to see the placeholder it is flushing:
ldlm_prepare_resource_list() and ldlm_cli_cancel_local() mark the lock
CBPENDING before the blocking AST runs, and lock_matches() rejects a
CBPENDING lock with 0 readers/writers.  The placeholder would be
invisible, so only a real lock granted concurrently by a racing read
- after the OST recovered but before the bl thread flushed -- would
be found and the reconstructed page kept, as if that lock vouched for
data reconstructed before it existed.  lock_matches() therefore lets
LDLM_FL_TEST_LOCK probes observe CBPENDING placeholders, and hides
them from every ordinary (referencing) lookup -- which also stops a
new reader from attaching to a placeholder whose flush is already
pending.  Real CBPENDING locks stay unmatched, so the ordinary
lock-cancel flush is unaffected.

Placeholder locks must not satisfy a normal request: a placeholder is
client-only, so a request reusing one would believe it holds a
server-granted lock.  osc_enqueue_base() and osc_object_fiemap()
therefore skip LDLM_FL_PLACEHOLDER locks via the skip_flags argument
of ldlm_lock_match_with_skip().  Besides, both search with
LDLM_FL_LVB_READY, and matching a placeholder there would block for
obd_timeout, as a placeholder has no completion AST to make it
LVB-ready.

Add ldlm_lock flag LDLM_FL_PLACEHOLDER to indicate a lock is a
placeholder lock.  It lives in client-only flag space (bit 33), above
the 32-bit on-wire mask, so it can never leak into a transmitted flag
set.  Add ldlm_cancel_flags LCF_PLACEHOLDER to scope the cancel to
placeholder locks only.

Placeholder locks are never replayed: ldlm_chain_lock_for_replay()
skips them.  A placeholder is client-only, granted locally without an
RPC (the server has no record of it) and marked LDLM_FL_LOCAL_ONLY, so
replaying one would leave a phantom grant on the OST after the silent
cancel.  They are dropped, and their possibly-stale reconstructed
pages flushed, by the existing osc_import_event(IMP_EVENT_ACTIVE) path
after recovery.

When a failed sub-lock enqueue cannot be converted to a placeholder,
the enqueue failure is tolerated as before, and the new
ci_ec.ec_unprotected_recovery flag tells vvp_io_ec_rd_end() to drop
Uptodate on the reconstructed pages at IO end, since nothing would
flush them later.

Export symbol ldlm_lock_create/ldlm_lock_destroy/ldlm_lock_enqueue/
ldlm_cli_cancel_unused/ldlm_cli_cancel_unused_async for use in other
modules.

Add cl_lock_cancel() before cl_lock_fini() in the lov_lock_sub_init
error path so initialized sub-locks are properly cleaned up.
lov_lock_cancel() also calls cl_lock_cancel() with every sublock with
sub_initialized set rather than only sub_is_enqueued, so that
placeholder locks are cancelled and normal locks w/o enqueue are
also cancelled.

Placeholder locks are client-only with no LVB data (lvb_len 0), so
prune only needs to clear l_ast_data.

Add test_49a checks: a second read of the degraded file must not touch
the OSTs (the reconstructed pages stay cached), reactivating an OST
must invalidate those pages, and a stripe whose stale LSS_READ_ERR
outlives recovery must not leave stale reconstructed pages behind
after a second mount rewrites the file.
