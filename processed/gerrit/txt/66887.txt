LU-20373 build: switch to kvfree_atomic

Linux commit v7.1-rc2-2-gdad0d91cc2c3e
  mm/slab: Add kvfree_atomic() helper

Which can directly replace use of vfree_atomic() in Lustre

Maintain the fallback to compat_vfree_atomic() and provide
a kvfree_atomic() wrapper when it is not available.

Since in the future a caller could pass a kmalloc'd address
to kvfree_atomic(), use kvfree() in compat_vfree_atomic()

AI code review results below, please doublecheck

Some concerns, see inline comments. The main one is that HAVE_KVFREE_ATOMIC_EXPORTED answers "is the symbol exported", but the header uses it to decide whether to define a function named kvfree_atomic() - and on 7.1 the kernel already declares that name in <linux/slab.h>. A negative detection is therefore a build failure rather than a graceful fallback, so it may be safer to base the guard on a compile test for the declaration (LB2_LINUX_TEST_SRC/RESULT) instead of an export check.
