LU-20791 efalnd: Don't update last use time on init conn inspection

Looking up a connection updates its last use time, which is what keeps
the idle timeout from expiring. That is correct when the caller is about
to send or receive on the connection, but the probe handler also looks
up the initiator connection purely to check whether it has gone stale
and needs to be deactivated. When the epoch matches nothing else happens
to that connection, yet its idle timeout has just been extended.

The effect is that a peer which keeps probing keeps our initiator
connection alive even though we never use it, holding on to the device
resources it owns. A connection's idle timeout should reflect our own
traffic, not the peer's.

Pass whether the lookup should update the last use time, and have the
probe handler ask for a lookup that leaves it alone. Every other caller
is about to use the connection and keeps the current behaviour.
