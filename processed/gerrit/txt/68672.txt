LU-18598 mdt: take UPDATE lock of migration source

Migrating a file that has more than one hard link decrements its link
count once per extra link (mdd_update_link()) and then destroys it, but
the source is locked with LOOKUP|XATTR|OPEN only.  The other names of
the inode are meant to be covered by name locks, and they are not: the
parent PDO lock covers the migrated name only, and
mdt_migrate_links_lock() deliberately skips a link whose parent is
already the source or the target parent.  A second name of the same
inode in either of those directories is therefore unlocked, and an
unlink of it - which needs EX UPDATE of the inode, a bit migration
never takes - can drop the link count to zero and destroy the object in
the window where mdd_migrate_create() has released the source object
lock.  osd_ref_del() then only warns about nlink == 0 and
mdd_migrate_create() destroys the object a second time, hitting
ASSERTION( !lu_object_is_dying(dt->do_lu.lo_header) ) in osd_destroy().

Take MDS_INODELOCK_UPDATE of the source as well when the inode itself
is migrated, so that everything which changes its link count is
excluded for the whole migration.  Dirent-only migration goes through
mdd_migrate_update(), which never touches the link count, and is left
alone so that directory restripe does not revoke a client attribute
lock per entry.

Also return the real error from mdt_rename_source_lock() rather than 0.
Both mdt_reint_rename() call sites already tested the return value, but
a failed mdt_object_lock() of the source was swallowed there too, and
rename went on to mdo_rename() with the source unlocked.
