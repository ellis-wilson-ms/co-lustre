LU-20869 tests: merge sanity 133f and 133g

sanity tests 133f (client) and 133g (server) each run
badarea_io over the proc files and then end with a
cleanup/setup remount, because the writes can leave
tunables set to garbage.  The test bodies take a few
seconds; the remount is 60 to 150 seconds each.

Fold the server part into 133f so one remount follows
both the client and server writes, and remove 133g.  If
the MDS or OST is nodsh only the server part is skipped.
A badarea_io failure no longer ends the test, so the
server part and the remount still run after it.

Measured on a single-node rocky9 setup, 133f and 133g
took 47 s each, and the merged 133f takes 64 s.  In CI
133g averages 207 s over 14479 runs per 30 days.

133g rarely fails: 9 failed sessions out of about 78000
suite runs in 90 days (11 failures, all on 4 in-flight
changes).  Its Maloo history ends with this change, and
a standalone ONLY=133f now also runs the server part.

Test-Parameters: trivial testlist=sanity env=ONLY=133f
