LU-19569 tests: fix sanity-lfsck test_45 ENOSPC on a small OST

sanity-lfsck formats small OSTs (100MB, 300MB on ZFS), and test_45
forces a 30MB write onto OST0000 with "setstripe -i 0 -c 1".  In
aggregate runs that dd fails with ENOSPC:

  dd: error writing '/mnt/lustre//f45.sanity-lfsck-0': No space left on device
  sanity-lfsck test_45: @@@@@@ FAIL: write /mnt/lustre//f45.sanity-lfsck-0 failed

The OST is not out of space when it refuses the write.  The BRW that
fails returns rq_status 0 with no transaction and carries -ENOSPC only
in the per-niobuf rc vector, which is the ofd_preprw_write() path that
sets lnb_rc = -ENOSPC for buffers whose OBD_BRW_GRANTED was cleared by
tgt_grant_check().  That happens when tgt_grant_space_left() -- the
cached os_bavail minus tgd_tot_granted -- falls below one RPC, and it
did so while the client's own statfs still reported 58MB free on that
OST.  Checking "lfs df" before the write does not help: ofd_statfs()
subtracts dirty and pending from os_bavail, but not the space already
granted to the other client mounts, so the free space it reports is not
the space the OST can still hand out.

Ask for less space, and free some before asking: unlike most subtests
here, test_45 never called check_mount_and_prep(), so what the
previous subtest wrote -- lfsck_prep() copies the test scripts, some
5MB today -- was still sitting on those OSTs.  Run it, wait for the
unlinks to be destroyed, hand back the grant the clients are not using,
and put the file on the OST with the most grantable space rather than
on OST0000 unconditionally.  The grant shrink reaches the OSTs
asynchronously, so the measurement is retried for a few seconds before
giving up.  "setstripe -i" is only a preference: when the requested OST
cannot take the object lod_ost_alloc_specific() moves on to the next
one, so where the object landed is checked before it is written to,
and the subtest gives up rather than measure one OST and fill another.
The stop/mount/chown/start of the backing filesystem and the LFSCK
status wait follow the OST that was picked instead of always ost1.
The file is removed when the test ends so it does not eat into later
runs.

The test file also moves to $DIR/$tdir, which check_mount_and_prep()
creates.  It was written as $DIR/$tdri, and as nothing sets $tdri it
landed in the root of the mount -- the doubled slash in the failure
quoted above.

Reproduced by mounting eight extra client instances so that OST0000
holds 62668KB free but 44966464 bytes granted: the unpatched test fails
with ENOSPC after 25 of 30MB, while the patched test passes.
