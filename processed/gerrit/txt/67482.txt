--- Commit Message ---
LU-20354 qmt: add per-slave quota usage cache for GETQUOTA

Let QMT serve aggregated quota usage from an in-memory per-slave
cache instead of always returning zero and forcing clients to fan
out to every OST/MDT.

Warm the cache from QSD DQACQ/REL piggybacked qb_usage, and refresh
stale or missing entries via OSP quotactl proxied through MDT. If a
per-slave usage fetch fails, fall back to granted from that slave's
local index file so other slaves' usage remains usable. Set
QIF_SPACE only when both DT and MD aggregates succeed so llite still
fans out on partial failure; set QIF_INODES from MD alone. When no
usable aggregate is available, omit QIF_SPACE/QIF_INODES and keep
legacy client fan-out.

Expose qmt.*.usage_cache_ttl (seconds; 0 means never expire) and
qmt.*.usage_cache_stats (hit/miss/proxy_rpc/fallback). Negotiate
OBD_CONNECT2_QMT_USAGE_CACHE on LWP so slaves can report qb_usage.
Pool membership is kept in sync via extend/shrink callbacks, and
the usage-cache lifetime follows the lqe.

Add sanity-quota/310.
