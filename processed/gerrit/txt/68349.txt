LU-10026 osc: limit compression chunks in RPC

Limit the number of partial compressed chunks that can be sent to
the server in a single RPC, so that it doesn't need to allocate
buffers for read-modify-write on a huge number of chunks at once.
It is better to handle that in separate server threads.

In the worst case, each extent in the BRW RPC belongs to a different
compression chunk, so the worst_case_chunks would expand on the OSS
to worst_case_chunks * compression_chunk_size bytes IO on the server.
That might be hundreds of MB in size per thread and LASSERT or OOM.

Add tunable osc.*.compress_rpc_fragment_ratio to reduce the maximum
compressed chunks by the given factor, its value ranges in [1, 32].

osc: scan extents to find compression chunks

as we can't trust oe_start and oe_end, we have to scan all the
pages covered by extent and so find all compression chunks to
estimate and limit potential read-modify-write IO on OST.

osc_submit_io() should not create too big extents we can't send
due to limits for compressed chunks.
