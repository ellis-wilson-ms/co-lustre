LU-17240 tests: unmount targets in parallel

stopall() unmounts every MDT and every OST one at a time, even when
they are on different nodes, and conf-sanity and other scripts do
this many times per run.

Unmount all MDTs in parallel, then all OSTs in parallel, using
parallel_start() and parallel_wait() in a new unmount_facets().  The
MGS is still stopped last, and MDTs are all stopped before the OSTs.
stop() restores the <facet>_dev variables when it removes a
dm-flakey device, and these are imported from the background
subshells by parallel_wait().

Remove the <facet>active files only after all stop() calls finish,
since stop() uses them to find a failed-over host.  Unload dm-flakey
once after all stop() calls finish, since a concurrent unload from
dm_cleanup_dev() can make dm_flakey_supported() fail for another
target, leaving its dm device behind.  unmountmds() and unmountoss()
now return an error if stop() failed for any target, which
replay-single test_135 checks.

Return the umount error from stop(), since "set -e" does not apply
when it is called as "stop ... || rc=$?" in unmount_facets().  It
also does not apply inside subtests, so the "stop <facet> || error"
callers there never saw a failed umount before and may now report
one.

Parallel unmount is on by default and controlled by:
- PARALLEL_UMOUNT: unmount targets concurrently ($PARALLEL_OPS)
- PARALLEL_UMOUNT_TARGETS: target types unmounted concurrently
  ("mdt ost")

stopall() of 2 MDTs and 6 OSTs on one 4-CPU VM, 3 runs:

           serial  parallel
  stopall()  35s     13s     (-62%)
