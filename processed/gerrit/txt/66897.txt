LU-20290 lnet: test NUMA-grouped discovery views

Add sanity-lnet coverage for the numa group source.

test_632 brings up two nets on one interface under
lnet_group_numa_nets and checks both directions. Sub-case A arms a
test-only fault injection that overrides the bucket key so the two
NIs fall in two groups, and asserts discovery keeps them as separate
peers. Sub-case B repeats the same one-interface setup with the
override disarmed: both NIs read the same ni_dev_cpt, so they form
one two-NID group, a GET on one returns both NIDs, and discovery
coalesces them into one multi-rail peer -- the positive control that
proves the split in A came from the override.

A single-NUMA VM cannot produce distinct ni_dev_cpt (every NI reads
the same value), so the test reads dev cpt only to assert the host is
single-NUMA (both equal) and verifies the split by the separate-peers
outcome, not by a differing dev cpt.

test_633 adds a third NI on an unlisted net and asserts a grouped NID
returns only its group's two members while the ungrouped NID is
permitted the full view, so a grouped NIC never leaks the merged
view.
