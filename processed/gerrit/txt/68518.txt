LU-17000 lfsck: clear the target bit when removing a target

lfsck_del_target() sets the target's bit in ltd_tgts_bitmap instead of
clearing it, so a removed target stays in the map for good.  Every
consumer walks the map with for_each_set_bit() and then asserts the
descriptor it gets back is not NULL - lfsck_lib.c:2481, 2923 and 3229,
and the same pattern in lfsck_engine.c, lfsck_layout.c and
lfsck_namespace.c - but lfsck_assign_tgt(ltds, NULL, index) on the very
next line has just emptied that slot.  The next LFSCK operation to walk
the map LBUGs the server.

The inversion came in with a mechanical conversion of the bitmap API:
cfs_bitmap_clear() became set_bit() rather than clear_bit().

Reaching it needs a target removal while an LFSCK instance is still
registered, which today means an LCFG_LOV_DEL_OBD config record.  The
other caller of __lod_del_device(), lod_fini_tgt(), runs during teardown
after mdd_device_shutdown() has already called lfsck_degister(), so
lfsck_del_target() returns at the instance lookup before it reaches the
bitmap.  So this is latent rather than something an administrator hits
today, unless the filesystem still carries such a record.
