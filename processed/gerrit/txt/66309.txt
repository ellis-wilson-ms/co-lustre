LU-20099 nrs: combine reserved rate and weight for mClock

Under the reserve plus weight dimension set, each class keeps its
floor. The weight splits the total service of the classes. Each
floor is a lower bound on that split. A dispatch from the reserved
tree also charges the weight tag. Thus a class with a high floor
gets less of the surplus, or none of it. With the limit dimension
off, a rule has no ceiling. The limit plus weight set has no
reserved tree. mClock and dmClock read a zero reservation as no
floor.

The rule dump now shows the weight of a rule.

Add sanityn/test_77v{i,n}, and move the scenarios of test_77vh into
one helper. In test_77vh, the higher weight flow now needs 1.5 times
the IOPS and the bandwidth of the lower weight flow. The function
cleanup_77v() no longer fails the test when a rule stop or a file
removal fails. The check of a start command with no dimension key
moves to test_77vn.

On a client with more than one NID, test_mclock_two_flows() adds a
UDSP rule. The rule sends every request over the first NID. LNet
binds each NID to one CPU partition on the OSS. A rule rate applies
to each partition. The pin keeps both flows in one partition. fio
now gets --max-jobs. The default job table of fio takes about
740 MiB for each fio process.

In the run below, flow 1 stays near its floor. Flow 2 gets the
remainder, which is more than the surplus of 837 IOPS.

    resv1   w1      resv2   w2   |  iops1   iops2   sum
    5000    100     600     200  |  4801    1636    6437
