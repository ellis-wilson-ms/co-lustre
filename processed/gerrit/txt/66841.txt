--- Commit Message ---
LU-11081 lfsck: recreate the LOV EA with DoM stripe

For DoM file, the LFSCK should recreate the LOV if it is corrupted
or missing, and it will try to shrink/grow the DoM stripe based on
the normal OST stripe.

The repair only runs when the option "-o" (LPF_OST_ORPHAN) is given
for normal files and the MDT object is checked whether it holds data
by probing it with dt_lseek(..., SEEK_DATA) (twice, to also reject
files with data at or beyond the 4GB DoM limit); the file size
shouldn't exceed the maximum DoM size (UINT_MAX).

A new type LLIT_DOM is added to "ll_objs_repaired" to count the
repaired DoM file, the new counter is taken from the reserved space
("ll_reserved_2" is shrunk from 7 to 6), so "struct lfsck_layout"
keeps 256-byte size, the LFSCK_LAYOUT_MAGIC is bumped from V4 to V5.

A new KEY_MAX_DOM_STRIPESIZE key is introduced in lod_obd_get_info()
to get the maximum DoM stripe size.

The check in lfsck_layout_verify_header_v1v3() on DoM entry is also
enabled because the DoM layout will be handled in this patch.
