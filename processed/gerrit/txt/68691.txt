--- Commit Message ---
LU-20669 snapshot: use a mirror as template to create new mirror

This patch implements the basic snapshot feature to create a new
mirror using a specified existing mirror as the template. The
new mirror has the same layout with its corresponding data stripe
objects located on the same OSTs as the template mirror.

Template mirror creation for Data-on-MDT (DoM) components is
not supported right now.

Add sanity-lsnapshot/test_5{a,b,c,d} to test the new feature.

Some concerns, see inline comments. The main one is that the new mirror is created empty but is never marked LCME_FL_STALE, so once the layout lands a client can pick it as its preferred read mirror and read zeros instead of the file data; test_5{a,b,c,d} only compare OST indices, so none of them would catch that. It would also be worth adding a case that writes a known pattern, creates the snapshot mirror and re-reads the file (and one that reads through each mirror explicitly with `lfs mirror read`). Separately, these are FLR mirror tests rather than lctl/ZFS filesystem-snapshot tests - would sanity-flr.sh be a better home for them than sanity-lsnapshot.sh, so the suite-wide ZFS gate does not have to be unwound per-test?
