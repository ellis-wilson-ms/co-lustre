LU-20894 compat: test for core XArray not CONFIG_XARRAY_MULTI

LU-19179 changes removed the copy of XArray from the Lustre tree and
relied on the in-kernel implementation; an autoconf test was added in
case there was no XArray support in the kernel, but it checked for the
presence of CONFIG_XARRAY_MULTI, which does not denote core XArray
support, but an XArray feature for supporting entries which occupy
multiple consecutive indices in the XArray, for increased efficiency.
This additional multi-index functionality is not currently used by
Lustre, though, so it should not be considered a requirement.

LU-19179 made the assumption that CONFIG_XARRAY_MULTI should be set in
virtually all distribution kernels, as it is selected by
CONFIG_ZONE_DEVICE, which was expected to also be normally set and
added a configure check for CONFIG_XARRAY_MULTI, so that the build
would fail, just in case it isn't set. However, it seems to be
possible to have at least some SLES 15 SP2/SP3 (probably
custom-config) kernels in practice (and this should be possible with
kernels for any distribution, or vanilla ones) that include core
Xarray support, but do not have CONFIG_ZONE_DEVICE (or
CONFIG_TRANSPARENT_HUGEPAGE, which also selects CONFIG_XARRAY_MULTI)
set, so CONFIG_XARRAY_MULTI is not set either, which causes the build
to fail at the configure stage.

Reinstate the previous autoconf test, that detected the presence of
XArray support in the kernel via a compilation test of xa_is_value(),
in order to address this issue.
