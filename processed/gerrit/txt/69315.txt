--- Commit Message ---
LU-20791 efalnd: Make connection last use time atomic

The connection last use time is updated whenever a connection is looked
up, and lookups only take a read lock on the NI connection lock, so
several CPUs can update the same connection at once on every send and
every receive. The connection daemon also reads it while draining
connections without taking that lock at all.

On 64 bit a naturally aligned 64 bit access is indivisible, so a reader
always sees either the old or the new timestamp and never a mixture of
the two. The races are therefore harmless in practice.

Make the field atomic, as the TX send time already is. Reading and
setting an atomic are relaxed operations that compile to a single load
or store on 64 bit, so nothing gets slower.
