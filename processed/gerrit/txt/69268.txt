LU-20808 tests: count remote-parent mkdir RPCs

Add sanity tests for mkdir under a parent on another MDT with DNE lock
intents. Each counts, from the OSP stats, the OUT_UPDATE and
LDLM_ENQUEUE RPCs that the MDT creating the child sends to the
parent's MDT, and compares the result with a child made where no
intent is involved. ptlrpc leaves LDLM_ENQUEUE out of its per-opcode
counts, so the enqueues are read from ldlm_ibits_enqueue.

 1000a  owner and mode, as root and as a user; the parent's link
        count; many creates of one name at once; a name that already
        exists, which takes the parent locks once and is then looked
        up without them
 1000b  a parent with S_ISGID
 1000c  a parent with a project ID to inherit
 1000d  a default ACL small enough to come back with the lock, one too
        large for that, and write permission granted by an ACL only,
        and then taken away, which the MDS itself has to refuse
 1000e  default file layouts - plain, PFL, and one too large for the
        reply - the default directory layout, and the pin

The budgets are what the intent leaves: one transaction, an attribute
read before the lock, and a read that appending to the update log may
need, plus one read for a value too large for the reply. Without the
intent, the same operations exceed them.

The tests skip on a filesystem with a single MDT, and unless MDT0 and
MDT1 have agreed on OBD_CONNECT2_DNE_INTENT with each other.

Test-Parameters: mdtcount=4 mdscount=2 testlist=sanity env=ONLY=1000
