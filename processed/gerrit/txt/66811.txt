LU-20420 llite: fix UID/GID on OST object for OST_PUNCH

When a file is truncated, the client builds an OST_PUNCH RPC that
carries UID/GID/PROJID. For a freshly created object these IDs are
what initialize the OST object's ownership, and therefore which
user/group the object's block quota is charged to.

cl_setattr_ost() used current_uid()/current_gid() instead of the IDs
from the file being truncated. This patch fixes this issue so the OST
object's quota is attributed to the file owner. This also fixes group quota accounting for files in setgid (SGID) directories, whose group is inherited from the directory and may differ from the truncating user's group.

Test sanity-sec/75 was modified to test this case while considering
interop when older clients are run.
