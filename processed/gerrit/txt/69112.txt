Some concerns, see inline comments. The e2fsck part does not appear to actually preserve the output for the failure case: run_e2fsck() always returns 0 (it calls error() itself on a real fsck failure, which exits), so the new `|| { cat $tempfile; }` blocks can never run and the captured output is dropped by the stack_trap. Doing the capture inside run_e2fsck() itself, into a file under $LOGDIR that is collected with the test logs and only removed on success, would cover sanity 17n/804 plus the sanity-scrub and conf-sanity callers in one place.
