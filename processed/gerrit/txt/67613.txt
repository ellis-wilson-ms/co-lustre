LU-19994 ec: block LCME_FL_PARITY flag changes

The LCME_FL_PARITY flag is reserved for EC parity mirrors that are
created implicitly by the --ec option.  It must not be settable on a
file layout component through "lfs setstripe --comp-set
--comp-flags=parity", nor clearable with "^parity", on either a
plain data component or the data component of an EC file.

The set of component flags that users may not set or clear on an
existing component, LCME_FL_INIT and LCME_FL_PARITY, was open-coded in
both llapi_layout_file_comp_set() and lod_declare_layout_set(), and
the same pair was reused as the keep-mask in mdd_split_ea().  Three
copies of one constant invite drift: adding another internal flag
later would have to be remembered at every site.

Hoist it into LCME_INTERNAL_COMP_FLAGS in lustre_user.h, next to the
existing LCME_USER_COMP_FLAGS, and use it at all three sites.

Also correct the LCME_USER_COMP_FLAGS comment.  LCME_FL_PARITY was
added to that mask by 782f0899635a ("LU-12186 utils: Add parity flag
to correct places"), but LU-19994 now rejects it on an existing
component, so "creation/modification time" is only accurate for
creation.
