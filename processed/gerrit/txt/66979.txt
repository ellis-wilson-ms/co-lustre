LU-20080 quota: fix qsd_fini() vs qsd_op_end() race

Add transaction counter per qsd instance. Increment it in qsd_op_begin
for each lqe added to quota transaction array. Decrement it in
qsd_op_end and wake up appropriate qsd instance that might wait in
qsd_fini. Patch fixes a panic with backtrace:

  BUG: unable to handle kernel NULL pointer dereference at 0000000000000060
  ...
  RIP: 0010:qsd_op_end+0x99/0x340 [lquota]
  ...
  Call Trace:
  osd_trans_stop+0x363/0xaa0 [osd_ldiskfs]
  mgs_nidtbl_write+0x949/0xb20 [mgs]
  mgs_ir_update+0x79/0x2a0 [mgs]
  mgs_target_reg+0xcd3/0x1eb0 [mgs]

Cleanup qsd_op_end. Qids involved in a transaction may relate to data
as well as to metadata qsd instance. That said, it is not correct to
pass to qsd_op_end pointer to only one of QSDs. This pointer should be
better accessed through the lqe.

Fixes: b2cb6fd109 ("LU-1842 quota: add core QSD code")
