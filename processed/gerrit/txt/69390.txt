LU-20869 tests: shorten sanity 255a

sanity test_255a spends nearly all of its time in
ladvise_willread_performance(), which does 10 iterations of
three passes that each do 25600 random 4KiB reads of a 100MB
file.  Those 30 passes of synchronous reads, each capped at
60 seconds, take 1000-2000 seconds in CI.

Do an eighth as many reads per pass and run 3 iterations
instead of 10.  The file stays 100MB, so the cold OSS cache
versus willread comparison is unchanged; only the number of
samples averaged shrinks.

The willread threshold compared the willread speedup in
percent with half the cached read rate in MB/s, a mixup
reintroduced by LU-17527.  Fewer reads lower the absolute
rate, which would move that threshold, so compare with half
the cached read speedup instead, as originally intended.

On a test VM cluster, ONLY=255a took 1089s and 2017s before
and 170s, 166s, 137s and 252s after (the spread is VM disk
speed; the slow runs hit the 60s per pass cap).

Test-Parameters: trivial testlist=sanity env=ONLY=255a
