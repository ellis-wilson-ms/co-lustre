LU-20216 rustreapi: version-cfg cleanup, bitflags migration

Two related cleanups: tighten the version-cfg story across the
crate, and convert the bitmask types to `bitflags!` so per-variant
cfg gating actually works.

1. Version-cfg cleanup
----------------------

`lu-version` sets `LUSTRE_2_N` cumulatively (every supported build
sets `LUSTRE_2_14`), and refuses to set up a build for minor < 14.
Together those make `cfg(not(feature = "LUSTRE_2_14"))` always
false, so any code under it has been dead since the cfg was
written.

The intent of the existing `not(2.14)` cfgs was clearly "newer
than 2.14": their bodies use C symbols
(`LLAPI_LAYOUT_WIDE_MIN/MAX`, `LLAPI_OVERSTRIPE_COUNT_MIN/MAX`,
`llapi_layout_v2_sanity`) that only exist in newer Lustre.  Survey
across the 2.15/2.16/2.17 worktrees shows all five symbols first
ship in 2.16, so:

- Five sites in `lib.rs` and `layout.rs` move from
  `cfg(not(feature = "LUSTRE_2_14"))` to
  `cfg(feature = "LUSTRE_2_16")`.  This makes `LAYOUT_WIDE_MIN/MAX`,
  `OVERSTRIPE_COUNT_MIN/MAX`, and `Layout::sanity_v2` callable from
  Rust on 2.16+ for the first time, instead of being permanently
  dead.
- The duplicate cfg'd `LayoutGetFlags` / `CompEntryFlags` enums in
  `layout.rs` collapse to the single (formerly-dead) modern form,
  with `Compress`/`Partial`/`NoCompr`/`Parity` correctly gated by
  `LUSTRE_2_16` (where those C `LCME_FL_*` flags were added).

Same exercise on the symbols that were used unconditionally but
aren't actually present on the released 2.15 client (lfs 2.15.8):

- `Fid::open_at`, `open_by_fid_at`, and the `llapi_open_by_fid_at`
  import gain `LUSTRE_2_16` gates (the function isn't in 2.15
  headers).
- `mdt_count` and `get_lmv_uuids` move to `LUSTRE_2_17`: the
  `llapi_lmv_get_uuids` prototype is in headers from 2.15 onwards,
  but the symbol is not exported by liblustreapi until 2.17, so
  this is a header/library skew the version-cfg scheme cannot
  detect on its own.

Two adjacent 2.15-build hygiene fixes that surfaced once correct
cfgs let the 2.15 build proceed:

- Add the explicit headers (<errno.h> <fcntl.h> <stdlib.h>
  <string.h> <unistd.h>) that newer Lustre headers happened to pull
  in transitively but 2.15's do not.
- Allowlist the `llapi_layout_comp_use` enum in `lustreapi-sys` so
  its constants come through on 2.15 (the type is in the headers
  but bindgen drops it without an explicit allowlist).

2. bitflags migration
---------------------

Per-variant cfg gating of `LCME_FL_PARITY/COMPRESS/PARTIAL/NOCOMPR`
in `CompEntryFlags` and `HS_PCCRW/PCCRO` in `HsmState` is part of
the cleanup above, but bitmask-enum's proc-macro does not
propagate `#[cfg]` to all of its expansions (FLAGS array,
vec_debug, all_flags), so cfg on a variant breaks the generated
code.  Convert all bitmask-enum users (`HsmState`,
`CompEntryFlags`, `HsmRequestFlags`, `ChangelogFlag`,
`ChangelogExtraFlag`) to `bitflags!`, which forwards `#[cfg]`
faithfully and, with its `serde` feature, yields native serde
support.

Net dep changes: add `bitflags = { features = ["serde"] }` to the
workspace, drop `bitmask-enum` entirely.

Wire-format change: the bitmask-enum-generated structs derived
their `Serialize`/`Deserialize` field-by-field, producing JSON like
`{"bits": 5}`.  bitflags' built-in serde produces a human-readable
string (`"FOO | BAR"`) for human-readable formats and raw bits for
binary formats.  This is a breaking change for any consumer
deserializing the old `{"bits": N}` shape.  The `Debug` format also
changes (`HsmState[Exists, Archived]` -> `HsmState(Exists |
Archived)`), which required updating two stored insta snapshots.

Sweep `none()` -> `empty()`, `all_bits()` -> `all()`, and
`Self::from(u32)` -> `Self::from_bits_retain(u32)` across tests,
examples, and `hsm/copytool.rs` to match the bitflags API.

Verification
------------

Verified on lustre-builder containers for 2.15.8, 2.16.1, 2.17.0,
and master (2.17.52): `cargo test -p rustreapi --lib` and
`cargo clippy --workspace --all-targets` are clean on all four.
Integration tests (`tests/hsm_test`, `tests/layout_test`) pass
30/30 and 40/40 against a live cluster (lfs 2.17.51).
