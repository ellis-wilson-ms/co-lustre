LU-19783 lfsck: fix MDT orphan by LFSCK

This patch adds a new option "-O | --mdt-orphan" in "lfsck_start"
to check the possible MDT orphan, which is no "linkEA", owned by
non-root user and group, old enough since its creation time,
(the timeout can be specified by "-T | --mdt-orphan-timeout"), and
the size is 0. It will be moved into ".lustre/lost+found".

Before recording a possible orphan MDT-object during the first-stage
scanning, check and skip it if it is still tracked in the MDT PENDING
directory, because these objects will be handled by the MDD orphan
subsystem.

The "struct lfsck_bookmark" is modified, then this patch adds the
corresponding check during setup and load.

It introduces a new failure injection "OBD_FAIL_LFSCK_MDT_ORPHAN"
to create an orphan object in MDT, which will be fixed by LFSCK
in the newly added test in sanity-lfsck.

Use plain bit numbers in "enum lu_object_header_flags" instead of
BIT(n), since loh_flags is only used with set_bit()/test_bit(),
which take a bit number rather than a mask, BIT(n) only worked by
accident, and the next flags would eventually overflow loh_flags.

It also adds check on "test_45" in "sanity-lfsck" to verify LFSCK
is completed, which should check on "SINGLEMDS" instead of "ost1",
otherwise the LFSCK could still be running on the "SINGLEMDS" and
affect the follwing test.
