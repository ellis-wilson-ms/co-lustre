--- Commit Message ---
LU-20553 mdd: detect DoM on SEL layouts in mdd_lmm_dom_size()

mdd_lmm_dom_size() only matched LOV_MAGIC_COMP_V1, so a DoM component
paired with an extension component (lcm_magic == LOV_MAGIC_SEL) was
treated as non-DoM. That skipped the LA_SIZE workaround in mdd_attr_set
and let full layout swap proceed without the DoM guards.

Recognize SEL so DoM detection matches the actual composite layout for
those call sites. mdd_xattr_split is unaffected: it rejects SEL with
-EINVAL before mdd_lmm_dom_size(), and builds buf_vic as plain COMP_V1.
Mask LOV_MAGIC_DEFINED only for consistency with mdd_lmm_oi()/mdd_lmm_gen();
callers pass on-disk EAs or pre-DEFINED swap buffers and never set the
bit here.

Fixes: 4c7fe0c7cdae ("LU-10070 lod: SEL: interoperability support")

Mostly good, comments inline. The DoM-on-SEL detection itself looks right, and DoM+extension layouts are a real supported combination (sanity-pfl test_21a/21b build them). There is no test though: a regression case that truncates a `-E 1M -L mdt -E -1 -z 64M` file, and one that migrates it, would cover both behaviors this changes. Note also that mdd_object.c still has several other `lcm_magic != LOV_MAGIC_COMP_V1` gates that reject SEL outright (mdd_xattr_merge, mdd_xattr_split, mdd_layout_change) - worth saying whether those are deliberately left for a follow-on.
