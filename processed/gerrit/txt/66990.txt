(1 comment)

Experimental feature testing in progress, please pay attention to the comments

The fix itself looks correct: fld_range_set_ost()/_mdt()/_any() OR into lsr_flags (range->lsr_flags |= flags), and both callers reuse the persistent oti_seq_range buffer, so a stale type bit from a prior lookup can turn an OST range into ANY, or an MDT range into OST/ANY. Zeroing lsr_flags first restores the behavior this path had before the wrappers were introduced.

This is a bug fix (sanity test_230k migrate failure), so a Fixes: tag would help backport tracking. The assignment that used to clear the field was replaced by the OR-based wrappers here:

    Fixes: ec0c7b569d5a ("LU-2681 fld: shrink seq_type in lsr_flags")

Before that commit this function did range->lsr_flags = LU_SEQ_RANGE_OST (plain assignment); it changed those to fld_range_set_ost() etc., which OR the bits in.
