LU-19179 o2iblnd: read SG_GAPS cap from kernel_cap_flags

Linux 5.15 commit e945c653c8e97 ("RDMA: Split kernel-only global
device caps from uverbs device caps") moved SG_GAPS registration
support out of ib_device_attr::device_cap_flags and into the
kernel-only ib_device_attr::kernel_cap_flags, renaming the flag from
IB_DEVICE_SG_GAPS_REG to IBK_SG_GAPS_REG.

We compat-define IBK_SG_GAPS_REG back to IB_DEVICE_SG_GAPS_REG on
older kernels, so a single test of device_cap_flags is correct there
but wrong on 5.15 and newer, where the driver reports the capability
in kernel_cap_flags. mlx5 sets IBK_SG_GAPS_REG in kernel_cap_flags,
so IBLND_DEV_CAPS_FASTREG_GAPS_SUPPORT is never set on ConnectX and
use_fastreg_gaps=1 silently keeps allocating IB_MR_TYPE_MEM_REG.

Worse, the bit is not spare: IBK_SG_GAPS_REG is 1 << 3, and bit 3 of
device_cap_flags is IB_DEVICE_RAW_MULTI. A device advertising raw
multicast would get SG_GAPS MRs it never claimed to support.

Select the field along with the flag. Add ib_sg_gaps_reg_supported()
to the rdma compat header so the flag and the ib_device_attr member
that carries it stay together.
