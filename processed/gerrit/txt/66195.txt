## Explanation of the Fix

**Problem:** The patch applied an incorrect transformation on line 161 of `lnet/lnet/acceptor.c`, changing:
```c
lsock = kmalloc(sizeof(*lsock), GFP_KERNEL);
```
to:
```c
lsock = kmalloc_obj(*lsock, GFP_KERNEL);
```

**Issue:** The function `kmalloc_obj()` does not exist in the Linux kernel API. This was an erroneous "fix" applied by `checkpatch.pl --fix-inplace`.

**Solution:** Reverted the incorrect change back to the proper kernel memory allocation function `kmalloc(sizeof(*lsock), GFP_KERNEL)`.

**Rationale:** 
- `kmalloc()` is the standard kernel function for allocating memory
- The `sizeof(*lsock)` idiom is a common C pattern that calculates the size of the type that `lsock` points to (in this case, `struct listening_socket`)
- `kmalloc_obj()` appears to be a non-existent function that checkpatch mistakenly tried to use, possibly confusing it with some project-specific macro or misinterpreting coding style rules

The fix restores the correct, working memory allocation call that was present before the patch was applied.
