LU-18456 mdt: fix trash dir setup issues found in review

This is a follow-up fix for
LU-18456 mdt: create trash dir for MDT after MDT stack setup:
https://review.whamcloud.com/61977

It addresses the review comments on the trash directory setup. The
main changes, listed in order:

1. Give the trash setup kthread a session and credentials; otherwise
   lu_ucred() returns NULL in mdd_create_object(). That does not
   crash. uc->uc_jobid only computes an address (the field is an
   array), and the only read of it sits behind "initial_create &&
   spec->sp_cr_job_xattr[0] != '0'", false for an internal create,
   so this is undefined behaviour and skips jobid/audit steps. Set up
   an LCT_SERVER_SESSION context, point env->le_ses at it and fill
   in mdt_ucred(info)->uc_valid, like mdt_ctxt_add_dirty_flag() does.

2. Make the retry loop back off and be quiet. The sleep before a retry
   is unconditional now (2 seconds, interruptible) and lgt_abort is
   tested before retrying, so a persistent failure (the parent .ltrash
   lives on MDT0 and may not exist yet, or the MDT is read-only) no
   longer spins the thread at full speed and does not delay an umount.
   The error message is rate-limited: it is printed only when rc
   changes, not on every iteration.

3. Convert lum_stripe_offset with cpu_to_le32(), like lum_magic above
   it and like mdt_auto_split_prep() does. The field is little-endian
   and read back with le32_to_cpu(); without the conversion a big
   endian MDS stores 0x01000000 for index 1 and lod_declare_create()
   then finds no MDT to use for the create.

4. Declare index as __u32. server_name2index() takes an __u32 * and
   passing int * is an incompatible pointer type.

5. Only continue after the locked lookup on -ENOENT, mirroring the
   lockless lookup above it. A transient error from a remote parent
   (-EIO, -ENOTCONN, -ETIMEDOUT) is not turned into a create any more,
   and the real error is no longer replaced by what mdo_create()
   returns.

6. Create the per-MDT directory with mode 0500, like .ltrash itself,
   so that it is not created with mode 0000.

7. Drop two redundant NULL checks before OBD_FREE() and shorten a
   comment to a single line.

8. Clear lgt_init in lu_generic_thread_wait() so that the helper can
   be started again after it was waited for, and so that a later
   mdt_trash_setup() starts a fresh thread instead of returning early.
   lu_generic_thread_start() asserts that the flag is false.

9. Use the return value of snprintf() as the length of the per-MDT
   directory name instead of calling strlen() on the buffer again, as
   Oleg asked. The buffer cannot overflow here: mti_filename is
   NAME_MAX + 1 bytes and the name is just "MDT%04x".

10.Change ".trash" in osd_ldiskfs/osc_scrub.c and osd_zfs/osc_scrub.c
   to dot_ltrash_name.

11.Fixed some style and comment problem.
