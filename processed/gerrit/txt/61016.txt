--- Commit Message ---
LU-13638 ptlrpc: delay to handle the req_unlinked

We ignore the req_unlinked flag in sending process
since sometime the reply could be received before
request out callback was invoked. In such case we
should go ahead despite the md unlink ACK. Just
keep the request buffer until it arrived.

AI code review results below, please doublecheck

Problematic, see inline comments. The reference that request_out_callback() used to hold on the request is dropped, and the thing that replaces it is a sticky on-wire flag plus a list that is only drained at module unload. That combination does not seem to hold up: the reference is lost entirely for noreply sends, dropped twice on the ptl_send_rpc() error path, and every request that ever sets the flag is parked on the list forever. It would be worth reworking around the existing rq_req_unlinked state rather than a new pb_flags bit.

Also, recovery-small test_171 does not appear to cover the case the patch is about: with fail_loc 0x538 the callback returns early but LNet has already released the MD, so the request buffer is never really in flight and the module-unload check passes for the wrong reason.
