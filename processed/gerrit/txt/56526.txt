(5 comments)

AI code review results below, please doublecheck

Some concerns, see inline comments.

The mount UUID is purely per-client state, yet this still creates a persistent MDT object to hang it off. Making it a client-side-only pseudo-file under .lustre was raised on an earlier patchset and agreed to be preferable, and the on-disk object does cost something: every cold open now does an intent open plus an immediate MDS_CLOSE from ll_client_uuid_open(), stat() reports size 0 while read() returns 36 bytes, the new FID needs matching osd_dl_maps entries in both OSDs, and a new client talking to an older MDS gets -ENOENT instead of the UUID (which is what breaks the new llapi_fid_test case below). None of that is needed for a pseudo-file.
