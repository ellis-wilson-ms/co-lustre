LU-19932 osc: keep the page fault path off the abortable wait

An mmap store reaches osc_queue_async_io() through page_mkwrite(), so
with the abortable wait it can now come back with -ERESTARTSYS, and
ll_page_mkwrite() has no vm_fault_t that is right for it.
VM_FAULT_SIGBUS kills an application that installed a SIGTERM handler
instead of letting it run.  VM_FAULT_NOPAGE suits a fault taken from
user mode, where the signal is delivered on the way out and the store
simply re-faults, but a fault taken from kernel mode - read(2) copying
into a shared mapping - never dequeues the signal, so the copy
re-executes against the same stalled extent instead of ending through
the exception fixup.  VM_FAULT_RETRY is not available at all:
do_page_mkwrite() calls page_mkwrite() with FAULT_FLAG_ALLOW_RETRY
cleared and only short-circuits on VM_FAULT_ERROR and VM_FAULT_NOPAGE,
so a retry would fall through to folio_lock() with mmap_lock held.

Key on CIT_FAULT rather than on cl_io_is_mkwrite(), so that a read
fault reaching this path would not get an abortable wait either -
to_fault_error() turns -ERESTARTSYS into VM_FAULT_SIGBUS the same way.

Leave CIT_FAULT on the uninterruptible wait, as it is on master, and
keep the abortable one for the write paths that have somewhere to
return the error.

The change itself looks correct: CIT_WRITE and CIT_FAULT are the only two io types that can reach osc_queue_async_io() (cl_io_commit_async() is only called from vvp_io_write_commit() and the mkwrite branch of vvp_io_fault_start()), lov_io_sub_init() copies ci_type into the sub-io, and the do_page_mkwrite() reasoning in the commit message holds.

The wider question is whether this should be a separate commit at all. It only repairs behaviour that the parent change in this relation chain introduces, so if the series lands in order there is a window where an mmap store that hits a stalled extent turns a SIGTERM into a SIGBUS. Folding it into the parent change would keep every landed commit bisectable and would avoid the Fixes: tag problem noted on the commit message.
