LU-20342 lnet: fix deadlocks during module unload

Resolve two critical hangs and a use-after-free during module unload:

1. Fix client-side use-after-free: destroying a session frees its
   client RPCs, but sfw_test_unit_done() -- reached from inside a
   client RPC's own workqueue handler via srpc_send_rpc() ->
   srpc_client_rpc_done() -> sfw_test_rpc_done() -- could reach that
   destruction synchronously. cancel_work_sync() on the
   currently-running work item would deadlock, and skipping the
   wait left a racing re-arm free to run against already-freed
   memory. Defer the destruction to a new fw_reap_wi work item
   instead, so it never runs from within the work item it is
   tearing down.

2. Pin the session (sn_busy) across the window in
   sfw_deactivate_session() where fw_lock is dropped to call
   srpc_abort_service(): the reaper now sweeps every zombie session
   on each run, so without the pin it could free the session out
   from under sfw_deactivate_session() before it comes back to walk
   sn->sn_batches.

3. Fix server-side logical deadlock where aborted RPCs remained in
   the active list forever. Intercept the final UNLINK event in
   srpc_handle_rpc() even if state is SWI_STATE_DONE, ensuring
   srpc_server_rpc_done() is called. A new srpc_completed sentinel
   on struct srpc_server_rpc guards against running that completion
   twice.

4. Prevent use-after-free by calling swi_cancel_workitem() in
   srpc_service_fini() to sync with running workitems before
   freeing; srpc_completed also guards this path against completing
   an already-completed RPC a second time.

5. Split srpc_init_server_rpc() so swi_init_workitem() runs once
   from srpc_service_init(), via srpc_init_server_rpc_workitem().

6. Bump the log-level in srpc_finish_service() to CWARN().
