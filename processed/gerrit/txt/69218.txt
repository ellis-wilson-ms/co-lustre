LU-17768 build: embed BTF in Lustre kernel modules

Out-of-tree modules lack .BTF sections because kbuild's
Makefile.modfinal skips BTF generation without
$(objtree)/vmlinux, which kernel-devel does not ship.

Add config/embed-btf.sh and run it from the modules make
target after kbuild.  pahole encodes a distilled base
(.BTF.base) so the module BTF relocates against the running
kernel at load time.

When the build tree has a vmlinux, kbuild already encodes the
module BTF with the kernel's own pahole flags, so the script
leaves those modules alone.  Otherwise the base BTF must come
from the kernel the modules are built against: the script uses
/sys/kernel/btf/vmlinux only when building against the running
kernel, and only when that kernel's scripts/Makefile.btf itself
uses distilled_base, i.e. its module loader reads .BTF.base
(v6.11+ or a backport).  BTF encoded against a foreign base, or
a distilled base on a kernel that cannot relocate it, fails
module BTF validation, and with
CONFIG_MODULE_ALLOW_BTF_MISMATCH=n the module does not load.
The earlier commit b5c451820443 ("LU-17768 build: embed BTF
in Lustre kernel modules") always used /sys/kernel/btf/vmlinux,
so modules built against a kernel other than the running one
did not load, and it was reverted.

Encoding is best effort: a module pahole cannot encode keeps
no BTF rather than failing the build.

Gated at configure time on CONFIG_DEBUG_INFO_BTF_MODULES
(kernel 5.9+).

Keep both .BTF and .BTF.base through find-debuginfo so
they reach the shipped RPMs.
