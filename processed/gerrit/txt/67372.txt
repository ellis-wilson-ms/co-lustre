LU-20494 llite: don't run statahead on a non-directory parent

ll_getattr_dentry() derives the "parent" directory of the dentry
being stat'd with dget_parent() and feeds it to the statahead
machinery.  NFS re-export (knfsd) hands Lustre a disconnected,
self-parented dentry obtained from d_obtain_alias(): its d_parent
points at itself, so dget_parent() returns the file's own dentry and
@dir ends up being the regular file itself, not a directory.

ll_statahead_enter() and sa_pattern_fname_detect() then update the
directory-only members of struct ll_inode_info (lli_sa_match_count,
lli_sa_fname_index, ...).  These share a union with the regular-file
members, and lli_sa_match_count overlaps the upper half of
lli_size_mutex.wait_list.next.  Writing it zeroes the top 32 bits of
that list pointer.  The damage is silent until a later glimpse takes
lli_size_mutex on the slow (contended) path: __mutex_add_waiter()
walks the corrupted wait_list and hits

  kernel BUG at lib/list_debug.c:26!  (list_add corruption)
  __mutex_add_waiter -> __mutex_lock -> ll_merge_attr ->
  cl_glimpse_lock -> ll_getattr_dentry -> nfsd

This reproduces under parallel-scale-nfsv3 (connectathon, iorssf),
where many nfsd threads glimpse re-exported files concurrently.

Only run statahead when the parent really is a directory.  For a
normally-connected dentry the parent is always a directory, so this
is a no-op except for the disconnected re-export case.
