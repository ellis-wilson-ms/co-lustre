LU-20403 ptlrpc: refresh import conn on primary migration

ptlrpc keys a connection on the primary NID of the peer. It never
resolves the primary NID again. LNet can later migrate the primary
of an unlocked peer. The client reply ME then keys on the old NID.
The reply does not match, and the import stays in CONNECTING.

Add LNetPrimaryNIDNoWait(). It returns the current primary and does
no discovery. It returns -ENOENT when no peer owns the NID.
It returns -EAGAIN when a concurrent primary NID write gives a NID
that is not the primary NID of its peer.
ptl_send_rpc() calls ptlrpc_refresh_import_primary() before it posts
the reply ME. That function calls LNetPrimaryNIDNoWait(). On a change,
the import switches to a connection keyed on the new primary. The call
comes before the LU-17906 check, which drops a connect to a peer that
discovery has not checked. Otherwise an import in CONNECTING on an old
NID never moves.

A primary NID change is rare, so almost all lookups on a send find no
change. Add a generation counter, ln_prim_gen. LNet increments it
after each change that can make a NID resolve to another primary NID.
These changes are a primary NID write, an attach of a peer NI, and a
detach of a peer NI. All primary NID writes on a peer in the peer
table go through lnet_peer_write_primary_nid(). LNetPrimaryGen()
reads the counter. Each connection keeps the generation of its last
lookup that found no change, in c_prim_gen_seen. If the generation is
the same, ptlrpc_refresh_import_primary() skips the lookup. A lookup
that finds a migration records nothing. A concurrent send on the old
connection thus checks again.

imp_p2pdma now comes from the closest configured NID of the current
failover entry. The primary NID can be on a net with no local NI,
and LNetDist() then fails.

A reverse import now has two writers of imp_connection. Thus
rev_import_reconnect() takes imp_lock, or c_refcount can underflow.

The new conf-sanity test 73g migrates the primary NID of a server and
checks that the import moves.
