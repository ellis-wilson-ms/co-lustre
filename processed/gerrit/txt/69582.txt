LU-20813 tests: fix changelog GC races in sanity 160g/160h

test_160g and test_160h register two changelog users back
to back and required both to start at the same record
index, which fails whenever another record reaches the MDT
in between. In test_160g that record also counts against
the first user's idle index limit, so clear the first user
up to the second one's index instead of failing.

test_160h enabled GC with a 10 second idle limit before its
remote setup commands, so slow nodes let GC deregister both
users before they were checked, or run an unblocked GC
thread before fail_loc 0x1316 was set.

Age only the second user with fault injection, which needs
an MDS of 2.14.55 or later, and enable GC once the blocking
fault is set and min_gc_interval has passed since the last
GC check of the previous test. Drop the index check, write
one record to each MDT directly, since the filename hash
misses some stripes with many MDTs, wait for GC threads and
umounts to appear, and restart stopped MDTs on failure.

Fixes: 31fef6845e8b ("LU-10680 mdd: create gc thread when no current transaction")
