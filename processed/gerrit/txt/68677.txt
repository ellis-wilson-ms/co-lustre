LU-19139 lnet: bulk connections follow accept_port

accept_port_bulk is a separate module parameter defaulting to 988, so a
node that sets only accept_port still dials its bulk conns to 988. A
2.15 or 2.16 peer listens on accept_port alone and refuses them, so no
bulk connection is ever made: the mount and metadata keep working over
the control conn while writes fail and are resent. On a cluster with
accept_port=7988 sanity-flr test_70a resent one write for the 91
minutes it took to time out.

Default accept_port_bulk to 0, meaning dial accept_port. The set of
listening ports is deliberately unchanged, since 2.17.0 also dials bulk
to 988, so 2.15, 2.16, 2.17.0 and master peers interoperate in both
directions.

Also report the address actually dialled when a connect fails; since
accept_port_bulk was added the message named the control address, so a
refused bulk connect reported a port it had never used.

Two nodes with accept_port=7988, the server pinned to a single listener:
64MB of dd took 25.6s at 2.6MB/s unfixed, 0.3s at 220MB/s fixed. New
sanity-lnet test_292 fails without the patch.
