--- Commit Message ---
LU-20258 lod: reject EC layouts with k+m > 256 (MDS side)

Companion to the userspace check in 65870 (Gerrit Change-Id
I380dcd52, parent of this commit).  Andreas pointed out on
65870 PS1 that the MDS must enforce the same bound, since we
cannot trust userspace or the client to send correct data.

A composite layout with LCME_FL_PARITY components carries the
EC geometry per-component in lcme_dstripe_count (k) and
lcme_cstripe_count (m).  Today lod_verify_striping() walks
every component but never inspects these fields, so a malicious
or buggy client can hand-craft a layout with k+m > 256 and the
MDS will store it on disk; the EC encoder later fails because
the Cauchy-over-GF(2^8) matrix construction needs k+m distinct
field elements and GF(2^8) has 256.

Add the k+m <= LOV_EC_MAX_TOTAL_STRIPES check in
lod_verify_striping() for every parity component, applied
unconditionally (covers both is_from_disk=true and =false
paths so client-submitted layouts and on-disk layouts get the
same enforcement).
