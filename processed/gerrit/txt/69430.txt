LU-20831 mdt: recheck migrate source under parent locks

Migration looks up the name it is moving before it takes
the parent locks, and acts on the object it found once they
are held.  Only the BFL, which migration holds throughout,
keeps a rename of that name out of the gap: every rename
that can move a file's last name onto another MDT takes it.
Once cross-MDT file renames stop taking the BFL, such a
rename fits in the gap, and the migration then moves and
destroys the object, leaving the renamed name dangling.

Look the name up again once the parent locks are held, and
start over if it is gone or names another object.

Add sanityn 80c, which holds a directory migration after
the lookup of a child while the child is renamed into the
directory's new stripe.
