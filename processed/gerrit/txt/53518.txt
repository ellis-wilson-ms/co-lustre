LU-17240 tests: format targets in parallel

formatall() formats the MGS, every MDT and every OST one at a
time, even when they are on different nodes.  With many targets
this adds up, since conf-sanity and other scripts reformat the
filesystem many times per run.

Run format_mgs(), format_mdt() and format_ost() in the background
with new parallel_start() and parallel_wait() helpers, and wait for
all of them before returning.  Each target's output is saved and
printed in order once it finishes, so logs are not interleaved, and
any failed format still exits the test script.  formatall() calls
stopall() before formatting, so add() running "stop" in a subshell
has no device state left to change.

Parallel format is on by default and is controlled by:
- PARALLEL_OPS: default for all parallel operations (1)
- PARALLEL_FORMAT: format targets concurrently ($PARALLEL_OPS)
- PARALLEL_FORMAT_TARGETS: target types formatted concurrently
  ("mgs mdt ost")
- PARALLEL_FORMAT_TYPES: overlap formatting of different target
  types, instead of MGS, then MDTs, then OSTs ($PARALLEL_FORMAT)

Also use a per-process status file in do_node() for rsh and pdsh
without -S, so concurrent commands on one node do not share it.

Parallel mount and unmount will be handled in separate patches.

formatall() time for 2 MDTs and 6 OSTs of 500MB on one 4-CPU VM,
average of 5 runs:

  serial  parallel
  1.25s    0.85s    (-32%)
