LU-20694 lod: don't LBUG when an MDT update llog is not ready

lod_add_device() publishes a new MDT target into lod_mdt_descs with
ltd_active set and drops ltd_rw_sem before calling lod_sub_init_llog()
to create that target's LLOG_UPDATELOG_ORIG_CTXT.  A client connect
landing in the gap runs mdt_obd_connect() -> mdd_obd_get_info() ->
lod_obd_get_info(), which walks the same list under lod_getref() and
finds an active target whose llog context does not exist yet:

  lod_dev.c:2459:lod_obd_get_info()) ASSERTION( ctxt != NULL ) failed:
    lod_obd_get_info+0x7e8 [lod]
    mdd_obd_get_info+0x319 [mdd]
    mdt_obd_connect+0x4cc [mdt]
    target_handle_connect+0x831 [ptlrpc]

A missing context is the same "not ready yet" state that the following
!loc_handle test already reports as -EAGAIN, which mdt_obd_connect()
turns into a connect reply the client retries.  That is how a NULL
context was handled here until it was replaced by the assertion.
Restore it, folded into the existing test.

Report it at D_HA rather than D_INFO: lod_sub_init_llogs() ignores what
lod_sub_init_llog() returns, so a target can stay active with no context
for good, and that state - the one LU-15934 was filed for - now refuses
every client connect with nothing in the default debug mask to say why.
