LU-20805 utils: client mount option handling

parse_one_option() checks the options given to mount.lustre with
strncmp(check, opt->opt, strlen(opt->opt)), so an option is claimed
by any entry of opt_map[] it merely starts with.
Fix that to only match the whole option name, optionally followed by
a value, like util-linux does.

Since the fs_context migration, the Lustre client provides its own
->parse_monolithic() handler, and the VFS only calls
security_sb_eat_lsm_opts() for filesystems that do not define the
handler. So call security_sb_eat_lsm_opts() for a client mount to pass
the LSM mount options to SELinux, and let vfs_get_tree() apply them to
the superblock.

Add sanity-selinux test_22.
