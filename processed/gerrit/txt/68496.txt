LU-17000 obdclass: leave llog_osd_open() retry through out_name

llog_osd_open() allocates handle->lgh_name for a named llog and then
jumps back to the FID generation when the object it located turns out
to exist already under a freshly generated ID.  That retry leaves
through out, the one exit of the function that does not free
lgh_name, while llog_open()'s llog_free_handle() does not free it
either.

No leak can happen today - local_object_fid_generate()
(obdclass/local_storage.c:177) returns 0 unconditionally, so the error
branch is dead - but out_name is the correct label for an exit taken
after the name was allocated, and it is safe for the unnamed callers
too, since lgh_name is only set in the named branch and OBD_FREE()
does nothing for a NULL pointer.
