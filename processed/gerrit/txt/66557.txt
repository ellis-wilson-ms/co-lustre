Some concerns, see inline comments. The main one is that the new sanity cases never reach the code being added: do_renameat2() returns -EEXIST itself when the target dentry is positive, before ->rename is called:

    error = -EEXIST;
    if ((flags & RENAME_NOREPLACE) && d_is_positive(new_dentry))
            goto exit5;

In test_24Ka/24Kb the target was just created by the same client, so the EEXIST half of each test is satisfied entirely in the client VFS and no rename RPC is sent. Both tests pass against an MDS that does not have this patch. The server-side check only matters when the target name appears between the client lookup and the RPC, so covering it needs a second mount ($MOUNT2 / $DIR2) creating the target, or a fault injection point. Could a case for that be added?
