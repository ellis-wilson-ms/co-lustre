LU-20525 utils: fix parsing of repeated interactive cmds

lctl, lfs, and lnetctl all provide an interactive shell that
dispatches subcommands through cfs_parser(), which rebuilds the
static global top_level[] table on every invocation and is intended
to be called exactly once, from main(). However, every subcommand-
group handler (lnetctl's jt_net, jt_route, jt_peers, jt_lnet,
jt_routing, jt_stats, jt_debug, jt_global, jt_set, jt_udsp,
jt_fault*, etc.; lctl's JT_SUBCMD()-generated jt_* handlers such as
jt_pcc, jt_changelog, jt_net_drop, jt_net_delay, jt_nodemap,
jt_barrier, jt_snapshot, jt_llog, jt_lfsck; and lfs's
LFS_SUBCMD()-generated lfs_mirror, lfs_pcc, lfs_hsm) also called
cfs_parser() recursively to dispatch into its own subcommand table.
Each such call overwrote top_level[] with the subcommand table plus
overrides, discarding the real top-level command list. As a result,
the first command typed in interactive mode worked, but every
subsequent command failed to be recognized, since top_level[] no
longer matched cmd_list.

Add cfs_parser_nested(), a lightweight dispatcher that executes a
single command against a given command table without touching
top_level[] or REPL state, and switch all lnetctl, lctl, and lfs
subcommand handlers to use it instead of recursing into
cfs_parser(). main()'s top-level cfs_parser(argc, argv, cmd_list)
call is unchanged in all three utilities.

Since cfs_parser_nested(), unlike cfs_parser(), does not fall back
to an interactive sub-shell when no further argument is given, guard
the JT_SUBCMD() and LFS_SUBCMD() macros in lctl.c and lfs.c with an
argc < 2 check that returns CMD_HELP instead of dereferencing past
the end of argv.

Since "help" and "--list-commands" are implemented against the
global top_level[] table, dispatching them through cfs_parser_nested()
would report the top level commands instead of the subcommand group.
Split the table walk out of cfs_parser_help() and cfs_parser_list()
into cfs_parser_help_cmdlist() and cfs_parser_show_cmdlist(), and let
cfs_parser_nested() invoke those directly on its own cmds[] table, so
"lfs hsm --list-commands" and "lnetctl net help show" describe the
subcommand group without any global state being modified.

The JT_SUBCMD() and LFS_SUBCMD() macros also left
program_invocation_short_name pointing at a stack-local buffer that
goes out of scope when the handler returns, which corrupted the
program name printed by every later command of an interactive
session.  Save and restore it around the cfs_parser_nested() call.

process() used a static "depth" counter to escape runaway ambiguous
command lookups, but never reset it.  Resolving a command whose name
is a prefix of many others -- "nodemap", which follows ~20 nodemap_*
entries in lctl's cmd_list -- used about half of that budget on every
lookup, so the third such command in a session exceeded the limit and
process() returned CMD_NONE for it from then on.  This stayed
invisible while an interactive session could not get that far.  Make
the counter a process_depth() argument bounding a single lookup.

lctl's jt_opt_device()/jt_opt_net() (--device, --net) and lst's
lst_print_usage() also re-entered cfs_parser() from a command
handler; convert them to cfs_parser_nested() as well.

Also lnetctl net show to close output file correctly.
