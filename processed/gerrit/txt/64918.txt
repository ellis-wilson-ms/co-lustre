LU-19712 utils: Add 'lfs pool pin/unpin/pin_info' commands

Introduce lfs pool commands to manage pool pinning via lustre.pin
xattr.  Three new commands added: "lfs pool pin" to pin
files/directories or FIDs to an OST pool, "lfs pool unpin" to unpin
files/directories or FIDs from an OST pool, and "lfs pool pin_info" to
report whether files/directories or FIDs are pinned to an OST pool.
"lfs pool pin" and "lfs pool unpin" take the pool name as an optional
argument: when omitted, it is inferred from the primary mirror layout
of each file or directory. "lfs pool pin_info" requires --pool
explicitly, since a query has no layout-derived default to fall back
to. They also support operating on FIDs via --fid option. A --pool
argument may also be qualified with an "fsname." prefix, stripped by
the new lfs_poolarg_strip_fsname() helper, matching how
llapi_pool_name_validate() already accepts the same notation
elsewhere.

Add the lfs-pool-pin.1, lfs-pool-unpin.1 and lfs-pool-pin_info.1 man
pages documenting the new commands, add a new lfs-pool.1 page to list
them (plus an lfs-pool-list.1 stub redirecting to it, matching the
lfs-pcc-pin.1/lfs-pcc-unpin.1 convention, since "lfs pool list" would
otherwise be undocumented under its own name), and wire them all into
Documentation/man1/Makefile.am and lfs.1.  Also add bash-completion
support for --pool pool-name completion, and cover the new commands in
sanity.sh test_157c. The completion script's new "pool)" case also
already lists --not-pool, ahead of that option itself landing in a
later change in this series.

Also extend racer's file_setxattr.sh to exercise "lfs pool pin/unpin"
against a real pool name on about one iteration in ten when running as
root, alongside its existing random user.* xattr stress testing, and
switch the pre-existing hsm_cmdlist comment to the same kdoc-style /**
block as the new pool_cmdlist one just above it, for consistency.
