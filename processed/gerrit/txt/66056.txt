LU-20291 llite: fix iov_iter_is_aligned compat for ITER_UBUF

On Linux 6.18+, iov_iter_is_aligned() was removed from the kernel.
When HAVE_IOV_ITER_IS_ALIGNED is not defined, Lustre uses its own
compat shim which has a bug in the ITER_UBUF branch:

  iter_iov(i) returns (const struct iovec *)&i->__ubuf_iovec, a
  pointer to the embedded iovec struct.  Adding i->iov_offset
  performs pointer arithmetic scaled by sizeof(struct iovec) = 16,
  producing a kernel stack address unrelated to the user buffer.

The correct expression dereferences iov_base first so the offset
is applied as a byte offset on the user buffer address:

  iter_iov(i)->iov_base + i->iov_offset

Without this fix, iov_iter_is_aligned() always returns false for
ITER_UBUF iterators regardless of the actual buffer alignment.
Since write()/read() syscalls create ITER_UBUF on Linux 6.0+, all
O_DIRECT operations are misidentified as unaligned, resulting in
either -EINVAL (unaligned_dio=0) or silent performance degradation
via the bounce-buffer path (unaligned_dio=1).
