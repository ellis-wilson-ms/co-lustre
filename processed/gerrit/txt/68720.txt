LU-20714 llite: fix foreign symlink destination path sizing

ll_foreign_symlink_upcall_parse() trusts the (pos,len) of a
POSLEN_TYPE upcall item. Both are __u32, so "pos + len" wraps at
2^32 and a pair summing to 0 passes the lfm_length test; the memcpy()
then reads ~4GiB past the foreign EA and readlink() hands that to any
user. The item sizes are summed into an int, which a large len
truncates to a negative value; as a size_t that wraps the allocation
below PATH_MAX and the path is built in a few bytes. The error path
also frees one byte less than was allocated, drifting obd_memory up.

Compare pos + len in 64 bits, sum the item sizes in a u64 bounded by
PATH_MAX, reject a suffix longer than PATH_MAX, and have the
allocator hand its size back so the error path frees what it got.
Add sanity test 27Pb, the first test to reach that error path.
