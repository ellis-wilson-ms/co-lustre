LU-17569 misc: use CAP_SYS_RESOURCE for HSM/quota/DNE

Add the ability to use CAP_SYS_RESOURCE (in addition to CAP_SYS_ADMIN
for now) for managing HSM, filesystem quotas, and remote DNE ops.

The CAP_SYS_RESOURCE capability is more fine-grained and limited in
what it can do, compared to CAP_SYS_ADMIN.  Allow a transition period
until the 3.2.0 release to allow both capabilities to be used.

The xattr handling is left with CAP_SYS_ADMIN since it may have more
wide-ranging impact than just consuming more storage.

Some concerns, see inline comments. The two version-guard problems and the copytool timestamp path look worth a refresh.

One wider point that has no single home: this changes what cap_sys_resource means on an MDT. Until now it meant "ignore quota" (mdd_trans.c) on top of the DAC bits in CAP_FS_SET. After this it also confers copytool registration and HSM progress reporting via mdt_hsm_is_admin(), unrestricted HSM action permission including HSMA_REMOVE of the archived copy via hsm_action_permission(), remote/foreign directory operations, and 'lfs rmentry'. cap_sys_resource is explicitly grantable to regular users through 'lctl nodemap_set_cap --type set' -- allowed_cap in nodemap_handler.c and mdt_lproc.c is CAP_FS_SET plus CAP_SYS_RESOURCE, and it is the worked example in Documentation/man8/lctl-nodemap-set-cap.8. A nodemap configured today for quota bypass would silently acquire all of the above. Should that man page and the nodemap capability docs be updated to describe the wider meaning?

There is also no test coverage in the patch. sanity-sec test_51 already drives mdt.*.enable_cap_mask and setcap, so a case that performs an HSM or DNE operation with only cap_sys_resource raised would pin the new behaviour down.
