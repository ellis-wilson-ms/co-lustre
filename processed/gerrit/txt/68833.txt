LU-20669 snapshot: set "trusted.snap" xattr on mirror objects

When a new mirror is created from a template mirror, tag every data
stripe object of the new mirror with the "trusted.snap" xattr so the
OST can later tell which snapshot a data object belongs to and which
object it was derived from.

Define XATTR_NAME_SNAP ("trusted.snap") and its on-disk content
struct lustre_snap_attrs with lsa_flags (enum lustre_snap_flags),
lsa_refcount, lsa_snapid, lsa_data_version, lsa_parent_size and
lsa_pfid. For a newly created snapshot mirror the xattr is set with
SNAP_FL_CURRENT | SNAP_FL_PARENT and lsa_pfid pointing to the stripe
object at the same component/stripe position of the template mirror.

The new mirror is cloned component-by-component and stripe-by-stripe
from the template, so the Nth component/Jth stripe of the new mirror
maps 1:1 onto the template. Add lod_obj_for_each_mirror() to iterate
the stripes of one mirror, and lod_snap_stripe_cb() /
lod_snap_xattr_set() to declare and set the xattr on each stripe.
The template mirror index and snapshot ID are passed to the callback
via a struct lu_snap_tmpl embedded in lod_obj_stripe_cb_data.

The xattr must be sent to the OST through OUT RPC on the OSP sub
transaction. lod_sub_get_thandle() cannot be used here: in the
declare phase the stripe object is still anonymous (zero FID), and in
the execution phase an OST object without th_complex is routed to the
local OSD thandle. Both cases return the master OSD thandle, which
osp_xattr_set() then casts to an osp_thandle and dereferences a
bogus ot_our pointer.

Add lod_sub_get_thandle_remote() which always resolves the sub
thandle of the object's own (OSP) device via thandle_get_sub(), and
lod_sub_declare_xattr_set_remote() / lod_sub_xattr_set_remote()
built on top of it. They keep the update record handling of the
existing lod_sub_{declare_,}xattr_set() and are used by
lod_snap_stripe_cb().

Add sanity-lsnapshot/test_5e to verify the "trusted.snap" xattr of
every stripe object of the snapshot mirror on the OST, and that
the template objects are not tagged.
