LU-17936 mdt: take BFL for cross-MDT dir layout change

Concurrent cross-MDT directory layout change, rename and getattr on the
same striped directory can deadlock the MDS. A janitor crashdump of a
racer-long DNE run shows every MDT service thread blocked in
ldlm_completion_ast: mdt_reint_migrate() holding the global rename (BFL)
lock and waiting on a remote parent lock; mdt_reint_setxattr() ->
mdt_dir_layout_update() holding a directory stripe EX lock and waiting on
another cross-MDT stripe lock, with a wall of mdt_getattr_name_lock()
readers queued behind it; and a cross-MDT lock exported to the peer MDT's
OSP that cannot be revoked because no service thread is left to run the
OUT/AST RPC. Clients then pile up on the directory i_rwsem. The wedged
distributed transaction finally aborts into out_tx_index_delete_undo()
"can not rollback index_delete: rc = -524" (LU-18289) and LBUGs the MDS.

The root of the inversion: mdt_reint_migrate() and mdt_reint_rename() take
the BFL rename lock before locking objects/stripes, but the layout-change
path -- mdt_reint_setxattr() -> mdt_dir_layout_update() and the restripe
thread via mdt_restripe_layout_update() -- calls mdt_object_stripes_lock()
on the directory and its cross-MDT stripes with no BFL, so it has no common
serialization point with rename/migrate and their cross-MDT stripe-lock
order can invert.

Give mdt_dir_layout_update() the same ordering: take the BFL first, before
locking the directory and its stripes, and drop it on exit. It then blocks
at the BFL before acquiring any stripe EX lock, so it can no longer hold the
locks a BFL-holding migrate (and the getattr readers) wait behind, and this
cycle cannot form. Both callers reach mdt_dir_layout_update() without the
BFL or any persistent object lock held, so there is no self-nesting.

Export mdt_rename_lock()/mdt_rename_unlock() from mdt_reint.c for the
layout-change path.

No regression test is included: the failure is a multi-party cross-MDT lock
inversion plus MDT service-thread starvation, which racer only hits
intermittently and which a single fail_loc cannot force deterministically
(and a BFL-hold timing probe cannot isolate this path, since dir migration
also takes the BFL via mdt_reint_migrate()). It is exercised by the existing
racer suite on DNE.
