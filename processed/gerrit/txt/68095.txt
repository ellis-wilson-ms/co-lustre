LU-20605 llapi: build find on the scan record

Rebuild the first half of cb_find_init() on the code that
llapi_scan_namespace() uses, so lfs find and the scanner share one
gather path and one record:
- scan_rec_dirent() fills what the directory entry says.
- find_prefilter() rejects what the entry is enough to reject. It
  returns a bool, because it cannot fail.
- find_want() turns the search into a demand mask.
- scan_rec_gather() asks the MDT for the fields in the mask. lfs find
  calls its two steps itself, scan_rec_gather_begin() and
  scan_rec_gather_finish(), so the directory stripe checks still reject
  a directory before the stat RPC.

Behaviour changes:
- With -printf, the unstriped --foreign case prints this object's
  attributes, not the previous object's.
- An MDT index that cannot be fetched no longer fails the object.
  With --mdt, such an object is left out: it matches neither --mdt
  nor ! --mdt.
- A directory that is not on Lustre answers ENOTTY. This is now an
  answer, not an error, so the walk goes into the directory instead of
  losing the subtree. This bug was reachable with -printf, and with
  --links, --mdt-count, --mdt-hash, --hash-flags and --foreign since
  they were added.
- -printf %LF and the layout fetch no longer report an error for an
  object that is not on Lustre: ENOTTY for the layout, and ENODATA,
  ENOTSUP or ENOTTY for the FID. Making llapi_fd2fid() return ENOTTY
  would be cleaner, but it changes a public call, so it belongs in its
  own patch.
- For an object with no project id, --projid N does not match,
  ! --projid N matches, and -printf %LP prints 0. Before, the walk
  failed. get_projid() no longer logs ENOTTY.
- -printf %Li on a foreign directory prints the directory's own MDT
  index, or nothing when it could not be fetched. Before, it printed
  lfm_type: lmv_foreign_md aliases lum_stripe_offset, so the code read
  the foreign type as a stripe offset.
- -name now tests lfsr_name, which is the whole path when the path ends
  in '/'. So --name '*lustre*' now matches a start point written as
  /mnt/lustre/. What the name should be in that case is left for a
  separate patch.

sanity 56El mounts a tmpfs under the Lustre mount. It checks that the
walk finds the objects below it with --links, so that each directory
there has its LMV fetched, and that -printf %LF and %Lc print
nothing on stderr for them. sanity 56* has the same results before and
after this patch.
