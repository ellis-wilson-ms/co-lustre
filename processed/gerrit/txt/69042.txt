LU-20782 osc: keep pages covered by another lock on cancel

When a lock is cancelled, pages another lock still covers
should stay cached. Since LU-11290 the lookup for this
returns the nearest lock at or after a page and takes one
starting past the page to mean nothing covers it. The
lookup returns the first match in lock mode order, PW
before PR, not the lowest start, so a PW lock further
along the object hides a PR lock covering the page, and
every page up to the PW lock is discarded.

That costs only cache while the discard holds
invalidate_lock, but discarding without it (LU-20157)
depends on those pages being kept.

Remove LDLM_MATCH_RIGHT, the only match that can return
a lock outside the requested extent. Find a covering lock
with a normal match and, when there is none, get the next
covered offset from a query over all lock modes that
returns no lock.

Add sanity test_255d.
