LU-20363 tests: use GNU ls in sanity test_33i

In sanity.sh test_33i, find and use GNU ls to substitute
the default ls.

On traditional Linux distributions, ls defaults to GNU ls.
It returns a non-zero exit code when encountering an error.
However, on some newer distributions (e.g., Ubuntu 26.04),
ls is a Rust-based implementation (from the uutils/coreutils
rewrite). When encountering errors such as ESHUTDOWN during
closedir(), it may panic and abort the process instead of
returning a proper error code. This behaviour breaks the
expectations of sanity.sh test_33i.

To make the test robust across distributions, add a helper
function get_gnuls_cmd() in test-framework.sh. It searches
for a GNU-compatible ls in the following order:

the gnuls binary (explicit GNU version),

the default ls if it reports being GNU coreutils,

/bin/ls if that is GNU coreutils.

If none of the above is found, the function returns 1.

In test_33i, call this function and assign its output to
LS_CMD. If no GNU-compatible ls is found, print a message
and skip the test by returning 0.

This change ensures that test_33i uses a GNU ls when available,
and avoids crashes on systems with non-GNU implementations.
