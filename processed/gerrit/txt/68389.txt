LU-10026 csdc: inherit CSDC params unless overriden

If a parent directory has been set CSDC parameters, the file created
under it needs to inherit the CSDC parameters unless another CSDC
parameters or an empty CDSC has been specified for a component of the
file. The file create method includes touch, setstripe a plain layout
file, or setstripe a composite layout file.

As "-Z none" would be used to set compression type to 0 and server
would treat it as no CSDC parameters has been set, so "-Z none"
can not be used to stop inherit parent directory's CSDC inheritance,
so this patch introduces another compression type
LL_COMPR_TYPE_SPEC_NONE to associate with "none" compresstion type,
and it can be used to stop the CSDC inheritance from parent
directories, when user uses "-Z none" to reset compression type,
this patch would set the compression type to LL_COMPR_TYPE_SPEC_NONE.

If we use patched new client to create a file with "-Z none" upon old
servers, the old servers cannot recognize this new
LL_COMPR_TYPE_SPEC_NONE compression type, and it just records the
type as is in the layout.

On old clients "lfs getstripe" will show "unknown" to the component's
lcme_compr_type, and on new clients, "lfs getstripe" will show "none"
to the lcme_compr_type.

When we write data to this file, both clients work but with different
behavior. On old client, with "unknown" compression type, it chooses
a fallback algorithm to compress the data, twisting the original
intention not to compress the component; while on new client, it will
treat "none" component as uncompressed one as intended.
