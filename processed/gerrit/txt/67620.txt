--- Commit Message ---
LU-19921 nodemap: Skip nodemap update and lock revocation

Skip nodemap update and lock revocation if no change
are needed.

When clearing nodemap capabilities, nodemap_idx_capabilities_del()
can return -ENOENT if no capabilities record existed on disk (e.g.,
if inherited from default). Treat -ENOENT as success to avoid
improper rollback.

Fixes: 14b519b52d40 ("LU-17410 sec: per-nodemap capabilities mask")

AI code review results below, please doublecheck

Some concerns, see inline comments. The main one is that the new short-circuit assumes the in-memory value and the on-disk index record are always in sync, which is not true after a failed nodemap_idx_nodemap_update().

Separately, is the stated goal reached on the MGS path? mgs_iocontrol_nodemap() still calls mgs_revoke_lock(mgs, fsdb, MGS_CFG_T_NODEMAP) unconditionally once the ioctl returns 0, so every target still re-reads the whole nodemap index even when these setters now return early. Plumbing a "no change" indication back to the caller, the way out_ro_cmd already does, would let that be skipped too.

Should this also get a sanity-sec case that re-applies a property with its current value, so the new no-op behavior is covered?
