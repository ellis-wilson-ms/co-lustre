LU-20613 build: compile libscan_zfs.c as libzpool is built

OpenZFS builds libzpool, and the programs that link it (zdb, zhack,
ztest), with -DDEBUG -UNDEBUG -DZFS_DEBUG. Its config/Rules.am says
why: ZFS_DEBUG changes shared data structures, so all libzpool users
must be compiled with the same flags
(openzfs#16476). 2.0 and 2.1 set them in lib/libzpool/Makefile.am,
2.2 calls the set FORCEDEBUG_CPPFLAGS, and 2.3 renamed it
LIBZPOOL_CPPFLAGS and added that comment.

None of the three header sets that LB_ZFS_USER tries passed them,
so libscan_zfs.c saw the non-debug layouts of zfs_refcount_t, abd_t
and dmu_buf_user_t while libzpool uses the debug ones. Nothing reads
a moved field today: dmu_buf_t has no debug members, and
dn_num_slots comes before dnode_t's first refcount. A later read of
a dnode_t field past dn_tx_holds would land at the wrong offset with
no warning.

The flags now lead each set, so the configure probe and the build of
libscan_zfs.c both see libzpool's own layouts.
