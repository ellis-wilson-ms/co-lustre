LU-20896 llite: transfer ciphertext for O_CIPHERTEXT DIO

A file opened with O_CIPHERTEXT|O_DIRECT reads and writes the data
as stored on the OSTs only when the encryption key is not loaded.
With the key loaded, the same direct IO decrypts on read and
encrypts on write, so "lfs migrate", "lfs mirror extend" and "lfs
mirror resync" decrypt and re-encrypt the data, and EC parity resync
computes the parity from the plaintext and stores it encrypted,
while without the key it is computed from the ciphertext.
Encrypted file backup and restore need the ciphertext whether the
key is loaded or not.

Record O_CIPHERTEXT at open, since the VFS clears O_NOCTTY from
f_flags afterward, and mark the direct IO pages of such a file so
that OSC transfers them as it does without the key, in RPCs of their
own.  Let such a read reach the end of the last encryption unit, as
without the key.  Refuse such IO not in whole encryption units,
except a read ending within the clear text, and with the key refuse
to fall back to buffered IO, including for EC recovery, which would
encrypt or decrypt the data.  Keep the clear text size of a migrated
volatile file and of a resynced mirror.  Have EC parity resync of an
encrypted file cover its whole last encryption unit.

Also check for O_CIPHERTEXT direct IO on truncate, rather than for
any one of the O_CIPHERTEXT flags, which O_NONBLOCK or O_DSYNC alone
matched and skipped re-encrypting the zeroed end of the last page.

Also set up the key before the glimpse for stat, since a lookup
without open does not, and without the key the size is rounded up
to the encryption unit, e.g. after a migrate and a cache drop.

Reduce cl_page cp_pgno to 19 bits, which still holds the page number
of a 1GiB folio, so the new flag does not grow struct cl_page.

Add sanity-sec test_66b for ciphertext read and truncate, test_66c
for migrate, mirror extend and resync, and test_66d for EC parity
resync, all with the key loaded.
