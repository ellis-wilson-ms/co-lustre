LU-12187 llite: enable FLR EC support unconditionally

Remove module parameter guards and enable FLR EC support
unconditionally. This patch is intended to be applied
after the guarded development phase is complete.

Changes:
- Remove mdt_enable_flr_ec module parameter and add
  OBD_CONNECT2_FLR_EC to MDT_CONNECT_SUPPORTED2
- Remove llite_enable_flr_ec module parameter
- Add OBD_CONNECT2_FLR_EC unconditionally to client
  connect flags
- Change ll_enable_erasure_coding default from 0 to 1
- Remove the LFS_EC_OK check from lfs setstripe
- Remove MODOPTS_MDT and MODOPTS_LLITE settings from
  test framework

Test-Parameters: trivial
Test-Parameters: testlist=sanity-ec

Some concerns, see inline comments. The main one is that nothing consumes OBD_CONNECT2_FLR_EC, so turning EC on by default also turns it on against servers that cannot do EC.

On the test side, sanity-ec.sh's enable_ec() still does `$LCTL set_param llite.*.enable_erasure_coding=1` and sanity.sh test_27N does the same, so after this change no test actually exercises the new default. A case that creates an EC file on a freshly mounted client without touching the tunable would cover the behavior this patch is adding.
