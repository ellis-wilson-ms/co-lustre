LU-20649 llapi: add llapi_scan_changelog()

The two scanners we have list what exists. A changelog lists what
happened. llapi_scan_changelog() reads one MDT's changelog and gives
each event in the same record as llapi_scan_namespace() and
llapi_scan_device(), so one consumer can take all three.

A changelog record has the FID, the parent FID, the name, the event
type and time, and the uid and gid of the caller where the server
recorded them. It has no size, mode, owner, times, layout or HSM
state, so those fields are absent and their lfsr_valid bits are clear.
The caller's uid and gid are in lfsr_event_uid and lfsr_event_gid, not
in stx_uid: they say who acted, not who owns the object.

Two modes:
- Event mode calls the callback once for each object an event is
  about, in log order. A rename over an existing name is about two
  objects.
- Object mode (LLAPI_SCAN_CL_F_COALESCE) keeps events in a cache keyed
  by FID and gives one record per object after it has been quiet for
  sc_min_age. A file written a hundred times is one record. Each
  field comes from the last event that carried it.

Flags:
- LLAPI_SCAN_CL_F_RESOLVE fills the object's own attributes through a
  client mount: one O_PATH open by FID and a statx() per object. It
  fills only what the record lacks. The demand mask decides if the
  lookup runs at all. It needs CAP_DAC_READ_SEARCH and is refused with
  -EPERM without it. The project id, layout, LMV and HSM state are not
  filled.
- LLAPI_SCAN_CL_F_FOLLOW keeps reading as the log grows.
- LLAPI_SCAN_CL_F_ONCE, with _COALESCE, gives each object at most once
  per run.
- Clearing is off by default. It needs a registered user (sc_user) and
  never clears past a record that a cached object still needs.
- sc_type_mask selects event types and needs sc_user. The client
  drops the other records as it reads them.

New record fields, behind four new validity bits: lfsr_event_type,
_flags, _time, _index and _prev, the rename source, and the job id. An
event time is not put in stx_mtime.

lfsr_parent_fd and lfsr_fd are -1, not 0, because 0 is stdin.

sc_startrec and sc_endrec are both inclusive. Under _COALESCE the
delivered indexes are not a checkpoint: only a run that reaches the
end of the log may save its highest index. The man page explains this.

llapi_scan_changelog_test has eleven cases and sanity 56Eea runs it.
It takes -m for the MDT, -u for a registered changelog user and -d for
a client mount. test6 and test9 need -u and skip without it.
