LU-20661 ptlrpc: Lower CPU latency system wide

kick_cpu_latency() only lowered the latency of the cpt the primary
NID maps to, while the thread consuming the reply runs elsewhere
-- the caller for a sync RPC, a ptlrpcd for an async one.  Take a
single system wide cpu_latency_qos request instead of a per CPU
device DEV_PM_QOS_RESUME_LATENCY one, with a shim for kernels
before v5.7.

Rework kick_cpu_latency() and the work item: senders take no
lock, and the work item alone holds the request while RPCs flow.
With pmqos_use_stats_for_duration set, the hold time follows the
longest RPC round trip or delay between sends, not the per-target
PTLRPC_REQWAIT average.

Clearing enable_pmqos now drops the request at once, and
ptlrpc_connection_init() runs before ptlrpc_lproc_init() so the
store never sees an uninitialized work item.

Default enable_pmqos to CONFIG_CPU_IDLE and reject enabling it
when that option is off, since the PM QoS calls are then stubs.

pmqos_default_duration_usec=3000, pmqos_use_stats_for_duration=1.
