LU-20076 tests: check all nodes once after each subtest

After every subtest, run_one() runs three separate commands on all
nodes: reset_fail_loc(), check_node_health() and
check_dmesg_for_errors().  The last one also copies the whole dmesg
of every node back to the client each time and filters it there.

Add check_nodes_after_test() to reset fail_loc, check for an LBUG and
check dmesg in one remote command per node, and filter dmesg on the
node so only error lines are returned.  check_dmesg_for_errors() and
check_node_health() share this code and remain for their other
callers.

Each node's dmesg is now checked from the newest of that node's
marker for this subtest, a stamp that each check now writes to
/dev/kmsg, or a run_one() banner, so a node whose modules were not
loaded when the banner was printed (e.g. conf-sanity unloads them)
is still checked from its last check, and all of dmesg is checked on
a node with none of them.  Before, the combined output of all nodes
was cut at the last marker in it, which dropped errors from every
node printed before that, so subtests may now report dmesg errors
that were missed before.

Time per subtest for the checks after it, with 2 pdsh nodes over ssh
and 427KB of dmesg per node, average of 2x50 iterations:

  before  after
  0.63s   0.23s  (-64%)
