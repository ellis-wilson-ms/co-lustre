LU-20290 lnet: add nodemap NID range discovery visibility

Add a discovery visibility policy based on Lustre nodemap NID
ranges. Visibility-enabled persistent nodemaps are published to LNet
as client classes, and each class advertises only server NIDs that can
reach the class networks directly or through a live route.

Extend external_disc_visibility with nodemap_nidrange. Bootstrap
discovery remains available until Lustre publishes authoritative
nodemap state. Once activated, publication failures fail closed and
are retried from delayed work until a current generation is ready.

Classify GETs by the requester source NID. For Push, choose a peer NID
that belongs to the selected class and send the view to that same NID.
When composed with servicenode visibility, require the registered
service connection NID to belong to the nodemap class. This keeps GET
and Push classification consistent for multi-rail peers.

Rebuild nodemap visibility when local NI or route reachability
changes. Keep a valid persisted nodemap configuration usable if LNet
projection fails, while discovery remains fail closed until
publication succeeds. If rollback restores a ready generation, force
peers through Push again.

Raise the filtered-view limit from 128 to 1024. Expose and document
the discovery_visibility property and extend conf-sanity coverage for
nodemap publication, routing, CIDR ranges, restart, and large class
sets.

Example configuration:

    options lnet external_disc_visibility=nodemap_nidrange

    lctl nodemap_add tenant1
    lctl nodemap_add_range --name tenant1 \
        --range 10.10.0.0/16@tcp
    lctl nodemap_modify --name tenant1 \
        --property discovery_visibility --value 1

To compose this with servicenode visibility, configure the policies
independently:

    options lnet external_disc_visibility=nodemap_nidrange
    options ptlrpc target_nid_policy=servicenode
