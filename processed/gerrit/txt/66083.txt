--- Commit Message ---
LU-20221 lnet: fix panic in lnet_net_show_dump with >128 NIDs

Dumping more than ~128 NIDs at high verbosity exhausts the hardcoded
64 KiB Netlink buffer. When the buffer is full, nla_nest_start()
returns NULL. The code previously failed to check this return value,
resulting in a NULL pointer dereference and an immediate kernel panic.

This patch fixes the crash by specifying the needed sk buffer size.
cb->min_dump_alloc is now dynamically sized based on
lnet_net_size_skb().
While strace profiling shows a typical NI payload takes ~480-520 bytes,
NI_MSG_VALUES_SIZE is set to more than 6Kb bytes. This provides
a safe margin for complex UDSP rulesets and massive IPv6 NIDs.

test_113 is added to sanity-lnet.sh to exercise high-stress
Netlink dumps using 140 LNet nets using the same interace.

Test-Parameters: trivial

Some concerns, see inline comments. The error handling added to lnet_net_show_start() does not appear to be reachable: neither of the two new failure arms can trigger under the default configuration.

On the earlier question about using multipart messages: lnet_net_show_dump() walks every net and every NI in one ->dump() invocation and returns 0, and netlink_dump() only re-invokes ->dump() while it returns > 0. So the dump is always a single skb, nlist->lngl_idx never resumes anything, and sizing one large buffer is the only option left open by the current dump handler. Teaching lnet_net_show_dump() to stop when the skb is full, record lngl_idx, and return a positive value would let min_dump_alloc stay at a page or two regardless of NI count.

Some concerns, see inline comments.

On the open question about using multipart messages: netlink_dump() only calls ->dump() again while it returns a positive value, and lnet_net_show_dump() returns 0 on success, so it is always a single pass. nlist->lngl_idx is written at the end of every pass but nothing ever reads back a non-zero value, so the whole reply has to fit the one skb that ->start() sizes, and an estimate that is short is unrecoverable rather than just slow.
