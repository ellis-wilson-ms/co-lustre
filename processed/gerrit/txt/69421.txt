LU-19823 lod: balance RR allocation across failure domains

The RR array interleaves OSTs only by OSS, and EC and FLR layouts
that need their stripes in different failure domains skip the OSTs
of domains they already use.  Each skip advances the shared start
index, so the layouts lock into a pattern that uses some OSTs much
more than others and some not at all, e.g. 24 OSTs on 6 OSSs in 3
failure domains with 3-stripe EC layouts get 0-401 objects per OST.

Order the RR array in lu_rr_fill() by failure domain, then by OSS in
each domain, so that consecutive OSTs are in different failure
domains, unless OSSs have OSTs in several domains, when it is ordered
by OSS as before so consecutive OSTs are still on different OSSs.
Stagger OSSs and domains with the same OST count so that their OSTs do
not fall next to each other, and swap apart any OSTs still next to one
of their own OSS or domain, as with OSSs of different sizes.  Domains
of different sizes still need skips, so layouts that need distinct
domains now scan from a start reserved by lu_rr_reserve() without
advancing the shared index, use each array slot only to pick a failure
domain, and take the OSTs of each domain in turn in lu_rr_fdom_tgt(),
separately for the first stripes of each stripe count and component,
and likewise for the OSTs of each OSS without a failure domain,
skipping any the layout already uses.  Layouts that use several OSTs
of an OSS without a failure domain can still be up to about 1.3x
unbalanced within it, but a failure domain should be set for all OSTs.
A domain offers only one of its OSTs per slot, so if a layout is still
short of stripes, try the slot OSTs themselves before accepting fewer.
EC parity takes the OSTs of each domain like the later stripes, so it
does not shift the first stripes of the data.  FLR mirrors prefer the
OSTs of a domain on an OSS that the other mirrors do not use yet,
which can unbalance domains whose OSTs are on several OSSs (LU-20925).
Rebuild the RR arrays when an OST failure domain changes, counted in
lq_rr_gen, since it is only known once the OST has reported statfs.

Add failure domains to lod_rr_test and sanity test_51g, and add
sanity-ec test_35c to check RR balance with unequal domains.  Test
of lod_rr_test with 3-64 OSTs, 1-16 OSSs, 1-8 failure domains and
up to one stripe per domain, comparing OSTs in the same domain:

              combinations   24 OSTs, 6 OSSs, 3 domains, 3 stripes
              failed         objects per OST   #0 objects per OST
  before      16344/22165    0-401             0-399
  after           0/22165    300               100

sanity-ec test_35c, 8 OSTs in domains 1,1,1,1,2,3,2,3, 160 EC 2+1
files with qos_threshold_rr=100, objects per OST:

          OST0  OST1  OST2  OST3  OST4  OST5  OST6  OST7
  before    80    79     1     0    81    81    79    79
  after     41    41    39    39    80    80    80    80
