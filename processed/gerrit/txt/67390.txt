LU-19757 target: clear env->le_ses after update replay

distribute_txn_replay_handle() sets the recovery thread's
env->le_ses to point at session_env, a struct lu_context that
lives on its own stack, but never clears env->le_ses before it
returns. Once the function returns that pointer dangles into a
stack region that the deeper recovery call chain immediately
reuses.

replay_request_or_update() runs the update replay handler and
then, on the next loop iteration, calls target_recovery_overseer().
If recovery hits the hard timeout it aborts and evicts stale
exports: class_disconnect_stale_exports() -> mdt_export_cleanup()
-> tgt_client_del() -> tgt_server_data_update() starts a
transaction, and dt_txn_hook_start() calls tgt_txn_start_cb() with
the same recovery-thread env. tgt_txn_start_cb() sees le_ses != NULL
and calls tgt_ses_info(env) -> lu_context_key_get(env->le_ses, ...),
dereferencing the reused stack and crashing:

  BUG: unable to handle kernel NULL pointer dereference at 0x744
  RIP: lu_context_key_get+0x33 [obdclass]
   tgt_txn_start_cb+0x97 [ptlrpc]
   tgt_server_data_update / tgt_client_del [ptlrpc]
   mdt_export_cleanup / mdt_obd_disconnect [mdt]
   class_disconnect_stale_exports [obdclass]
   target_recovery_overseer / replay_request_or_update [ptlrpc]
   target_recovery_thread [ptlrpc]

A vmcore confirms env->le_ses points into the recovery thread's own
stack, between the target_recovery_overseer and
replay_request_or_update frames - exactly where session_env lived -
with lc_value overwritten to 0x714 (0x714 + lct_index*8 = 0x744).

The LCT_CL_INIT guard added by the earlier LU-19757 change does not
catch this: the pointer is dangling into reused stack, so lc_tags is
arbitrary garbage that happens to have LCT_CL_INIT set, letting the
guard pass and the WARN stay silent.

Clear env->le_ses before returning, matching the convention in
handle_recovery_req() which resets le_ses to NULL after use. This is
reproduced by replay-single test_119 (DNE update-log replay followed
by a recovery hard-timeout abort).
