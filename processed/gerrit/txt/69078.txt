LU-20107 nrs: pick the node shared rate dimensions per rule

A node tier mClock rule shares both of its rate dimensions: the R tag
and the L tag of its buckets come from the node tokens of the service.
Some rules want one node-wide dimension alone. A rule can spread one
reservation over the CPTs that have the load while each CPT keeps its
own share of the ceiling, or cap the node-wide sum while each CPT
keeps its own share of the reservation.

Add the share= key to the node tier command. The value is a set of
the short rate keys, "R" and "L" in any order, or "none". A command
with no share= key shares both, as before. The node class keeps the
set in nnc_share, and nrs_node_token_active() reads the set with the
node rate, so a dimension that the set leaves out opens no token
window. The per-CPT rule copies keep 1/nheads of every node rate, and
a dimension that is not shared runs on that per-CPT rate with the
local tag of the CPT scheduler, as a rule of a plain policy command
does. The mClock node ready and relocate paths already work on the
mask of the shared dimensions, so a dequeue waits for a node token of
a shared dimension alone, and a relocate re-keys the shared tags and
leaves the local tags in place.

A shared dimension needs the rate dimension on the head, so share=R
is not valid for TBF or for a limit only mClock policy. share= is a
node tier key: a plain rule start refuses it. A rule that shares the
reserved rate alone can land the whole node reservation on one CPT,
whose local ceiling is 1/nheads of the node limit rate, so the
command refuses a node reserved rate above the per-CPT limit rate
with -ERANGE. A rate change of the rule keeps the same check and
logs the same reason. The nrs_hsch file shows the dimensions of
each rule that take node tokens, so a TBF rule with no share= key
shows "L".

A node tier command takes R=0 and L=unlimit as a plain command does.
Such a rate has no quota to divide, so the per-CPT copies keep it and
the node class opens no token window for the dimension; the copies
reserve nothing, or have no ceiling. Document the semantics.

Add sanityn 77wi, which checks every share= value, the malformed
values, the TBF and plain rule refusals and the per-CPT ceiling
check, and 77wj, which runs one fio flow under share=L, share=R and
share=none and checks the shared dimension at the node rate and the
local dimension at 1/nheads of it. Add 77wk, which checks R=0 and
L=max node tier rules and their rejections, and 77wl, the node tier
form of 77vl, which runs two fio flows through node tier rules with
R=0 and L=max under share=RL and share=L. Its last step runs two
flows under share=R. The step checks that the node reservation goes
whole to the one CPT of the client. The two flow helpers take
NRS_MCLOCK_NODE_RULE to start their rules through nrs_hsch. A node
tier command with no queue word divides a local rate over the regular
head and the high priority head of every CPT, so the tests take the
head count from nrs_node_head_number() rather than the CPT count.
