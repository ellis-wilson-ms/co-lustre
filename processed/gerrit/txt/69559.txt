--- Commit Message ---
LU-20923 mdt: check remote object is on an MDT before locking

A client supplies the FID of the object an operation acts on, and
the MDT instantiates an object for it.  A FID passing fid_is_sane()
but maps through the FLD to an OST produces an OSP object with no
metadata operations which trips the device-type LASSERT.  The request
is resent after recovery so the MDS crashes again on each mount.

Check in mdt_remote_object_lock_try() that the object's FID maps to
an MDT, and return -EINVAL with the MDT name and FID otherwise,
rather than locking an object that is not a remote MDT object.

Triggered in test with an old client still mounting an MDT reformatted
with the same fsname but different SEQ assignments for the targets,
which only happens with parallel target formatting and not production.
