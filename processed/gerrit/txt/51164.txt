LU-16858 build: Remove pinger config option

Lustre is never built or tested without the pinger, so the
--enable-pinger/--disable-pinger configure option and
CONFIG_LUSTRE_FS_PINGER are removed and the code they
guarded becomes unconditional.

Remove the read-only pinger parameter, which reported the
build option and no longer provides useful information.
Sites that need to suppress pings can still use the
ptlrpc suppress_pings module parameter.

Patrick-Bot: Patchset 5 makes /sys/fs/lustre/pinger report suppress_pings
instead of a constant "on".  obdclass cannot call
ptlrpc_pinger_suppress_pings() -- ptlrpc depends on obdclass -- so the
parameter's storage moves to obdclass as obd_suppress_pings, the way
at_min/at_max already live in class_obd.c and are declared as parameters in
ptlrpc/service.c.  ptlrpc keeps module_param_named(), so
ptlrpc.suppress_pings keeps its name, path and 0644 permission.

One limit worth stating plainly, since it decides whether this is the
behaviour you want: suppress_pings is only read on the server connect path
(ofd_obd_connect, mdt_connect_internal).  It does not stop the local pinger
-- ptlrpc_start_pinger() runs regardless, and a ping is skipped per import
on the PINGLESS flag the peer granted.  So the file reports the
administrator's setting on this node, not proof that no ping leaves it: a
server with suppress_pings=1 reads "off" while still pinging its own MGC and
OSP imports, and a client of such a server reads "on" while its pings really
are suppressed.  If you would rather the file went away than reported an
intent, say so and I will do that instead.

Tested on a Rocky 9 single node: the file follows the parameter through
on/off/on, and with suppress_pings=1 a fresh mount keeps "pingless" in the
mdc and osc connect_flags, which are cleared again at 0.  sanity
0a/1/17m/27a/39a pass; recovery-small 26a needs a remote OST and skips
there.  checkpatch reports the same warnings as patchset 4, none new.

Automated run, no vote.
