## Summary

### The Fix

I reverted three incorrect calls from `kzalloc_obj(*ptr, GFP_KERNEL)` back to the standard Linux kernel pattern `kzalloc(sizeof(*ptr), GFP_KERNEL)` in the file `lustre/ofd/ofd_access_log.c`:

1. **Line 222**: `ocb = kzalloc(sizeof(*ocb), GFP_KERNEL);`
2. **Line 474**: `oal = kzalloc(sizeof(*oal), GFP_KERNEL);`
3. **Line 613**: `ccf = kzalloc(sizeof(*ccf), GFP_KERNEL);`

### Rationale

The patch applied automated fixes from `checkpatch.pl --fix-inplace`, which suggested using `kzalloc_obj()` as a "better" alternative to `kzalloc(sizeof(*ptr), flags)`. However, **`kzalloc_obj()` does not exist** in either the Linux kernel or the Lustre codebase.

The checkpatch.pl script (around line 7425 in `contrib/scripts/checkpatch.pl`) suggests this function as part of a code style recommendation, but it's not actually implemented. This is a case where the automated tool made an incorrect assumption about available helper functions.

The standard and correct pattern for allocating memory for a single object in the Linux kernel is:
```c
ptr = kzalloc(sizeof(*ptr), GFP_KERNEL);
```

This pattern is:
- Type-safe (uses `sizeof(*ptr)` to get the correct size)
- Standard across the Linux kernel
- Works correctly with all compilers
