LU-17000 llite: fix memory safety in ll_rmfid()

ll_rmfid() reads the caller's fa_nr with get_user() and sizes both
the lfa FID array and the rcs[] status array from that value, then
copy_from_user()s the header again.  lfa->fa_nr is a second read of
the same user field, and every buffer downstream is sized from it
instead of from the value the allocations used.  Return -EAGAIN if
it changed between the two reads, since that cannot happen under
normal usage.

Reject nr == 0 up front as well.  OBD_ALLOC_PTR_ARRAY(rcs, 0) hands
back ZERO_SIZE_PTR rather than NULL, so an empty array got past the
!rcs check and fell into the "nothing is visible" branch, which
returns rcs[nr - 1] and so reads far past the allocation.

That same branch leaks on a fileset mount, where lfa is reassigned
to lfa_new and lfa_flag makes free_lfa: skip it, leaving
free_lfa_new: as the only site that frees the buffer.  The branch
jumps past that label to free_rcs:, so send it to free_lfa_new:
instead.  'lfs rmfid <subdir mount> <fid outside the fileset>'
reaches it, since every FID that fails __ll_fid2path() goes to the
hidden tail of the array and leaves lfa_new->fa_nr at 0.
