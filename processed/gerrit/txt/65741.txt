LU-17920 mgs: mgs_modify_param() return -EINVAL on bad param

mgs_modify_param() returned positive EINVAL (+22) instead of -EINVAL
when a non-delete set reached the function with no parsable value.
The caller in mgs_wlp_lcfg() checks rc < 0, so the positive return was
treated as success and would fall through to write a new llog record
after the cancel-old-entry step had already bailed.

This path is currently unreachable through mgs_set_param() because
mgs_param_empty() upstream maps the trigger conditions (no '=', or '='
with empty RHS) to del=true, sending control to the MPM_DELETE branch
instead. No user-visible bug today, but the function should reject
bad input on its own terms rather than rely on every caller doing the
right empty-value mapping first.

Fix return to use -EINVAL, and move validity checks earlier in the
function to avoid error handling complexity.  Use GOTO(active_err, rc)
to make it more clear which code path is returning an error.

Found during code review.  It should have been found by checkpatch,
but the USE_NEGATIVE_ERRNO warning only triggers on "return EPOS",
but not "(rc|ret|retval|err) = EPOS; return rc;" or "ERR_PTR(EPOS)".
The checkpatch.pl script will be fixed in a separate patch.

## Fix Explanation

### The Problem
The compile error occurred due to a **forward reference issue** with the `mgs_param_empty()` function:

1. **Line 1386** (previously 1377 in the patch): The function `mgs_modify_param()` calls `mgs_param_empty(param)`
2. **Line 3975** (previously 3966): The `mgs_param_empty()` function was defined as `static inline` much later in the file
3. When the compiler encountered the call at line 1386, it hadn't seen the definition yet, so it created an **implicit declaration** assuming a non-static function
4. When it later encountered the actual `static inline` definition at line 3975, this conflicted with the implicit declaration, causing the error:
   - `implicit declaration of 'mgs_param_empty'` 
   - `static declaration of 'mgs_param_empty' follows non-static declaration`

### The Solution
**Moved the `mgs_param_empty()` function definition before its first use:**

- **Moved from**: Line ~3966 (after many other functions)
- **Moved to**: Line 1347 (immediately before `mgs_modify_param()` which uses it)
- **Removed**: The duplicate/original definition at the old location

### Rationale
For `static inline` functions in C, the definition must be visible at the point of use. The cleanest solution is to place the function definition before any code that calls it. This approach:
- ✅ Eliminates the implicit declaration issue
- ✅ Keeps the inline function close to its caller for better code locality
- ✅ Avoids needing forward declarations
- ✅ Follows common C programming practices for inline functions

The fix ensures the compiler sees the complete `static inline int mgs_param_empty(const char *ptr)` definition before it's called in `mgs_modify_param()`.
