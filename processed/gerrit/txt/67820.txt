--- Commit Message ---
LU-20559 target: drop an export reference on reply_data error

tgt_reply_data_init() takes a reference on each export it finds:

	exp = cfs_hash_lookup(hash, &lrd->lrd_client_gen);

and drops it at the end of the loop body with class_export_put().  The
tgt_set_reply_slot() failure path in between returns without dropping
it, so the export is left with an extra reference and never destroyed.

Today this is only a leak: mdt_init0() sends a tgt_init() failure to
err_free_ns, which unwinds past err_tgt, so nothing barriers on the
way out and nothing notices.  It matters for anything that does wait
for the exports to drain - the extra reference keeps the export on
obd_unlinked_exports, obd_zombie_export_add() never runs for it, and
obd_exports_barrier() has no timeout, so such a caller would spin in
schedule_timeout_uninterruptible() with the mount thread unkillable in
D state.

tgt_set_reply_slot() fails when tgt_bitmap_chunk_alloc() cannot get
its chunk - BITS_TO_LONGS(1 << 20) * sizeof(long), 128KB.  tgt_init()
has just OBD_ALLOCed lut_reply_bitmap with every chunk pointer NULL,
so the first reply record with a live export always takes that path:
any mount with recoverable reply data can hit it, not only one
spanning an unallocated chunk.
