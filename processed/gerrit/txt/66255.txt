LU-19712 utils: Handle migrate/mirror on pinned files

Add a safety gate to lfs setstripe/migrate/mirror operations that
respects a file's lustre.pin pool constraints:

- migrate requires the new layout to keep a pinned pool's coverage:
  a whole mirror on the pool for a plain pin, every component for an
  exclusive pin, and none on a denied pool. A flat/omitted --pool
  falls back to the pool the MDS would itself assign from the target
  directory's default layout, so an in-place restripe still
  succeeds; a bare "lfs migrate FILE" that keeps the file's own
  layout is exempted entirely, since nothing about pool placement
  can change. MDT-only migrate (-m) is not covered.
- mirror extend and component-add only add data alongside what is
  already there, so only an exclusive pin or a deny_pool constraint
  restrict the new components; a plain pin is satisfied by the
  untouched existing copy.
- mirror split and mirror delete are rejected only if removing the
  targeted mirror would leave a pinned pool with no surviving copy.
- mirror create is not covered: it always targets a file with no
  existing layout.
- DoM and foreign components carry no OST pool and are skipped.

mirror split/delete's selector and the pin gate's survivor check now
share one resolve_split_mirror_id() helper, so they can't disagree
about which mirror is targeted.

Also add llapi_pool_is_denied_fd()/_file()/_fid() to
include/lustre/lustreapi.h alongside the existing is_pinned trio,
with a matching man3 page, and have the gate parse each file's
lustre.pin xattr once per call instead of once per layout component.
