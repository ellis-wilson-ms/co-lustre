LU-20040 llapi: use getpwuid_r/getgrgid_r in find -printf %u/%g

The printf_format_directive() %u and %g handlers cache the resolved
username/group per worker thread (LU-19557 made the cache __thread), but
still resolve names with getpwuid()/getgrgid(). Those are non-reentrant:
each returns a pointer into a shared static buffer that a concurrent
parallel-find (pfind) worker's lookup can overwrite between the lookup
and the strncpy into the thread-local cache. A file owned by e.g.
'sanityusr' then caches the name of whatever uid another thread resolved
concurrently (often 'root'), producing intermittent sanity test_56Eaa
failures: "expected 'sanityusr' but got 'root'".

This is the residual of LU-19557, which fixed the cache race (static ->
__thread) and localtime -> localtime_r for the same reason, but left the
getpwuid()/getgrgid() calls non-reentrant. Use the reentrant
getpwuid_r()/getgrgid_r() with caller-provided buffers.

This is a test of automated regression finding and fixing process.
