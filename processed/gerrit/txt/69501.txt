LU-20650 llapi: pass FID and nlink to llapi_scan_fid() filter

lfsp_filter in llapi_scan_fid() got the record a directory entry
would give: the path, the name and the type. A subtree filter over a
changelog, which is the case the function's documentation names,
also has to look at a hardlinked file's other names. For that it
needs the FID, and the link count to know whether there are other
names. Without them a filter has to ask fid2path once more for every
object it rejects, to learn that a file with one link has no other
name.

The filter now gets a copy of the record with the FID that was asked
for and the link count, a directory's included, as the other
scanners give it; the filter tests the type itself. The statx()
that reads the type asks for STATX_NLINK as well. On Lustre the link
count comes from the MDT with the type and needs no glimpse, so it
costs nothing more. The record that the callback gets is unchanged: it
carries a FID only when the gather read one back; under a name-only
mask no gather runs, so it carries none. llapi_scan_test 17 checks
both.
