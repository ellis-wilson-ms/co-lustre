LU-20626 lnet: cancel discovery Ping on peer down

An LND peer-down notification can arrive after the send event of a
discovery GET. Its response MD then remains PING_SENT until response
expiry, preventing prompt rediscovery after a connection reset.

Cancel an outstanding discovery Ping when an LND reports the peer
down, but only if no other peer NI is cached UP. After
lnd_notify_peer_down() returns, re-read lpni's peer and its cached
NIs before deciding to cancel. This handles peer reassignment while
locks were dropped, repeated DOWN notifications that otherwise look
like Old news, and multi-rail peers with another usable NI.

lnet_peer_send_ping() keeps the new Ping-MD handle local while
lnet_send_ping() binds it, then publishes it under lp_lock only while
PING_SENT remains set. If peer-down clears PING_SENT first, the
sender unlinks its private handle. Its terminal UNLINK event requeues
discovery, preventing another Ping from starting while an event from
the canceled MD is still pending.

This does not cancel an in-flight Push or a Ping that may use another
cached-UP multi-rail path.

Add a sanity-lnet case that holds a discovery GET in PING_SENT by
dropping it at the remote peer. The test then injects one local-error
GET with CFS_FAIL_SOCK_CONN, causing SockLND to close the connection
and report peer-down to LNet. It requires that notification to cancel
PING_SENT before response expiry, then verifies that a fresh
discovery succeeds.

Tested with an OST HA failover and with the sanity-lnet case after a
SockLND local error.

Addressed Serguei comments from patch set 23 in patch set 24. The peer-down path no longer directly requeues discovery: a published Ping MD remains PING_SENT until its terminal LNET_EVENT_UNLINK, so a replacement Ping cannot start while an event from the canceled MD is pending. If cancellation wins before publication, the shared helper clears PING_SENT and sets FORCE_PING; lnet_peer_send_ping() then unlinks its private MD, and that terminal event serializes the retry. The pre-publication handshake is shared by lnet_peer_cancel_discovery() and lnet_peer_cancel_ping(), so a bound MD cannot be left untracked. The cancellation decision is also now made after lnd_notify_peer_down() returns: it re-reads the peer through lpni and rechecks all peer NIs, covering peer reassignment while locks were dropped, repeated DOWN notifications that are otherwise Old news, and multi-rail peers with another usable NI.
