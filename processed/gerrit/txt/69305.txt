LU-8933 lod: balance round-robin first stripe start

With qos_threshold_rr=100, some OST/stripe count combinations give
some OSTs twice as many first stripes (#0 objects) as others, e.g.
6 OSTs with 4 stripes, or two OSSs with 12 OSTs each and 16 stripes,
where the OSTs of one OSS got 75 and the other OSS 125 per 100.

Each layout starts where the previous one ended, so layouts start
only on OSTs gcd(stripes, OSTs) apart in the RR array, and the start
index wraps after an uneven number of layouts.  Advancing the start
offset by one on every wrap then visits some of those OST sets more
often than others, and lod_qos_calc_rr() interleaves the OSSs in the
array, so the imbalance can follow the OSS boundary.  The components
of PFL layouts, allocated in turn, advance the same start index, so
a fixed sequence of stripe counts can also leave the start of each
component on only a few OSTs.  Overstriped layouts with more stripes
than OSTs advance the start index by more than the OST count, but it
was only wrapped by one OST count, so the same OSTs got the extra
stripes of every layout until the next reseed.

Keep a separate start index for each stripe count and component
extent, in struct lu_qos_rr_stream, for the 16 (LQR_STREAMS) most
recently used.  A new one continues from the start index of the one it
replaces, so using more of them in turn is no worse than before.  The
mirrors and EC parity of one extent share the start index of the first
of them, and when they are allocated one after the other they continue
from each other without advancing the start offset, so they are still
on different OSSs.  Advance the start offset once every N/gcd(stride,
N) layouts, where the stride is the stripes of a layout and of the
mirrors or parity that continue from it, after every OST in the
current set has been used as a start, so each run of N layouts with
the same stripe count starts once on each of N OSTs.  Count layouts
rather than wraps, since OSTs that are skipped change the stride
between layouts.  Wrap the start index fully for overstriped layouts.
This also fixes the same imbalance for directory stripes over remote
MDTs.

Make sanity test_51g check the first stripe balance, overstriped, PFL,
mirrored and EC layouts, and keep the test_51d exceptions only for
older MDSs.  Before this patch, lod_rr_test finds that these fail the
test_51d first stripe check (for some component):

                                          before         after
  3-256 OSTs, 1-8 OSSs, 1-256 stripes     50777/263079   0/263079
  3-32 OSTs, up to 4 stripes per OST      2511/8388      0/8388
  3-64 OSTs, PFL with 1, 4, all stripes   25/247         0/247
  3-64 OSTs, PFL with 8, 4, 2, 1 stripes  68/247         0/247

562 of the overstriped combinations also fail it for total objects
before this patch.  With one unusable OST that is skipped, 3544 of
4500 combinations of 4-48 OSTs have more than 3x the #0 objects on
some OST than another before this patch, and 853 after.

Objects per OST from sanity test_51d, 6 OSTs, 600 files -C 4:

  before #0   133    67   133    67   135    67
  after  #0   100   100   101   101   100   100
