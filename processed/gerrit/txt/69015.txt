--- Commit Message ---
LU-20769 lfsck: flush signals before sending RPC

lfsck uses signal SIGINT to stop assistant threads, then those
assistant threads notifiy lfsck on other nodes (like OSTs) using
dedicated RPCs, but ptlrpc_set_wait() sets rq_allow_intr=1 and then:

	if (signal_pending(current))
		remaining = -EINTR;
...
	} else if (remaining < 0) {
		rc = -EINTR;
		ptlrpc_interrupted_set(set);

i.e. ptlrpc doesn't even try to send RPC and remote lfsck instances
keep going leading subsequent subtest failures.

the fix is to flush pending signals in lfsck's stop path.
