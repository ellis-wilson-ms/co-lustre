LU-20290 lnet: rebuild filtered ping views off datapath

lnet_parse() and the router checker rebuild the filtered discovery
ping views inline when a local NI status change marks them stale, via
lnet_disc_views_refresh(). That rebuild allocates and, while freeing
the previous generation of views, can block in lnet_ping_md_unlink()
until an in-flight ping reply drains. On a router with self-only views
configured, every net_last_alive transition would tear down and
rebuild all filtered views inline, stalling LNet message processing.

Defer the rebuild to the discovery thread, the way the neighbouring
lnet_push_update_to_peers() already defers its work. The receive path
and router checker only set the_lnet.ln_disc_views_dirty under
LNET_LOCK_EX and wake the discovery thread; the thread tests and
clears the flag and rebuilds before draining its request queue, so
queued peers still advertise current views. The flag is set only when
filtered views are active, so there is no added cost otherwise.
