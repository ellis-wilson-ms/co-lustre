LU-20590 llite: pin the layout lock for a starving IO

can_populate_pages() asks ll_file_io_generic() to restart the IO when
the cached layout generation of the inode is the invalid sentinel.
Local reclaim of the MDC ibits lock which carries the layout produces
that sentinel. With the lock cache under pressure, a reader or a
writer then goes round the restart loop. The loop can run until the
budget is gone, and move no data at all.

Count consecutive restarts which moved no bytes and found no cached
generation. After LL_LAYOUT_PIN_RESTARTS of them, hold the layout lock
out of voluntary LRU reclaim for the rest of the syscall. The pin
takes no mode reference. The server can still revoke the layout at
once, and the existing generation checks stay in force.

The counter is a heuristic. A server revoke and a local reclaim both
reach vvp_conf_set() through ll_layout_conf(OBJECT_CONF_INVALIDATE).
The sentinel therefore does not name the cause. A mirror failover
retry which moves nothing can advance the counter too. The cost of a
wrong guess is one spare pin, which the syscall drops on the way out.
A try which moves bytes, or which reads a valid generation, resets the
counter. The threshold only has to clear the one-shot paths.

A try at the pin can fail. A failure which says that no pin can help
spends one of LL_LAYOUT_PIN_TRIES. One syscall makes at most four such
tries. A failure with -ENOENT or -ESTALE says only that the reclaim
won the race. That race is the condition the pin exists for, so it
spends no try. The count of restarts still bounds the retries. Every
restart already sends its own layout intent RPC from vvp_io_init(), so
a try adds at most one RPC. A failed try never aborts the IO.

While a thread starves on a file, cancel_lru_locks and an
lru_size=clear no longer drop that file's layout lock.

Add a fault injection which drops the unused locks of the MDC
namespace inside the window the IO uses. The injection goes through
the LRU cancel path, not a direct invalidation of the object. The
condition under test is therefore the real one. The injection fires
only after the layout refresh succeeds. The injection also gates on
the IO type, because vvp_io_init() serves every llite cl_io. The
reclaim is best effort, so the injection can bite fewer times than the
test needs.

Add the llite stats counters layout_restart and layout_pin. The first
counts the restarts which moved no data and found no cached
generation. The second counts the pins. A layout_restart count which
grows on a production client shows starvation of the lock cache.

Add sanity test_251d. The test writes and then reads 1 MiB under the
injection. It checks that each IO completes, that the data is correct,
and that the client took a pin. The test reads the counters, not the
debug log, so a change to a debug message cannot break it. The test
skips when the injection bit too few times in both IOs. A test which
did not run must not report a pass.

ldlm_cancel_lru() moves to a public header for the injection site. The
llite module is separate, so the patch exports the symbol. The move
also corrects the description of ldlm_cancel_lru(). The old text named
LCF_ASYNC for both cases. The return section named a parameter which
the function does not have. The section also gave one meaning to a
return of 0 where the function has two.
