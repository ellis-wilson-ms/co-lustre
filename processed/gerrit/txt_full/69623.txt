LU-20936 llite: add nocgroupwb mount option

Lustre clients always set SB_I_CGROUPWB on the superblock, so every
inode a cgroup dirties is attached to that cgroup's writeback
context. When the cgroup is removed, for example when a container
exits, the kernel has to switch all of those inodes back to a parent
writeback context in inode_switch_wbs_work_fn(). On clients with a
very large inode cache this produces a large number of CPU-hogging
work items contending on wb->list_lock, which can stall kernel
workqueues for minutes. The client stops pinging during the stall
and gets evicted. Newer kernels (v6.18) make the switching cheaper,
but on older kernels Lustre gives no way to opt out.

Add client mount options "cgroupwb" and "nocgroupwb", backed by the
new LL_SBI_CGROUPWB flag. "cgroupwb" is the default and keeps the
current behaviour. "nocgroupwb" makes ll_fill_super() skip setting
SB_I_CGROUPWB, so inodes stay on the bdi root writeback context and
are never switched between cgroup writeback contexts. The trade-off
is that dirty throttling and reclaim writeback become system-wide
rather than per cgroup (see LU-16713). The option takes effect at
mount time only.

Document both options in mount.lustre.8.
