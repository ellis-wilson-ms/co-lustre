LU-20818 llite: hybrid IO thresholds follow folio support

Where hybrid IO should switch from buffered to unaligned DIO
depends on how cheap each path is, and large folios change
both.  Page cache large folios make buffered writes several
times cheaper, while folio extents make unaligned DIO cheaper
and do nothing for buffered reads, so the two directions move
opposite ways.

Measured on a single thread against faked targets with a
flash-RAID latency model, the write crossover moves out by 8x
with folios on, and the read crossover comes in by half.  The
absolute sizes there are not a real client's -- the buffered
path in that setup is faster than published single thread
numbers -- so it is the ratios that carry.

Keep the thresholds as they are, but when an admin has not set
one, take its default from the folio support in use: applying
those ratios to the shipped defaults, writes switch at 16MiB
with page cache large folios on (2MiB otherwise), reads at 4MiB
with DIO folio extents on (8MiB otherwise).  The tunables show
the threshold in effect; setting one pins it.  An encrypted file
is the exception: it gets no folio extents, so its reads use
the 8MiB default whatever the tunable shows.
