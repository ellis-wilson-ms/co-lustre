LU-20486 ldiskfs: give 6.12 series their own patch copies

Kernel 6.12.95 has drifted enough from the current ldiskfs-6.12-ml
series that the server build fails against it (LU-20486). Several
ext4 patches (ext4-add-fstrim-mount-option,
ext4-add-periodic-superblock-update, ext4-mballoc-for-hybrid,
ext4-fix-ext4_inode_attach_jinode, ext4-delayed-iput,
ext4-dirdata-core, ext4-prealloc) were shared across kernel-version
directories (rhel9.4, rhel9.5, rhel10.0, linux-6.5, linux-6.10, base)
whose underlying kernel sources have diverged from what the
6.12-based series now need. Give ldiskfs-6.12-ml its own linux-6.12/
copies, so adapting one series' patch no longer risks breaking
another series that happened to reference the same file.

el10.0 also needs its own ext4-dirdata-core.patch: namei.c's
ext4_match() gained a sb_no_casefold_compat_fallback(parent->i_sb)
check that the shared copy doesn't have. el10.1 diverges further,
with a struct_size()-based dir.c hunk in place of the int len,
extra_data form both el10.0 and the mainline copy share, so it
needs its own copy too. ext4-prealloc.patch is pulled off the
now-rebased linux-6.12/ copy into a new rhel10.0/ copy that rhel10.1
continues to share, the same way rhel10.1 already shared rhel10.0's
ext4-mballoc-for-hybrid.patch, ext4-add-fstrim-mount-option.patch and
ext4-delayed-iput.patch before this change.
ext4-fix-ext4_inode_attach_jinode.patch and
ext4-add-periodic-superblock-update.patch are untouched here and
still reference base/ and rhel9.5/ respectively.

Also in ldiskfs-6.12-ml.series:
- linux-6.5/ext4-pdirop.patch -> ubuntu24.04.3/ext4-pdirop.patch
- rhel9.4/ext4-add-IGET_NO_CHECKS-flag.patch -> rhel9.8/...
- base/ext4-symlink-xattr-inode-fix.patch dropped (fix is now
  upstream as of the kernels this series targets)

Added the original upstream commit messages to the new linux-6.12/
patch files to preserve history.
