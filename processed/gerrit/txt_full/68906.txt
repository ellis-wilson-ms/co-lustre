LU-20732 ptlrpc: fix nodemap_del() deadlock

This patch is used to fix nodemap_del() deadlock.

The nodemap_del() function removes the nodemap procfs entry
while it still holds active_config_lock.
Removing a procfs entry will wait for the processes already
hold it open, so the caller may block with the lock held.
Mean time the config log thread may run the upcall
"/usr/sbin/lctl set_param nodemap.<name>.fileset=..."
and wait for it to finish.
That lctl cmd opens the same procfs entry.
The entry's write handler needs active_config_lock,
which was already held by nodemap_del() function.
The two sides waits for the other,
causes sanity-sec test_27ac hangs and time out.

Removes the entry after the lock is dropped.
nm_pde_data is cleared under the lock,
so no other thread can pick the entry up while it is going away.
This is the order nodemap_destroy() already uses.

Because the old entry may still exist for a second after the lock
is dropped, lprocfs_nodemap_register() now returns -EEXIST instead of
going on with a NULL proc entry.
So let nodemap_add() rolls back and retries a few times.
