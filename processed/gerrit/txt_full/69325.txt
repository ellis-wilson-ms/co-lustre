LU-16897 lnet: variable-length hole encoding for sparse PUT

The hole information of a LNET_MSG_SPUT message was always carried
as a fixed 256-bit page bitmap (32 bytes + 8 bytes fixed part) in
the extended LNet header, regardless of how many holes the 1MiB
KIOV actually contains. Most sparse reads have only a few hole
ranges, so the bitmap wastes wire bytes on every SPUT.

Make struct lnet_hdr_ext variable-length on the wire and select the
most compact encoding per message via a new "flags" field:

  LNETHDR_FL_FULLHOLE  all pages are holes, no body     (8 bytes)
  LNETHDR_FL_EXTENT    nexts contiguous hole ranges
                       as struct kiov_hole_extent   (8 + 2*nexts)
  LNETHDR_FL_BITMAP    more than SPUT_MAX_HOLE_EXTENTS
                       (20) ranges, the full bitmap    (48 bytes)

"size" gives the number of bytes actually transferred for the
extension. lnet_md_build() counts the contiguous hole extents into
the new md_hole_nexts while it compacts the KIOV, and
lnet_hdrext_pack_sput() picks the encoding when the SPUT is sent.

On the receive side lnet_parse_sput() no longer expands the hole
information into an intermediate bitmap. A full hole is handled as
a single [0, niov) extent, extents are walked one at a time, and a
bitmap is scanned for runs of set bits; each hole run is zeroed
and the data pages are compacted in place. The consistency check
of the received hole information against the MD is now optional
and off by default (lnet_sput_check module parameter) to keep it
off the fast path.

Add a global LNet tunable lnet_sput_hexts, exposed both as a module
parameter and under /sys/kernel/debug/lnet/, to control whether the
extent (or no-body full hole) encoding is used. When disabled, every
SPUT carries the full bitmap, including a pure full hole. The
receiver accepts all encodings regardless of its own setting, so
the two sides may be configured differently.

socklnd: pack/unpack only hdrext.size bytes of the extension. The
receiver reads the 8-byte fixed part in SOCKNAL_RX_LNET_HEADER,
validates size against [8, sizeof(struct lnet_hdr_ext)], and then
reads the remainder in the new SOCKNAL_RX_LNET_HDREXT state.

o2iblnd: a pure full-hole SPUT still goes through the IMMEDIATE
path with a zero payload and the receiver synthesises a FULLHOLE
extension; PUT_REQ carries the extension and is sized by
hdrext.size. Validate on receive that ibm_nob covers the fixed part
and then the whole extension before it is byte-swapped, since
kiblnd_unpack_msg() only checks the fixed PUT_REQ size.

Add sanity test_880c, which reads a sparse file with a few holes
per MiB with lnet_sput_hexts disabled and enabled on the OSS and
verifies from the client's "SPUT recv:" traces that the extent
encoding transfers fewer extension bytes than the bitmap while the
data read back is identical.
