LU-20896 osd-zfs: serialize LMA flag update in osd_attr_set

Every read and write RPC of an encrypted file passes
LUSTRE_ENCRYPT_FL to osd_attr_set(), which adds it to the LMA xattr
of an object that does not have it yet while holding oo_guard only
for read.  The SA xattr nvlist is not updated atomically, so
concurrent RPCs to a new object race, giving "failed to set LMA
flags: rc = -2" or "rc = -14", and slab corruption or an oops in
nvlist_remove_nvpair() on the OSS.

Take oo_guard for write when osd_attr_set() may update the LMA
flags.  Track the flags known to be on disk separately, since
osd_declare_attr_set() already sets oo_lma_flags, so that only the
first RPCs to an object take the lock for write and look up the LMA.
Also keep the other flags in oo_lma_flags when adding some, as in the
LMA, in both osd-zfs and osd-ldiskfs.

Fixes: 348446d6370b ("LU-16091 enc: S_ENCRYPTED flag on OST objects for enc files")
