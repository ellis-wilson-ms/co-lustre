--- Commit Message ---
LU-20808 target: no IT_MDT_TO_MDT_READ lookup in striped dirs

An IT_MDT_TO_MDT_READ may look a name up in the locked object, on the
MDT that owns it. In a striped directory the names live in stripes
that may be on other MDTs, so looking one up in the directory itself
would not find it, and the requester would take the name for absent.

The requester names the stripe itself in the ordinary case, since the
client resolves a name to its stripe before it sends the request. So
when the object is a striped directory rather than a stripe of one,
out_reads_run() answers the lookup -EREMOTE, and the requester looks
the name up the ordinary way. out_dir_striped() tells the two apart
with one local read of the LMV, by its magic: LMV_MAGIC_STRIPE for a
stripe, LMV_MAGIC_V1 for the striped directory. The size alone would
not do, since the LMV stored is the bare header for both. Anything
else, an LMV that cannot be read included, is answered -EREMOTE too.

A directory being migrated or split keeps the rules it had: the name
is looked up in the stripe the requester names, which is where the
requester looked for it without the intent too.
