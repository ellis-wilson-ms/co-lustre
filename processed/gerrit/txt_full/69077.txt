LU-20107 nrs: share node-wide R and L tokens in mClock

The node-wide shared token quota added for TBF caps the aggregate
rate of a global rule across the CPT schedulers of a service. mClock
still keys its R and L tags from the per-CPT rate copies, so a global
mClock rule reserves and limits up to rate x ncpts on a node.

Take the R tag and the L tag of a node-wide mClock rule from the node
tokens of the service. A class bucket holds at most one limit token
and one reserved token. The L tag is the paced deadline of the limit
token, or the retry time of the next window when the ceiling refuses
one. The R tag is the deadline of the reserved token, bounded below
by the L tag so reserved service obeys the node ceiling. A bucket
without a reserved token stays in the reserved tree. Its R tag is
then the retry time of the refusal, and the dequeue asks again at
that time. Reserved service debits both tokens. Surplus service
debits the limit token alone and keeps the reserved token for the
next request.

Add nrs_node_token_consume_mask() to take the limit token and the
reserved token under one hold of nnc_tok_lock. Separate takes could
interleave with other CPTs and pace the R deadline of a bucket behind
an L deadline that another CPT advanced in between; a single critical
section keeps both deadlines from the same point of the shared
windows. Take the reserved token only behind a granted limit token.
Thus a take never debits a reserved token while the ceiling refuses
the limit token. A reserved token that the bucket keeps after
surplus service still waits for the next limit token.

Re-key only the shared tags when a selected bucket lacks a node token,
and return the bucket to the limit tree so the eligibility test runs
again on the new L tag. The virtual finish time and the local weight
tags stay unchanged; weight fairness remains local to each CPT.
Relocate keeps the bucket in the reserved tree, as the class insert
does. The R tag is the new token deadline or the retry time. Clear
the token bits when a bucket binds to another rule. A rate change of
the rule keeps them, because the node window already counts them.

Rename NRS_CLASS_TOKENIZE_BIT to NRS_CLASS_TOKENIZE_LIMIT_BIT and add
NRS_CLASS_TOKENIZE_RESVD_BIT. Document the token order, the locking
and the relation between node tokens and weighted eligibility.

Parameterize the sanityn node share tests by policy and add 77wg and
77wh, which run the single-client and multi-client node rate checks
under mClock with the reserved rate and the limit rate set to the same
value, so both shared token dimensions take part.

Looks good; I found no correctness problems in the shared R/L token path. There are a few optional nits inline for the next refresh, and none of them needs a re-spin.

On test coverage: 77wg/77wh set the reserved rate equal to the limit rate. With R == L the R tag and the L tag are paced together, so the R tree nearly always wins. The surplus path, where a bucket keeps its reserved token while the limit token alone is debited, is then hardly exercised. A follow-up case with the reserved rate below the limit rate (for example resvd_rate=rate/2 rate=rate) would check that the sum of reserved and surplus service across CPTs still stays at the node limit.
