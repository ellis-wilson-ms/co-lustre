LU-20403 lnet: resolve a pruned NID through an alias

A server can delete the net of its primary NID. Discovery on the
client then prunes that NID from the peer. An import that keys on
the pruned NID cannot move: LNetPrimaryNIDNoWait() finds no peer for
the NID. Sends fail with "has no available nets", and the import
stays in CONNECTING.

When discovery prunes a NID, record an alias from that NID to the
primary NID of the peer. LNetPrimaryNIDNoWait() resolves a NID that
no peer owns through the alias. The import then moves to the peer.
At most 1024 aliases stay, one for each pruned NID. When the list is
full, the oldest goes.

Traffic to the pruned NID creates a peer with only that NID. That
peer must not hide the alias. The alias thus wins over a peer that
has one NID, and that discovery and configuration have not checked.
Only discovery or configuration removes an alias. A ping reply that
lists the NID, or a configured peer that adds it, is the proof.

Only a NID with no local net and no route uses an alias. The client
cannot send to that NID, so sends fail with "has no available nets".
A NID that the client can reach, such as a floating IP, can move to
another node. An alias would then send the import to the old node.
A local net or route add or delete thus bumps ln_prim_gen. The first
discovery of a peer also bumps it, because an alias ends only at a
checked peer.

With the default lock_prim_nid=1, discovery does not prune the locked
primary NID that an import keys on.

The new conf-sanity test 73j deletes the primary NID net on each
server. The client pings the pruned NIDs before the next send. A
route to the pruned net first stops each alias lookup. The route
delete then bumps ln_prim_gen. The test then checks that the imports
move and that I/O passes. The new test 73l is the negative control.
It prunes with fail_loc 0xe006, which stops new aliases. It checks
that an import then stays on a pruned NID and cannot connect.
