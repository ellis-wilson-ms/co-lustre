LU-20305 tcu: fix errors when deleting remote dirs under a shard

This patch main fixes the errors when deleting remote dirs under
a shard directory. The root cause is that the parent FID locate
on a remote MDT, but the child FID locate on the local MDT. When
deleting the child dir and create a "pFID" stub object, the stub
object must be located on the same MDT with the parent object.

This patch also tolerate the -ENODATA error when create the stub
striped dir in which it will move the trash shard objects from
Trash to the REMOTE_PARENT_DIR.

This patch fixes the atomic_open error for the virtul ".Trash".
It should not locate the target according to name hash, but
should locate the target according to the parent FID.

This patch also fixes the ->flush() call for the Trash directory.
If the readdir() via ".Trash" on a striped directory, some Trash
shards maybe not create yet. In this cast, it will report the
following error message:
"dir [0x280000404:0x1:0xffff0000] stripe 3 readdir failed: -2,
directory is partially accessed!"
We tolerate this error for Trash directory in ->flush for the
close() system call.

Add sanityn/test_118y to verify the above fixes.
