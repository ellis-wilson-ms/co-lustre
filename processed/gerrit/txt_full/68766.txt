LU-20725 osd-ldiskfs: run commit callbacks newest first

An MDS soft lockup panics the jbd2 commit thread in
ptlrpc_commit_replies() under a metadata create load.

osd_trans_txn_cb() runs the commit's callbacks in registration order,
so tgt_cb_last_committed() raises exp_last_committed one transno at a
time and ptlrpc_commit_replies() rescans the whole export uncommitted
reply list each time.  With sync lock cancel that list held 8069
replies in the crash dump, and 6930 callbacks were still queued.
ext4-jcb-optimization.patch reversed the order for older ldiskfs.

Queue the extra handles at the head so the callbacks run newest
registration first, which normally commits the highest transno first
and lets the rest take the tgt_cb_last_committed() fast path.
100k creates on 2 MDTs: 2.2e9 list steps scanned before, 1.0e5 after.
