LU-17000 obdclass: fix jobstats rbtree wipe on collision

job_alloc() clears js_idnode but leaves js_posnode as the zeroes
OBD_ALLOC_PTR() gave it, and job_insert_pos() only links js_posnode on
the path where the job was actually added to the id tree.  A job that
loses the insert collision is dropped with job_putref() while it is in
neither tree, so job_purge_locked() reaches

	rb_erase(&job->js_posnode, &stats->ojs_postree);

with an all-zero node.  rb_erase() reads a NULL parent from it, takes
that to mean the node is the root, and stores NULL into
ojs_postree.rb_node - every other job is dropped from the position tree
at once, job_stats output goes empty and later erases walk a detached
tree.  RB_CLEAR_NODE() is what makes the js_idnode erase on the same
path harmless; do the same for js_posnode.

While here, handle every error pointer from job_insert() in
lprocfs_job_stats_log() rather than only ERR_PTR(-EAGAIN).  -EAGAIN is
the only value it returns today, so this is hardening rather than a live
defect, but the "on collision" branch below treats any other error
pointer as a valid job.
