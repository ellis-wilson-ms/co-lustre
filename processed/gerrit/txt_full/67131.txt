--- Commit Message ---
LU-20463 ldlm: fix missing unlock in flock error path

When ldlm_lock_create() fails during a partial unlock operation
(lock split), unlock_res_and_lock(req) is not called, causing
the resource lock to be held indefinitely.

This can occur when:
1. A process holds a byte-range flock (e.g., bytes 0-999)
2. It unlocks a sub-range (e.g., bytes 100-199)
3. Server needs to split the lock into two separate locks
4. ldlm_lock_create() fails (e.g., memory pressure)
5. Error path returns without releasing the resource lock

Fix by adding unlock_res_and_lock(req) before returning on error.
