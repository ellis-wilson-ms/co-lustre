LU-20720 lfu: an object stream from the OSD otable iterator

lfu.ko: a misc device that streams the object table of one OSD
target to userspace through a ring.  The producer kthread holds a
private DOIF_PARALLEL iterator, so the raw inode-table path is
used and a running OI scrub is neither driven nor disturbed.  The
ring stalls the producer when full and never drops a record.

LFU_IOC_TARGET binds a descriptor to one target before its first
read(), so one loaded module serves every target the node mounts
rather than the one it was loaded for.  The name is the target as
mounted, fsname-MDT0000 -- what the osd-<backend> parameter
directory is keyed by and what the caller already has -- and the
OSD obd under it is that plus "-osd", which is lsi_osd_obdname's
convention and the module's to know, not the caller's.  The obd is
looked up at bind time so a wrong name answers -ENODEV then rather
than at the first read(), and so INFO can say which OSD it is; the
producer looks it up again when it starts, since nothing pins it
in between.  A read() before any bind answers -ENXIO, a bind after
the scan has started -EBUSY, and INFO before a bind carries no OSD
bit.

The producer reads trusted.lma, and for a regular file trusted.lov
and trusted.som, and for a directory trusted.lmv, through
DORA_XATTR while the iterator still holds the object -- on a
block-parsing iterator that is the inode-table block it already
has.  LMA and SOM cross whole; they are 24 bytes each.  LOV and
LMV cross as presence: a layout does not fit a fixed record, and
the question a consumer needs answered first is not what the
layout is but whether there is one, since a file with a layout has
a size that is not its inode's.  An object with no LMA is
classified as one, as a device scan classifies it, rather than
lent a FID by the FID the iterator built.

A name is the one thing a consumer most wants and the one thing a
fixed record cannot carry: a linkea is as long as the names in it.
So the record has a tail, and the ring is bytes rather than an
array of records.  struct lfu_rec is a header, 176 bytes with
lr_reclen and lr_linklen appended, and the tail is the object's raw
trusted.link, up to LFU_LINK_MAX.  read() returns whole records
only, each at an 8-byte boundary, so a consumer casts in place and
walks with lfu_rec_next().  A record may straddle the ring's end --
it is copied out in two parts -- but what the consumer receives is
contiguous, so nothing is padded and no record is skipped for the
wrap.  The ring is not mapped, so contiguity inside it buys
nothing.  An object whose link does not fit is said to have one and
left to fid2path; STATS counts them.  The wire version is 3: a
reader of 2 would take this stream for fixed records and read tails
as headers, and it refuses instead.

Three tier counters take three of the reserved STATS slots, since
whether these xattr reads cost I/O is the number the model rests
on; the 0x01 bit lr_lfu had free says the LMA is real.

No filter yet: every object is emitted and the consumer decides.

Owed before this leaves the lab: a Documentation/man4 page for each
module parameter, which checkpatch asks for.
