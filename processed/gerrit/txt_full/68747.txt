LU-20718 llapi: ignore stale EC fields from old servers

Before EC was introduced, servers wrote lcme_timestamp only for
NOSYNC components, memset only the layout header and reused the EA
buffer, so every other component was persisted with stale bytes in
what EC now reads as lcme_time_and_id and the EC stripe counts.  A
stale link id makes llapi_layout_merge() flag an on-disk component
LCME_FL_IS_LINK_ID and the layout fails sanity ("lfs setstripe
--component-add": "Wrong flags", sanity-pfl test_18); a stale
timestamp prints as a date in the year 56546 (sanity-pfl test_19e).

Read the timestamp only for NOSYNC components or EC layouts, and a
data component's link id and stripe counts only while a parity
component, which such a server never wrote, links to it.  Print the
link id and timestamp only for layouts with a parity component, and
the timestamp also for NOSYNC components.

Fixes: 472e0f27d411 ("LU-19545 ec: tight binding parity mirror to data mirror")
