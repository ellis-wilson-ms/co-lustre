Experimental feature testing in progress, please pay attention to the comments

The change itself looks correct: class_incref() only does kref_get() on obd_refcount (an atomic kref), so obd_dev_lock never protected it, and lmv_obd's lifetime is already covered by obd_device_lock() (the obd_devs xa_lock) held across the loop. Removing the inner obd_dev_lock breaks the xa_lock -> obd_dev_lock nesting that lockdep flagged.

Since this fixes a real locking bug (the circular dependency in the commit message), it should carry a Fixes: tag. The xa_lock wrapper and the obd_dev_lock around class_incref were both introduced together, so consider:

    Fixes: c5e5060d9502 ("LU-8802 obd: remove MAX_OBD_DEVICES")

That commit converted obd_devs to an Xarray, wrapped this loop in obd_device_lock() (xa_lock), and added the spin_lock(&lmv_obd->obd_dev_lock) around class_incref() that this patch removes, which is what created the lock ordering being fixed.
