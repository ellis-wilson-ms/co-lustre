LU-20722 llapi: a scan backend for a target in service

The third backend of llapi_scan_device(): a target that is mounted
and serving, read through the Object Stream lfu.ko exports rather
than from the device underneath it.  Same five entry points as the
ldiskfs and ZFS backends; a different device layer, and the only
one that works while the target is in service.

A device that appears in osd-*.<name>.mntdev is in service and is
routed here when /dev/lfu_scan exists.  Where the module is not
loaded the device backends answer as before.

The backend binds the target right after open(), before INFO, so
one loaded module serves every target the node mounts.  An ENOTTY
there is a module from before the per-open bind, which would have
scanned whatever it was loaded for and called it this device; it is
reported as -EPROTO and named, not scanned.

Records carry trusted.lma and, for a regular file, trusted.som, so
the classifier sees LMAC_FID_ON_OST and a file with a layout is not
given its MDT inode's size as its own.  A layout crosses as
presence rather than as bytes, so the backend interface gains
so_xa_present, distinct from so_xa_valid, and scan_size() asks it:
a backend that has the bytes sets both, and this one can say
"striped" without handing the scanner a layout it would then hand
to lfs find -O as real.

The link is handed over as it is, which is what the scanner reads
off a device, so --paths and -name answer through it.  --paths makes
two passes on one open -- the directory map, then the search -- and
the ring is one enumeration per open, so the backend opens and binds
again when a pass is asked for after the stream was read out.  The
device backends read the disk twice for the same thing; this one
opens twice.

One chunk, one reader: parallelism stays behind the enumerator in
the kernel.

On the 09-09 fixture, one node serving lustre-MDT0000 and two OSTs,
88k files:

  lustre-MDT0000       87961      device scan: 87961, diff 0
  lustre-OST0000       44005      device scan: 44005, diff 0
  --paths       kernel 87957      device        87957, diff 0
  -name 'f12*'  kernel  1000      device         1000

  -size +0c / +1k / 0c on the MDT: 51 / 1 / 87895, both ways
  87957 of 88051 records carry a link, 46 bytes on average, none
  over the bound; 351896 xattr reads, all inline; no stalls.
