LU-20107 nrs: add the GDNRS coordinator and node agent

All the targets of one server node share the PtlRPC services and the
per-CPT NRS schedulers of the node. Thus a QoS setting is a setting
of the node, not of a target. Today an administrator writes the same
command to the nrs_policies file of every OSS and MDS. The nodes
drift apart when the administrator misses one write.

Add the Global Distributed NRS (GDNRS). A coordinator runs on MDT0,
and one agent runs on every server node. The coordinator takes a
command through the debugfs file gdnrs.cdtor.$FSNAME.conf, in the
form of the nrs_policies file:

  lctl set_param gdnrs.cdtor.$FSNAME.conf=
    "<tbf|mclock> [reg|hp] [<class type>] [key=value ...] [service=]"
    "<fifo|crrn|orr|trr|delay> [reg|hp] [service=]"

A classful policy name gives a scheduler start command. A start
command with no class type starts the generic class type. Any other
policy name gives a scheduler stop command. That command names the
policy that replaces the classful scheduler. A policy that the
service of an agent does not know fails on that agent.

The coordinator also takes a rule command through the debugfs file
gdnrs.cdtor.$FSNAME.rule. The command has the form of the
nrs_policies rule files:

  lctl set_param gdnrs.cdtor.$FSNAME.rule=
    "start <name> {conds} [key=value ...] [service=] [type=]"
    "change <name> key=value ... [service=] [type=]"
    "stop <name> [service=] [type=]"

The type= key names the scheduler of a rule command. The coordinator
converts a rule start, change or stop command to the wire. The agent
converts it back. The agent does not start a rule yet: a rule start
returns -EOPNOTSUPP.

The service= key names the PtlRPC service of the command, ost_io
when absent. The [reg|hp] token and the queue= key select one NRS
head instead of both. Only the coordinator accepts the service=,
type= and queue= keys. nrs_parse_cmd() refuses them on the local
nrs_policies and rule files.

The coordinator parses the command with nrs_parse_cmd() and
NRS_TYPE_FLAG_DYNAMIC. Thus the coordinator does not need the class
type of the schedulers on the agents. It then converts the command
to the wire struct gdnrs_cmd. The struct has a fixed layout in
lustre_idl.h, with checks in wirecheck.c and wiretest.c. The rate
fields of a rule go on the wire as struct gdnrs_ratecfg. The wire
values of the command types must not change. The same rule applies
to the NRS_CONF_FL_* bits and the NRS_TYPE_FLAG_* bits.

The command goes to one target of every node as a new GDNRS_CONF
RPC. Its path is MDT0, MDD, LOD and then OSP. LOD sends one RPC per
peer NID of the current connection of its targets. Thus a target
that fails over to its partner node gives that node an RPC of its
own. LOD holds no OSP for the local MDT. LOD compares the peer NIDs
with the local NIDs. If no target of the MDT descs is on the node of
MDT0, the local agent applies a metadata command. The local agent
also runs when the push to another MDT node fails. Every node gets
the command, even after a failure on an earlier node. lctl set_param
returns the first error. OSP sends the command to an OST on
OST_CREATE_PORTAL, as osp_statfs_update() does. Thus the command
does not wait in the ost service whose scheduler it can replace. OSP
sends the command to an MDT on OUT_PORTAL.

The agent handler tgt_gdnrs_handlers is in the slice tables of OFD
and MDT. The handler accepts the RPC only from the export of an MDT.
It returns -EPERM to any other export. The agent checks the count of
allowed types from the wire. A count above NRS_ALLOWED_TYPES_MAX
gives -EPROTO. A wire name with no NUL byte also gives -EPROTO.
The agent finds the ptlrpc_service of the portal of the command. It
then runs ptlrpc_nrs_policy_control() on the heads that the command
names, like the nrs_policies write path.

The start parameters of a policy become struct nrs_params. The field
np_arg is the argument string of the lprocfs path. The field np_data
is the parsed command of the agent. Thus op_policy_start() takes
struct nrs_params instead of a char pointer. A parsed command always
restarts the policy. The agent sets np_arg to "gdnrs:<class type>".
Thus a later local write of the same class type restarts the policy.

The function gdnrs_cmd_to_nrs_cmd() removes the head bits and the
type bits from nc_confl before the scheduler checks nc_confl.
Otherwise "tbf hp nid" fails with -EINVAL on every agent.

The coordinator is optional. When it cannot start, MDT0 logs a
warning and mounts without it.

Add a "Global NRS coordinator" section to nrs_policies.4 for the
conf file of the coordinator.

Add sanityn tests:
- 77wm switches ost_io between tbf, mclock and fifo from the
  coordinator, and checks the primary policy on every OSS.
- 77wn switches ost_io to crrn, orr and trr.
- 77wo selects the reg or hp head of the default service.
- 77wp configures the mdt and mdt_io services.
- 77wq writes malformed and unknown commands. The coordinator must
  refuse them, and the schedulers must stay. A local nrs_policies
  write with service= must fail.
