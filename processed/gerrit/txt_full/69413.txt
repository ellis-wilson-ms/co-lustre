LU-20791 efalnd: Reference count connections

Connections were destroyed by the connection daemon based only on idle
time and empty transmit queues. A connection could still be referenced
by a context that had looked it up, or by an in-flight transmit that had
not yet completed, leaving that context to dereference freed memory.

Add a reference count to the connection. A lookup or creation returns a
reference that the calling context owns and releases before it returns.
A transmit takes its own reference when it adopts a connection and
releases it on completion.

The reference count is checked only at the final destroy step, together
with the existing idle time and empty queue checks. Idle time alone
decides when a connection enters the cleanup pipeline, so that the drain
stage can force stuck transmits to complete and drop their references. A
transmit can stay outstanding until a remote reply arrives, so holding a
connection out of cleanup while a reference is outstanding could leave
it alive indefinitely when that reply never comes.
