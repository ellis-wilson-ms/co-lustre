LU-17000 mdt: reject an MDS_READPAGE that carries no FID

mdt_readpage() takes its object from tsi->tsi_corpus and passes it to
mdt_object_child(), which opens with LASSERT(o).  But
tgt_mdt_body_unpack() leaves tsi_corpus NULL and still returns success
when the client sends an mdt_body without OBD_MD_FLID, or with a zero
mbo_fid1 - a case it tolerates on purpose for pre-2.5 clients - so any
connected client can LBUG the MDS with a malformed MDS_READPAGE, and
with libcfs_panic_on_lbug set that takes the node down.  Only a build
with libcfs debug disabled faults instead.

Return -EPROTO the way the five other handlers that guard this same
condition do (mdt_getattr(), mdt_swap_layouts(), mdt_sync(),
mdt_tgt_getxattr(), mdt_hsm_state_get()), which is also what
tgt_ost_body_unpack() returns for the equivalent OST case.
