--- Commit Message ---
LU-20856 llite: do not force commits on background writeback

Background writeback runs whenever a client's dirty pages pass the
background threshold, which is normal for any client that is
writing. Since LU-16713 it is treated as memory reclaim, so every
background writeback pass sent an OST_SYNC for each stripe of
every file it visited, and busy clients produced storms of
forced journal commits on the OSTs.

Force a commit only for writeback started for page reclaim, which
LU-16713 added at the same time. Memory-limited cgroups do not
depend on the background commit: writers that write several times
their cgroup's limit with no fsync are not OOM-killed on cgroup v1
or v2 without it. Background writeback keeps the priority it gets
when the writer is over its dirty limit, so the active extent
flush from LU-19014 is unchanged.

Add sanity test 411c: with background writeback running for the
whole of a buffered write that never calls fsync, the client must
send far fewer OST_SYNC than OST_WRITE.
