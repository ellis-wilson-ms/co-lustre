LU-20589 llite: fail IO when the restart budget runs out

ll_file_io_generic() restarts an IO when a lower layer sets
ci_need_restart, at most RETRY_ATTEMPTS times.  One producer of
that request is can_populate_pages().  It compares the cached
layout generation of the inode with the generation the IO took a
copy of.  On a mismatch vvp_io_write_start() returns 0, a success
which moves no bytes.

If the generation keeps changing, the restart loop uses every
attempt.  The client can cause this drain, for example by
cancelling its own layout locks from LRU reclaim.  Control then
reaches RETURN(result > 0 ? result : rc) with result and rc both
0.  The io->ci_result fallback does not help.  vvp_io_init() and
lov_io_slice_init() reset ci_result to 0 on every restart.  The
layout mismatch path never sets it.  write(2) then returns 0 for
a non-zero request.  It drops the data without a message.
read(2) reports a false end of file.

Report -EIO when the budget runs out and nothing moved.  Also
log the fsname, FID and IO range at a rate limit.
ll_file_io_generic() still returns a transfer that moved some
bytes as a short IO.  -EIO is not retryable.  The condition that
causes it can be transient.  An error the application can see is
better than a silent loss of data.

Make the layout mismatch fault injection repeatable so that a test
can use up the budget.  Add sanity test_251c, which checks that
both a write and a read fail instead of returning 0.
