LU-17364 llite: discard un-flushable pages on evicted inode teardown

ll_delete_inode() flushes a still-linked regular file's dirty pages with
CL_FSYNC_LOCAL before truncating them, to avoid losing data at umount.
When that flush fails -- the client was evicted mid-write, or an OST
returned an I/O error -- the dirty pages are left in a cached (OES_CACHE)
extent that can never be written back now.

ll_truncate_inode_pages_final() then tears each page down via
osc_page_delete(); osc_teardown_async_page() finds the page still pending
in a non-OES_TRUNC extent, returns -EBUSY, and trips the assertion:

  (osc_page.c:182:osc_page_delete()) Trying to teardown failed: -16
  (osc_page.c:183:osc_page_delete()) ASSERTION( 0 ) failed
  (osc_page.c:183:osc_page_delete()) LBUG

This is the same osc_page_delete() teardown LBUG addressed for the mmap
write-fault path by commit dad3bed7617f ("LU-17364 llite: don't use stale
page."), but that fix is insufficient here: it stops a stale (non-uptodate)
page being reused for write in vvp_io_fault_start(), whereas this crash is
reached from inode eviction (ll_delete_inode -> ll_truncate_inode_pages_
final) tearing down a page that is dirty and cached, not stale. A build
carrying dad3bed7617f still LBUGs on the test below.

The regression originates in commit 41ef9e4b1085 ("LU-5584 llite: ensure
all data flush out when umount"), which changed ll_delete_inode() from
CL_FSYNC_DISCARD to CL_FSYNC_LOCAL. The discard it removed was, per its own
comment, "required by osc_extent implementation at LU-1030": osc requires
the dirty pages be discarded before truncate. CL_FSYNC_LOCAL preserves data
on a healthy client, but when the flush fails the discard never happens and
the invariant is violated.

The inode is being deleted regardless, so once the local flush fails the
data is already lost. Discard the pages locally with CL_FSYNC_DISCARD --
which completes cached extents without an RPC -- so the following truncate
has nothing left to trip on.

Add OBD_FAIL_OSC_NO_FLUSH to emulate a client that can no longer flush
(osc_cache_writeback_range() fails the non-discard flush and leaves the
dirty pages in their cached extent) and sanity test_912 to exercise the
inode-teardown path. Without this fix test_912 LBUGs in osc_page_delete();
with it the umount completes cleanly.

Fixes: 41ef9e4b1085 ("LU-5584 llite: ensure all data flush out when umount")
Fixes: dad3bed7617f ("LU-17364 llite: don't use stale page.")
