LU-20290 lnet: refactor discovery visibility framework

Refactor the discovery visibility framework to support multiple
independent visibility policies.

Each active policy contributes a partitioning of the local
discovery view. Composite views are formed by intersecting those
partitions, allowing multiple visibility policies to be combined.
The shared full discovery view is published only when every
active policy permits unrestricted visibility. Empty composite
views are omitted.

For unconstrained discovery Pushes, advertise each eligible
filtered view separately and track delivery independently so
temporarily unreachable views remain pending without blocking
reachable ones. Retry transient background Push failures with
bounded backoff, preserving completed deliveries and allowing
normal peer traffic to proceed.

Route and gateway topology changes can alter filtered-view
eligibility without changing the published view generation.
Re-evaluate routing-sensitive peers and restart stale Push
batches when topology changes.

Distinguish discovery Ping and Push MD unlink events using
LNET_MD_TRUNCATE and the saved MD cookie. Avoid attributing
delayed unlink events to unrelated outstanding discovery
operations, including when visibility filtering is disabled.

Retire replaced filtered views asynchronously while keeping their
buffers referenced until outstanding MDs complete. Track retired
MDs so shutdown waits for all filtered views to drain.

Keep global discovery and routing feature state consistent across
shared and filtered views. Only advance filtered-view generation
for NI status changes that affect a published filtered view.
