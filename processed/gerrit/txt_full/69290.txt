LU-20840 mdt: don't drop stalled dir migration

During directory restripe, mdt_restripe_migrate() migrates sub-files
one dirent at a time. If a sub-file is open by a client,
mdt_reint_migrate() returns -EBUSY and the error path removes the
stripe from the migrating list and drops it. This abandons migration
of the remaining entries in that stripe, leaving the directory
permanently in the restriping state, which blocks clients.

Treat -EBUSY as transient: keep the stripe queued and retry the same
entry later, so migration completes once the file is closed. To avoid
the restriper thread busy-spinning while the file stays open, record a
retry time (mdr_migrate_next) and gate the migrate branch of the
restriper main loop on it, sleeping until the retry time via
schedule_timeout() when a migration is backing off.

Add sanity test 230C and a fault injection point
(OBD_FAIL_MDS_RESTRIPE_MIGRATE_BUSY) that makes the restripe migration
return -EBUSY once, then verifies the migration still completes.

Also cap the dir_split_delta tunable at the MDT count in
dir_split_delta_store(): a single auto-split adds at most one stripe
per MDT, and a larger delta would only be silently reduced by the
target count clamp in mdt_auto_split().
