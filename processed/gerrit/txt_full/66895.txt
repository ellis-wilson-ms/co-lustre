LU-20290 lnet: group discovery views by a pluggable source

The self-only discovery-view policy advertised exactly one NID per
view, so a client saw each server NIC as its own single-NID peer. A
NUMA-aligned pair of NICs that should be coalesced into one multi-rail
peer cannot be expressed that way.

Generalize the single active policy into a group policy: it advertises
one view per group of local NIDs, keyed on the ingress NI, so a client
coalesces each group into one multi-rail peer. Where the groups come
from is a pluggable group source below the policy -- the only thing
that varies between groupings. This commit ships the per-ni source,
which makes each NI its own singleton group and is therefore
byte-identical to the self-only policy it replaces.

Group membership lives in a refcounted per-generation table reached
through a new pb_group_table pointer on the ping buffer. A view
resolves its group only through its own buffer's table, so current and
retiring generations coexist across a make-before-break refresh and
each table is freed when its last referencing buffer is freed. The
attach path stamps the table and key before the policy, so any view
reachable on the serve path -- which gates on a non-NULL policy --
already has its backing table.

lnet_self_nets is retained as the participating-net list and selects
the per-ni source. The self-only selectors and vtable are removed; the
net-list parsing front-end is kept.

No functional change: a per-ni group is a single NID, so view content,
serve, and push behave exactly as the self-only policy did.
