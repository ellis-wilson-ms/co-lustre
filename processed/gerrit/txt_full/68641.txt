LU-20438 lnd: fix EFA P2P configure guard

kefalnd_startup() guards its ni_p2pdma initialisation with
IN_KERNEL_HAVE_OFED_IB_DMA_PCI_P2P_DMA_SUPPORTED.  That name is
emitted only from LN_CONFIG_O2IB, which defines
LN_CONFIG_O2IB_SRC/LN_CONFIG_O2IB_RESULTS as empty macros when
o2ib is disabled, so a --disable-o2ib --enable-efa build defines
neither it nor the plain HAVE_OFED_ spelling and the hunk compiles
out, leaving ni_p2pdma clear on an EFA NI that does support P2P
DMA.  Test for ib_dma_pci_p2p_dma_supported() in LN_CONFIG_EFALND,
next to the EFA LND's other in-kernel rdma checks, and key
efalnd.c off that result instead.

Two kfilnd CDEBUG lines label tn->tn_p2p as "device %s"; print it
as "p2p %s", the spelling o2iblnd uses for the same value.
