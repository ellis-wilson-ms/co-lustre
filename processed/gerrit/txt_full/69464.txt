LU-20879 target: fix OUT double swab and xattr_list slot

out_handle() swabs each update buffer with
lustre_swab_object_update_request(), which already swabs every
object_update in it, then swabs each update again with
lustre_swab_object_update() while sizing the reply.  For a request
from a peer of the other byte order, this puts ou_type,
ou_params_count and ou_result_size back into wire order, so the
reply size and the walk to the next update are wrong, and the
second pass walks a byte-swapped ou_params_count of params,
swabbing memory past the end of the update.  Remove the second
swab and make lustre_swab_object_update() static.

out_xattr_list() gets its result buffer from reply slot 0 instead
of the update's own reply index.  If OUT_XATTR_LIST is not the
first update in a request, the xattr list overwrites the results
of the earlier updates and is missing from its own result.  Use
the update's reply index, as out_xattr_get() does.  OSP sends
OUT_XATTR_LIST alone in its request today, so this is latent.

Also print the real reply index in the out_attr_get() and
out_index_lookup() debug messages.
