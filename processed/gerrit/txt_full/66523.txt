LU-20339 gss: truncate keyfile when rewriting client key

write_config_file() opens the output with O_WRONLY | O_CREAT and, on
the overwrite path, without O_TRUNC. When a client mounts with an
ASCII-encoded type=server key (LU-19073), sk_load_keyfile() generates
the DH prime and rewrites the file in binary form. The binary image
is smaller than the ASCII representation, so the rewrite leaves a
stale ASCII tail; the immediate re-read no longer matches the
"Lustre SSK v1.0" magic and fails with "does not have a complete
key", aborting the mount.

Add O_TRUNC and O_SYNC on the overwrite path so a rewrite always
replaces the full file contents and syncs them to disk promptly to
avoid a truncated or partially written file on error.
The create-only path keeps O_EXCL.

Extend sanity-sec test_100 to run the mount-time prime generation and
key-rewrite path for both a binary and an ASCII server key, and to
verify the rewritten key parses back as a complete client key.
