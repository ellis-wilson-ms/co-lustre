LU-20669 ofd: record update extents of reflink objects on write

When a snapshot mirror is created from a template mirror, the new
data objects reference link the data of the read-only template
objects on the same OST. Writes to such a reflink object must be
recorded in its snapshot extent index ("<oid>.ind") so that a later
read can tell which ranges hold the object's own data and which
still come from the template.

- Add mirror component flags LCME_FL_READONLY (0x800) and
  LCME_FL_REFLINK (0x1000), and LCME_FL_SNAPSHOT as READONLY|NOSYNC.
  In lod_layout_repeat_mirror(), tag the new components with
  LCME_FL_REFLINK when the template component is instantiated,
  and mark the template components LCME_FL_SNAPSHOT | LCME_FL_STALE
  (with the mirror entry set stale) so the template is never
  written to or resynced from the new mirror. Add "readonly" and
  "reflink" to the layout flag names in lustreapi.h.
- Add OBD_MD_REFLINK (0x0000800000000000ULL) to obdo::o_valid. The
  client sets it in lovsub_req_attr_set() for a LCME_FL_REFLINK
  component so that the OST knows the object reference links a
  snapshot object.
- Change struct update_extent_rec to uex_start, uex_end, uex_scn and
  uex_flags. An extent is [uex_start, uex_end] with both ends
  inclusive, like a DLM extent lock, and PAGE_SIZE aligned. Record
  fields are stored little-endian on disk while the index key
  (uex_start) is big-endian so that the memcmp() order of the IAM
  lfix index matches the offset order.
- OFD write path for OBD_MD_REFLINK objects:
  * ofd_preprw_write(): ofd_update_extent_lookup() positions the
    index iterator with iops->load() on the write start and collects
    the recorded extents overlapping or contiguous (e1 + 1 == s2)
    with the PAGE_SIZE aligned write range into
    ofd_thread_info::fti_uex, validating alignment of each record.
  * ofd_commitrw_write(): ofd_update_extent_merge() walks the local
    buffers, rounds each contiguous range to PAGE_SIZE and merges it
    with the collected extents, leaving the gaps between
    discontiguous ranges untouched unless a recorded extent bridges
    them; unchanged extents are filtered out. The remaining old
    extents (fti_uex) are deleted and the merged ones (fti_uex_new)
    inserted in the write transaction by
    ofd_written_index_declare_update()/ofd_written_index_update().
  * The sentinel [0, 0] record of a new ldiskfs IAM leaf is treated
    as the extent to replace by a write starting at offset 0.
  The per-thread extent arrays are freed in ofd_key_fini().
- check_iam: add record type "update_extent" to decode the index,
  printing "<key>\t[<start>, <end>] scn <n> flags 0x<f>".
- Add wirecheck/wiretest constants for the new flags.
- Add sanity-lsnapshot.sh test_5f: write pages at various offsets of
  a snapshot mirror file and verify with debugfs + check_iam that
  the recorded update extents are merged (contiguous, overlapping,
  bridging), disjoint writes add extents, rewrites inside a recorded
  extent change nothing, and the IAM sentinel is replaced by a write
  at offset 0.
