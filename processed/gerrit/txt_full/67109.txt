LU-20306 scripts: lustre_rmmod wait to drain OBD devices

On a busy system, it is possible that some of the OBD devices may
still be processing mgc/lwp/osp import disconnects and obd_zombie
list asynchronously after umount completes.  If lustre_rmmod is
called immediately after umount returns it may fail spuriously due
to references on a module from active OBD devices.

Add a '-w | --wait SECONDS' option to lustre_rmmod so that it will
wait for a short time until the OBD devices are cleaned up (according
to 'lctl device_list') before trying to unload the modules.  If no
devices are configured or 'lctl' returns an error (i.e. no module is
loaded at all) there is no wait, and if the devices are successfully
cleaned up then the wait terminates immediately.

If the modules are still loaded when the wait expires, it will still
try to unload the modules, and will fail with an error at that time.

The default wait interval is 60s, and can be avoided with '--wait 0'.

Add a man page for the lustre_rmmod command.
