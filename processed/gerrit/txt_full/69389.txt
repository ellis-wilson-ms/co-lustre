LU-20869 tests: speed up sanity 160n

test_160n accumulates more than 65000 changelog records
before racing changelog_clear against deletion. It did so
with createmany, a shell loop forking mrename 10001 times,
and unlinkmany: 3 records per file, 30000 per pass, and
three passes (about 90000 records) to cross the target.
The mrename forks made it slow, 757s and 1057s on a VM.

Create and unlink 33000 files per pass instead. That is
2 records per file (CREAT and UNLNK), so a single pass
gives 66000 records, still above the 65000 target, and
the fail_loc race section is unchanged. On a VM the test
now takes 43s and 27s.

Cap the per-pass count to MDT0's free inodes, as test_24v
does, so a tiny MDT takes an extra pass instead of failing
in createmany().
