LU-19921 ptlrpc: atomic switch in nodemap_export_refresh

The nodemap_export_refresh() temporarily leaves the export
with a NULL ted_nodemap because it calls nodemap_del_member()
followed by nm_member_add(). This creates a window where the
export is live but has no nodemap assigned, which violates
the invariant that a live export must always have a valid
ted_nodemap and can cause panic.

Refactor the code by extracting the atomic switch logic from
nm_member_reclassify_nodemap() into a new shared helper function,
nm_member_reclassify_export(). Update nodemap_export_refresh()
and nm_member_reclassify_nodemap() to use this helper, ensuring
that the ted_nodemap pointer is always updated atomically under
the appropriate locks.
