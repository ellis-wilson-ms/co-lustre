LU-20783 llite: ignore nolock, remove LL_IOC_SETFLAGS

The nolock mount option and LL_IOC_SETFLAGS with
LL_FILE_IGNORE_LOCK both forced CILR_NEVER and
ci_no_srvlock, making buffered I/O both client- and
server-lockless. osc_req_attr_set() needs one of the two
to find a lock covering a dirty page when it builds a
writeback RPC; with neither, it LBUGs with "uncovered
page!" and "No lock resource". Direct I/O does not need
either interface: it is already client-lockless by
default, and normally still takes a server-side extent
lock per RPC, which these interfaces also dropped for no
benefit.

nolock still mounts, but is now ignored with a console
warning. LL_IOC_SETFLAGS and LL_IOC_CLRFLAGS are removed;
their ioctl numbers and LL_FILE_IGNORE_LOCK stay reserved
in lustre_user.h, and now fall through to -ENOTTY. A caller
that used LL_IOC_SETFLAGS(LL_FILE_IGNORE_LOCK) to get an
O_DIRECT file fully lockless, such as IOR's
--posix.lustre.ignorelocks, will see that ioctl fail rather
than silently keep the lock it asked to drop.
ll_file_nolock(), CILR_NEVER and ci_no_srvlock, along with
the code paths that existed only to serve them, are removed
as unreachable.

ll_show_options() had two separate display bugs around
"nolock". LL_SBI_NOLCK has no paired positive "lock"
pattern, so its generic "no"-prefix on/off handling printed
",nolock" on every mount that never asked for it; fixed by
skipping that token in the loop, since it is now never set.
The other bug was the leading, comma-less print used for an
actual nolock mount, which ran straight into the "rw" the
VFS itself prints, showing up as "rwnolock"; fixed by
dropping that print along with the option's effect.

Reproduced by mounting with nolock and doing a buffered
write: writeback LBUGed in osc_req_attr_set() as above.
The same write now takes a normal lock and completes
cleanly. Added conf-sanity/163 to cover it.
