LU-20788 tests: wait for quota release in sanity-quota/75

The squashed-root DoM part of test 75 removes files written
to one target and then expects a write within the limit to
succeed on another, as test 63 does. Grant still held for
the removed files can exhaust the limit first. This addresses
the phase-three DoM write failure reported in LU-20788.

After each cleanup, wait for deferred destroys. On ZFS,
which only returns space when the transaction group commits,
also wait before each of the three phases for enough grant
to be released, as test 63 does. Pin $tdir and $tdir_dom to
MDT0 and OST0000, as test 63 does for its own directories, so
the wait only needs to poll those two targets.

Move the ZFS check into a helper, used by test 63 too.

Test-Parameters: fstype=zfs testlist=sanity-quota env=ONLY=75,ONLY_REPEAT=20
Test-Parameters: fstype=zfs testlist=sanity-quota env=ONLY=63,ONLY_REPEAT=10
