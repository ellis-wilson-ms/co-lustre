LU-9633 obdclass: fix up jobid.c kernel doc

The lustre_get_jobid() comment became a real kernel-doc block, so it
is now rendered as reST, and it did not survive that.  The list of
obd_jobid_var values was a plain indented table: reST folds those
lines into one paragraph, and the indented continuation line for
/sys/fs/lustre/jobid_this_session raises an "Unexpected indentation"
error followed by an "unexpected unindent" warning.  Rewrite it as a
bullet list, the form the rest of this conversion uses for
multi-valued sections, which also drops the inconsistent ':' that
JOBSTATS_SESSION was missing.

Fix documented Return contract to match existing behaviour.

Document the two @joblen constraints as well: values below 2 are
rejected with -EINVAL, and min_t() caps the produced jobid at
LUSTRE_JOBID_SIZE.  The cap is on the jobid, not on the buffer - the
disabled case memsets all of @joblen.

Also unindent the wrapped summary line to the plain " * " continuation
that most converted blocks in obdclass use, such as
cl_object_glimpse() and lprocfs_stats_lock().

Reviews also found some return-related defects that will be addressed
by follow on patches.
