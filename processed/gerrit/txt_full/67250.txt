LU-20055 llite: Disable vfs leases

A VFS lease is node-local state: nothing in Lustre calls
break_lease(), so a lease is never recalled when another client,
or the MDS, changes the file. Over a re-exported mount nfsd turns
that lease into an NFSv4 delegation, and the NFS clients holding
it go on serving stale contents, which is the symptom this ticket
was opened for.

All the in-kernel cluster filesystems (ceph/gfs2) disable leases
for the same reason; only nfs4+ and cifs enable them. So refuse
them here too.

Add a compatibility check since the default flipped in v7.0: up to
v6.19 an unset ->setlease means generic_setlease() and leases are
granted, which is what every RHEL release we support (8, 9, 10)
does, while from v7.0 an unset ->setlease is itself the way to
refuse leases and simple_nosetlease() no longer exists.

Directories need the same treatment. v6.19 added F_SETDELEG, whose
fcntl_setdeleg() has no S_ISDIR guard the way fcntl_setlease() does,
and generic_setlease() there takes a directory for F_RDLCK, so
ll_dir_operations without ->setlease hands out directory read
delegations on v6.19. ceph sets it on its directory fops for the
same reason.
