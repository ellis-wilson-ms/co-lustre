LU-8933 obdclass: move RR target selection to lu_tgt_alloc.c

The round-robin start index handling is duplicated in
lod_ost_alloc_rr() and lod_mdt_alloc_rr(), and can only be tested
on a filesystem with the right OST, OSS and stripe counts, so
imbalances in it have gone unnoticed for many of them.

Move the RR array placement and start/next index handling into
lu_rr_place_tgt(), lu_rr_start() and lu_rr_next() in
obdclass/lu_tgt_alloc.c, shared by the OST and MDT allocators, and
later by the LMV client allocator, using only a few kernel interfaces
that are easily stubbed so that it can also be built in userspace.

Add lustre/tests/lod_rr_test, which builds lu_tgt_alloc.c with a few
stubs and checks the object distribution for 3-64 OSTs on 1-4 OSSs
and all stripe counts in a few seconds, and sanity test_51g to run
it.  It only counts the first stripe imbalance for now, since the
current code fails that check for some combinations.  There is no
functional change.
