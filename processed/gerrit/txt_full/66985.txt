LU-20438 lnd: Support PCI P2P DMA mapping

Modify o2iblnd to support mapping PCI P2P DMA pages.
Check HCA capabilities for P2P DMA support and use
appropriate DMA mapping APIs when P2P pages are detected.

Fix LBUG crash during zero-length bulk transfers when P2P DMA is active.
A zero-length GET sink MD (`msg_md->md_length == 0`), or a zero-length
payload for PUT/REPLY operations, trips the assert. When P2P DMA
is enabled, the code bypassed IMMEDIATE message checks and attempted
RDMA mapping even for 0-length transfers, triggering an assertion
panic in kiblnd_setup_rd_kiov. Fix this by forcing IMMEDIATE mode if
the transfer size is 0.

Clean up deprecated lnet_md_is_gpu() helpers across lnet and convert
callers in kfilnd (tn_gpu -> tn_p2p), efalnd (gpu -> is_p2p), and
o2iblnd (tx_gpu -> tx_p2p in struct kib_tx, and gpu -> is_p2p in
kiblnd_send()). Initialize ni->ni_p2pdma capability flags in startup
routines.

Prevent a kernel panic when transferring GPU pages that trigger a
negative error configuration code (e.g. NVFS_IO_ERR). The return of
lnet_rdma_map_sg_attrs() is verified to pass on negative returns
so it does not improperly fall through to a legacy memory map and
fail bounds checks. Assign kiblnd_dma_map_sg() to a signed integer
explicitly before checking to ensure no implicit loop truncations occur.
