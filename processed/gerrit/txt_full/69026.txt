LU-17217 nodemap: add client version policy

Let admins control which Lustre client versions may connect,
using nodemap rather than a separate policy framework. Each
nodemap gets a version_policy property, shown as POLICY:GLOB,
where GLOB is matched against the client "major.minor.patch"
version when it connects to an MDT or OST:

  allow:GLOB       only clients matching GLOB may connect
  block:GLOB       clients matching GLOB are refused

The default is allow:*, which accepts every client. A refused
client gets -EACCES at connect time, so the mount fails and the
import is deactivated rather than retried forever. Server to
server connections (MDS, MDS_MDS and lightweight) are never
checked, so a policy cannot partition the servers.

The policy is stored as a new NODEMAP_CLUSTER_VERSION record in
the nodemap config, so it is distributed to all servers like the
other nodemap properties. The record is only written when a
policy is set, so older servers never see it. Dynamic nodemaps
inherit the policy from their parent and may only change it if
the parent has no policy, or raises the new version_policy
privilege via child_raise_privileges.

Add "lctl nodemap_set_version_policy --name NM --policy
{allow|block} [--glob GLOB]", a man page, and sanity-sec
tests 86a (mount enforcement) and 86b (dynamic nodemap
privilege).
