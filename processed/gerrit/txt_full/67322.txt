LU-19955 osd: flush the old EOF page after a growing fallocate

fsx based tests intermittently LBUG the OSS:

  LustreError: (osd_io.c:1525:osd_write_commit())
          ASSERTION( !PageDirty(lnb[i].lnb_page) ) failed

osd_write_commit() requires that no page it is handed is dirty.  That
holds only if nothing leaves a dirty page behind in the OST page
cache, because osd_get_page() reuses an existing page cache page for
an IO that bypasses the cache, rather than allocating a private one,
to avoid data aliasing.

fsx issues fallocate(FALLOC_FL_ZERO_RANGE) without FALLOC_FL_KEEP_SIZE,
so a zero range that reaches past EOF grows the file.  osd_fallocate()
defers such a request to osd_execute_fallocate(), which calls into
ldiskfs and then flushes the range it asked for:

	rc = file->f_op->fallocate(file, mode, start, end - start);
	if (rc == 0)
		osd_partial_page_flush_punch(d, inode, start, end - 1);

ldiskfs_zero_range() allocates the blocks via
ldiskfs_alloc_file_blocks(), which, as it extends i_size, does:

	if (epos > old_size) {
		pagecache_isize_extended(inode, old_size, epos);
		ldiskfs_zero_partial_blocks(handle, inode,
					    old_size, epos - old_size);
	}

That zeroes - and with mark_buffer_dirty() dirties - the partial block
at the *old* EOF.  The old EOF is unrelated to [start, end), so the
range flush above never covers it and the page stays dirty in the page
cache.  A write that lands on it before the next journal commit writes
it back picks it up out of the page cache and hits the assert.

Instrumenting osd_execute_fallocate() on a growing zero range shows the
page left behind, and shows it gone once the old EOF is flushed too:

  before: start=65536 end=69632 old_size=49999 new_size=69632 rc=0
          dirty_tag=1 nrpages=1
  after:  start=65536 end=69632 old_size=49999 new_size=69632 rc=0
          dirty_tag=0 nrpages=0

A crash dump agrees: the asserting page is a page cache page (mapping
set, private_2 clear) at the offset the write covers, PG_dirty and
PG_private set but PG_uptodate clear, while its sole buffer_head is
Uptodate|Dirty|Mapped - the state ldiskfs_block_zero_page_range()
leaves, since it reads the block in and dirties the buffer but never
marks the folio uptodate.  It was the only dirty page in the mapping,
no punch was in flight, and neither the fallocate nor writeback had
reported an error.

Flush the partial page at the old EOF when the fallocate grew the file.
osd_partial_page_flush() already skips the case where the old EOF was
block aligned and ldiskfs had nothing to zero.

The other edge ldiskfs zeroes, at epos - 1, is inside [start, end) and
is already covered.

No separate test is required as fsx in sanityn hits this pretty
reliably and a synthetic test seems complicated due to a relative
small window.
