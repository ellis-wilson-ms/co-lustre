LU-20716 tests: use "-t lustre" for servers before 2.17.58

Since "LU-12514 tests: add testing for lustre_tgt type" mount_facet()
starts servers with $MOUNT_TGT ("mount -t lustre_tgt").  Releases
before 2.17.58 never install /sbin/mount.lustre_tgt (the RPM only
lists it as %ghost), and in interop sessions the servers run their own
installed test-framework via rpc.sh, so the mount.lustre_tgt symlink
that load_modules_local() creates only ever appears on the client.
Without a helper mount(8) falls through to mount(2) with fstype
"lustre_tgt" and no "device=" option, which the kernel rejects:

  LustreError: Can't find device name (need mount option 'device=...')
  LustreError: (obd_mount.c:1637:lmd_parse()) Bad mount options
  LustreError: (tgt_mount.c:2627:lustre_tgt_fill_super()) Unable to
               mount  (-22)

so every interop session against 2.17.0 servers has failed in
lustre-initialization since that patch landed.

Fall back to $MOUNT_CMD in get_lustre_env() when the MGS, MDS or OSS
is older than v2_17_57-80-g58adf0b4aaf, the first build that installs
mount.lustre_tgt, right after the server versions are collected, so
both mount_facet() and the tests that call $MOUNT_TGT directly mount
with "-t lustre" on those servers.
