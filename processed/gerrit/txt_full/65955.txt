--- Commit Message ---
LU-20099 nrs: enforce both reserved and limit rates for mClock

Add the limit rate to mClock. A second red-black tree sorts the class
buckets by limit deadline. The plain "rate", "iops" and "bps" keys now
set the limit rate, so a rule means the same under TBF.

The reserved deadline stays at most NRS_MCLOCK_RESVD_LAG_MAX (1 s)
behind the current time. Without that bound, a rule that reserves more
than the device gives takes the reserved tree after an idle period.
The bound also lets a starved class pass its limit inside one second.
The limit is a long-run bound, not a per-second cap.

A dimension key on the policy start command replaces the default set.
"start mclock projid limit=1" has no reservation. A start that turns
off every dimension returns -EINVAL.

Add sanityn/test_77v{f,g,m,r}.
