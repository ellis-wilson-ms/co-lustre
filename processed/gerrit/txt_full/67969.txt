--- Commit Message ---
LU-18298 pcc: recover a PCC file handle degraded at open

A file descriptor that misses the PCC cache at open never uses PCC
again: the read, write and splice paths bail out on a NULL pccf_file,
and only pcc_file_release() resets it. Any layout blocking AST makes
pcc_try_auto_attach() decline at PIT_OPEN, and for PCC-RW the write
that follows restores the released file and detaches the cache:
sanity-pcc test_1c/1d "expected <pcc copy> size: 7654321 got: 0".

Open the copy on the first read, write or splice instead, once
something else has attached the inode; refreshing the layout at open
deadlocks the copytool against its own restore, measured.
pccf_mmap_fallback bars a descriptor holding a Lustre VMA; encrypted
files stay out, as splice would hand back undecrypted pages. New
test_1h covers it.
