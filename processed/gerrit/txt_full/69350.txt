LU-12669 ec: create lock placeholder for reconstructed pages

Pages that CIT_EC_RD reconstructs from parity for a stripe on an
unavailable OST are not covered by a DLM lock, so their Uptodate bit
is dropped after each read, and every later read rebuilds them from
parity again.

Grant a client-only LDLM_FL_PLACEHOLDER ldlm_lock over the whole
stripe object locally, without an RPC, and keep the reconstructed
pages Uptodate under it.  A stripe gets a placeholder when its target
is inactive, or when its sub-lock enqueue fails.  If the conversion
fails, drop the pages after the read as before.  Add
cl_lock_operations::clo_to_placeholder() and
ldlm_cli_enqueue_placeholder() for this.

The pages stay valid while the parity they were rebuilt from is not
STALE.  Any write or truncate of the file must stale the parity with
a layout write intent first, which revokes the layout lock on every
client.  When a client loses the layout lock, cancel the placeholder
locks of the file with LCF_PLACEHOLDER, which discards their pages
under the page lock as a server lock cancel does, and cancel one that
a read creates meanwhile once that read is done.  Fast reads from
the page cache already wait for the next IO to refresh the layout,
so make the mmap fast fault do the same.  So the placeholder needs no
server state: it is neither replayed nor dropped before a lock
replay, is only matched by page coverage tests, does not hold up the
KMS, and otherwise leaves the cache through the LRU like any unused
lock.  Only PR locks are converted, since a PW placeholder could
satisfy a later write without a server lock.

Also cancel initialized sub-locks on the lov_lock_sub_init() error
path, and in lov_lock_cancel() when the sub-lock env is not found, so
a placeholder reference is not leaked, and free the lov_lock with the
size it was allocated with.  Drop lov_lock_sub::sub_initialized, as
every sub-lock is now initialized.

Add sanity-ec test_49f to check that a second degraded read sends no
read RPCs, that the placeholder survives OST recovery, and that the
cached pages do not hide a later write from another client from
either read() or an existing mmap.
