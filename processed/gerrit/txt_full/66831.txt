LU-20365 tests: sorted_readdir to replace 'du -a' in test_123h

Replace 'du -a' with sorted_readdir to trigger fname pattern statahead
in sanity.sh test_123h.

In Ubuntu 26.04, the gnulib update has changed. It no longer sorts the
outputs following the file traversal (fts_open context) for Lustre,
(coreutils (9.7-3ubuntu2) resolute). This also changes the behavior
of `du -a` (gnudu) as it no longer guarantees a sorted directory list.

This behavioral change breaks the expected access pattern required by
sanity.sh test_123h. Because it relies on the sorted order to properly
trigger the fname pattern statahead mechanism.  Without sorted entries
statahead cannot detect the fname pattern and the test fails.

To address this compatibility issue, introduce a new simple utility
`sorted_readdir.c` which sorts directory entries by the trailing
decimal field of each name.
For f123h.sanity.{0..10000} this yields the sequence
(0, 1, 2, ... 10000) that the fname pattern statahead mechanism in
sa_pattern_fname_detect() requires(num == lli_sa_fname_index + 1).
This ensures the directory entries are presented in the deterministic
order expected by the test, restoring fname pattern statahead and
allowing test_123h to pass consistently with different distributions.
