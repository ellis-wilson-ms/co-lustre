LU-19900 lov: split DIO appends at stripe boundaries

An O_DIRECT|O_APPEND write that crosses a stripe or PFL
component boundary is written entirely to the object of the
stripe it started in.  lov_dio_submit() sends a cl_dio_pages
array to the sub-object of its first page, and unlike other
IO an append is not split per stripe by
lov_io_rw_iter_init(), since its offset is only known once
the lock is held.  The data lands at the wrong offset, and
bytes past the component end are not counted in the file
size or fail with -ENODATA.

Add a cl_object coo_dio_max_bytes() method, called before
the user pages are pinned, and have lov limit each DIO page
array of an append to one stripe chunk.  ll_direct_IO()
submits the rest of the write in further page arrays, so
the append stays in one cl_io_loop() iteration under one
lock, and is written atomically at the end of the file.
Reset the lov DIO stripe cache for each page array, since
it assumed the whole IO iteration is in one stripe.  Share
the stripe chunk calculation with lov_io_rw_iter_init().

Add sanity-pfl/300 for a DIO append across a PFL component
end and across a stripe boundary, and sanityn/300 for
concurrent appends from two mounts.
