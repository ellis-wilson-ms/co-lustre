LU-20505 osd: add fail_loc to suppress all on-disk FIDs

sanity-lfsck test_5 is meant to verify that LFSCK can upgrade objects
that have no on-disk FID, as found on a filesystem upgraded from
Lustre 1.8.  It emulates such objects with OBD_FAIL_FID_IGIF (0x1504),
which suppresses FID-in-dirent and linkEA but leaves trusted.lma in
place.  LFSCK reads the normal FID back from the LMA and repairs
FID-in-dirent with it, so lu_igif_build() is never called and the IGIF
upgrade path is not actually tested.

Add OBD_FAIL_FID_IGIF_ALL (0x1508), which also suppresses trusted.lma,
leaving the object with no on-disk FID at all.

The new fail_loc must not be used when creating a directory.  The OI
still maps such a directory's normal FID to its inode, while a lookup
by name synthesises an IGIF FID instead, and any later create inside
that directory fails.  lfsck_prep() therefore uses 0x1508 for files
only, and keeps 0x1504 for directories.

OBD_FAIL_FID_IGIF keeps its existing meaning, so test_1c and
lfsck-performance.sh need no change.
