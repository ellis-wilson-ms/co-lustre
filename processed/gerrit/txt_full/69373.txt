LU-20815 mdt: return lookup lock on symlink open

An open of a symlink without MDS_OPEN_LOCK, which is the default
until a file reaches opencache_threshold_count opens, does not
return any lock to the client, so the symlink dentry is never
revalidated and every open of the same symlink sends an open intent
RPC to the MDS.

Try LOOKUP|UPDATE|PERM ibits in PR mode for symlink on open and
return the lock to the client, so repeated open of the symlink
can be resolved on the client side.

This also changes an open of a symlink with MDS_OPEN_LOCK, as with
opencache_threshold_count=1 or NFS export: the MDS used to grant a
blocking LOOKUP|OPEN lock on the symlink, and it now tries the same
LOOKUP|UPDATE|PERM lock in PR mode instead, without the OPEN bit,
since there is no open handle for a symlink.

Add sanity test_17r, which checks that with the open cache off,
opens through a symlink send no more enqueue RPCs than direct opens
of the target.
