--- Commit Message ---
LU-20210 utils: add nodemap RBAC roles to rustreapi

Bind the C `enum nodemap_rbac_roles` from `lustre_idl.h` as a
rustified bindgen enum in `lustreapi-sys`, exporting it for external
tools.  NB the sys enum is a constant carrier only: real rbac values
are OR'd masks that are not enum variants, so it must never be
constructed from a raw mask - `RbacRole` is the mask-safe type.

Add a new `rustreapi::nodemap` module with an `RbacRole` bitmask
type that mirrors the C enum's single-bit flags.  The
`From<nodemap_rbac_roles>` impl uses an exhaustive `match` over the
sys enum so that a new variant added to the C side fails to compile
here until a corresponding `RbacRole` variant is added.

`RbacRole::from_mask()` converts a raw `nmf_rbac` mask, normalizing
the `NODEMAP_RBAC_ALL` and `NODEMAP_RBAC_NONE` sentinels and dropping
bits from roles this build's headers do not know.  `from_bits()`
rejects both sentinels, so it cannot be used for that.

Variant names are chosen so their snake-case form (`HsmOps` =>
`hsm_ops`, `IgnoreRootPrjquota` => `ignore_root_prjquota`) matches
the kernel's user-facing names.  Serde serializes a set of roles as
a comma-separated string of those names (e.g. "file_perms,hsm_ops"),
matching the wire format used by lctl.  Unknown role tokens are
skipped on input so a reader built against older headers can still
parse the roles it knows from a newer server's list.
