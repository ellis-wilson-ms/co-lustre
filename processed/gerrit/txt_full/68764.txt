LU-20724 tests: add fsx option to drop client caches

-f only calls msync(MS_INVALIDATE), which leaves the DLM
locks in place, so the client still serves reads from
cache.

Add -Q P: a 1 in P chance per operation of syncfs() plus
writing "clear" to ldlm.namespaces.*.lru_size, cancelling
the unused locks and discarding the pages they covered.
Only client (osc and mdc) namespaces have an LRU to clear.
The sync is required: clearing the lru does not reliably
drop the cache with dirty pages still around.

A drop takes one mountpoint and a random subset of its
namespaces, leaving the rest of the cache to go stale
rather than making every mountpoint consistent at once.
The namespaces of a mountpoint are the ones named for its
client instance, so they are resolved once per path and
kept.

Clearing the lru needs root, so prove it works before
running any operations, and fail the run if it stops
working later, rather than finishing a run that never
dropped a cache.  The draws in test() only run when -Q is
given, so a seed replays the same without it, and they do
run while a -b replay is still simulating even though the
drop itself does not, so the replay follows the same
stream of random values.

Drops are logged to the oplog so logdump() shows them.
Take the operation number in that dump from the log entry
rather than counting entries.  That was already wrong
before this: a selected op that does no work returns from
test() without logging anything, so the count had drifted
from testcalls, which is what -b replays and what gendata()
stamps into the data.

Add -Q to sanityn test_16l.  Hoist the getopt option
string into a variable to keep it under 80 columns.
