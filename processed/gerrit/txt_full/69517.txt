LU-20690 llite: implement STRIPE I/O scope

In the RAID10-like EC parity layout the p stripes of a raidset share
one file offset but hold different data, so read and write must name
one of them. Implement LL_IO_SCOPE_STRIPE for that.

ll_io_scope_validate() accepts STRIPE with ios_mirror_id in
[1, MIRROR_ID_MAX] and ios_stripe_idx below
LOV_EC_MAX_CODING_STRIPES. ios_stripe_idx must be 0 for FILE and
MIRROR. It is not checked against p here: the scope outlives the
layout and the I/O type is not known yet. ll_io_scope_init() handles
STRIPE like MIRROR and, for STRIPE, copies ios_stripe_idx into
cl_io::ci_designated_stripe and sets ci_designated_stripe_set.
OBJECT stays reserved.

ci_designated_stripe is an unsigned index. 0 is a valid stripe, so
ci_designated_stripe_set says whether it is in use. A zeroed cl_io
is unset. vvp_env_new_io() and osc_env_new_io() still memset() the
reused cl_io. The index is meaningful only with ci_designated_mirror
set.

lov visits only the stripes an I/O touches through
lov_foreach_io_stripe(), and maps an offset to a stripe through
lov_io_stripe_number(). On a parity component, read and write use
only the designated stripe of each raidset and fail with -EINVAL if
it is unset or not less than p. Punch, truncate, fallocate and lseek
reach every stripe and ignore the index, so a leftover STRIPE scope
does not fail them. Page fault is rejected on a parity component.

These helpers apply only to the bare LOV_PATTERN_PARITY encoding.
Current RAID0|PARITY parity components are unaffected, so existing
layouts see no functional change.

llapi_io_scope_set(3) and the uapi comment document STRIPE.
sanity-flr test_213a checks the ioctl limits for FILE, MIRROR and
STRIPE, that OBJECT stays reserved, that mirror resync still goes
through the SET_MIRROR alias, and that a STRIPE read of a non-parity
mirror ignores the index. sanity-ec test_311 checks that lseek,
truncate and fallocate succeed for any index, and skips below 6
OSTs. io_scope gains -x, -r, -t, -f and -l for that.
