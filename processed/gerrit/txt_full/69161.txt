--- Commit Message ---
LU-20818 osc: build RPCs on a dedicated unbound workqueue

Since RPC building moved from ptlrpcd to the system workqueue,
every OSC's writeback work is queued on the submitting CPU and
runs there one after another, CPU-bound work being serialized
on a per-CPU pool.  A single thread's IO to a striped file is
built on one CPU, including the user copy of unaligned (and so
hybrid) DIO writes, which now caps at one core's copy rate.
The LRU work moved with it and has the same problem.  The
system workqueue also has no rescuer, though writeback and LRU
shrinking may be needed to reclaim memory.

Queue the writeback and LRU work on an unbound, memory reclaim
workqueue of its own, so the OSCs run it in parallel.  The
workqueue is visible in sysfs as osc_brw, for its CPU mask and
affinity scope.
