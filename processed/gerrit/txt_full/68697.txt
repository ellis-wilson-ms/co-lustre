--- Commit Message ---
LU-19548 mdd: refuse to split a parity mirror to a victim

A file whose layout holds only an EC parity mirror cannot be read:
parity is not file data, and there is no data mirror left to serve
reads. lfs already refuses to split a parity mirror into a file of
its own; the MDS should not rely on the client for that. Pass whether
a victim object exists (mrd_obj != NULL) into mdd_split_ea() and
return -EINVAL when the target is a parity mirror. Destroying a parity
mirror with 'lfs mirror delete' is unaffected.

lfs no longer takes the old-MDS volatile fallback for a parity
target. An MDS that knows what a parity mirror is also has the
fd == fdv purge path (LU-14521), and with the preceding LU-18466 fix
that path no longer fails with -EINVAL, so the fallback could only
build a volatile victim that the MDS now refuses. A client old enough
to always route 'lfs mirror delete' through a volatile file cannot
delete a parity mirror against this MDS.
