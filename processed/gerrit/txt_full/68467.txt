LU-20663 rustreapi: write the stripe pattern through the union

LU-16518 moved lsp_stripe_pattern of struct llapi_stripe_param into
an anonymous union with a new lsp_hash_type.  bindgen emits that as
__bindgen_anon_1, so rustreapi no longer compiles once the installed
lustre-devel headers catch up to master.

Do not gate this on the Lustre version.  lu-version derives the
LUSTRE_2_* features from "lfs --version", i.e. the installed tools,
while the union is a property of the header bindgen parses; the two
need not agree.  They already disagree in the build containers,
which report 2.17.53 and so get LUSTRE_2_18 from the patch >= 50
rule, yet ship a header with no union.

Probe the generated bindings instead, keying on lsp_hash_type: that
name is absent from headers predating the change, and unlike the
positional __bindgen_anon_N it does not shift if another anonymous
member is added later.  Match the bare identifier, since bindgen
falls back to unformatted token text when rustfmt is unavailable.

For the same reason the setter takes a plain u32 rather than the
bindgen type.  Pre-2.17 headers have no enum lov_pattern at all and
declare the field int, so naming a header-derived type in the
signature would not build against them.

Drop the rerun-if-changed on src/bindings.rs.  Bindings go to
$OUT_DIR, so that path never existed and cargo marked the unit stale
on every build, which is the only reason nothing was ever replayed
from cache.  Declare the parsed headers instead, so a header upgrade
invalidates has_lsp_union rather than reusing it.

The lfs binary and PATH are declared in lu_version::export_features()
rather than here, since every caller derives its features from that
same untracked shell-out.  They have to agree: each crate gates on
its own computed features, so a skew between two of them compiles a
call whose declaration was gated out.

Tested with cargo check against 2.15.8, 2.16.1, 2.17.0 and 2.17.52
installed headers, and against the in-tree headers for the union
arm, with and without rustfmt available.
