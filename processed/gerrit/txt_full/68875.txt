--- Commit Message ---
LU-20700 lmv: fix use-after-free in lmv_disconnect_mdc()

lmv_disconnect_mdc() and the error path of lmv_connect()
clear the mdc obd's obd_upcall (onu_owner/onu_upcall) after calling
obd_disconnect(), dereferencing the export stored in tgt->ltd_exp.

obd_disconnect() calls class_export_put() to drop the reference.
When reference reaches zero the export is queued
on the zombie list and freed asynchronously.
It may be freed before any consequent operation,
So touching tgt->ltd_exp after obd_disconnect()
may trigger a use-after-free case.

sanity-sec test_27e (read-only filesets) walks this path repeatedly,
and has more chance to trigger this BUG.

Clear the upcall before obd_disconnect(), while the export is still
referenced, And report a disconnect error via the mdc obd fetched at
the top of the function instead of dereferencing the export again.
The error path in lmv_check_connect() needs the same ordering,
and it also now clears tgt->ltd_exp so that a second pass
cannot disconnect the same target twice.
