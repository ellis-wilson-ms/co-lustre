--- Commit Message ---
LU-17000 lnet: fix use-after-free on NI alloc failure

lnet_ni_alloc_common() links the new NI onto net->net_ni_added and
can then still fail; the CPT setup in lnet_ni_alloc() and
lnet_ni_alloc_w_cpt_array() also fails after that point.  All three
error paths call lnet_ni_free(), which never removed the NI from
the net list, so the following lnet_net_free() walked net_ni_added
and dereferenced freed memory.  A CPT expression naming more values
than the node has CPTs, e.g. "tcp(eth0)[0,0]" with one CPT, reaches
this with no allocation failure at all.

Unlink the NI in lnet_ni_free() itself.  ni_netlist is initialised
in lnet_ni_alloc_common() before any failure path and every other
caller already unlinks first, so the added list_del_init() is a
no-op for them.
