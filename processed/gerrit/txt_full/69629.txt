LU-20909 tests: fit sanity/42e to small OSTs and large pages

sanity test_42e first writes max_dirty_mb to OST0000 and then dirties
another max_dirty_mb there, before writing 16-page files.  On small
test OSTs that already hold data from earlier subtests, the client
runs out of grant and falls back to sync single-page writes, failing
with "less than 16-pages write RPCs 39% > 15%".  With PAGE_SIZE 16KiB
each 16-page file is also 4x the size, which makes this much likelier.

The measured loop also continued the warmup loop's index, starting at
OSTCOUNT * max_dirty_mb, so the number of files written depended on
the client RAM, and was zero with 4GiB or more of RAM, where the
subtest passed without checking anything.

Limit max_dirty_mb to a quarter of the OST0000 free space for the
subtest, scale the number of files by 4096 / PAGE_SIZE so about 31MiB
is written to OST0000 for any page size, start the measured loop at
0, and fail if no file landed on OST0000.

With 40MiB already on a 400MiB OST0000, 16KiB-page aarch64 client:
2/2 failed before (39%, 69% of RPCs under 16 pages), 4/4 pass after
with no RPC under 16 pages; 4KiB-page x86_64 client: 2/2 pass.
