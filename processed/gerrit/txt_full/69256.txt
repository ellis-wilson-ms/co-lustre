LU-20808 osp: carry a lock intent on a remote lock enqueue

Add struct md_lock_intent and ldlm_enqueue_info::ei_intent, through
which a caller can attach an IT_MDT_TO_MDT_READ to a remote lock
request: the MDT that owns the object reads back what the intent asks
for while it grants the lock, and sends it in the same reply.

When ei_intent is set and the peer advertises
OBD_CONNECT2_DNE_INTENT, osp_md_object_lock() packs what the intent
asks for into the enqueue as OUT reads of the locked object: an
OUT_INDEX_LOOKUP of the name, an OUT_ATTR_GET, and an OUT_XATTR_GET
for each xattr, in that order, with room in the reply for their
results. The xattr values share the room the caller asks for.

On return it puts the name's resolution in the intent and sets
mli_replied, but only when the owning MDT says with DISP_IT_EXECD
that it ran the intent, and every result is within the reply. The MDT
does not run it when the lock was not free at once and was granted
the ordinary way, nor for a resend. A peer that does not support
intents gets a plain enqueue, and so does an intent that cannot be
packed, so a caller must always be ready to read what it needs
itself.

OSP names the object to read in the request itself, from the lock
resource, which is what the owning MDT checks it against: a caller
cannot name a different object than the one it locks.
