--- Commit Message ---
LU-20090 nrs: use allowed types for class bucket lookup

A rule match walks every rule of the class head. The cost grows with
the rule count.

The dynamic classifier now builds a request key for each allowed type
and finds the class bucket by hash. The module parameter
tbf_dyn_rule_thresh (default 8 rules) starts the hash path.

The default rule takes the union of the allowed types. A "change
default rate=N" command then gives N RPC/s to each live tuple of that
union. The rate no longer applies to each NID.

When the start command has a free allowed type entry, it adds the
policy type to the list. Otherwise it returns -E2BIG.

Fix the cleanup of test_77k, test_77kh and test_77ki.

Add sanityn/test_77t{d,f} and the -E2BIG case of test_77tc.
