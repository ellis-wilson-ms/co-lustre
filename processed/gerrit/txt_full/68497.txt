LU-17000 lnet: print in6_addr with %pI6c, not %pIS

ksocknal_inet6addr_event() and kiblnd_inet6addr_event() log
&ifa6->addr, a bare struct in6_addr, with %pIS.  That specifier expects
a struct sockaddr: the kernel reads sa_family out of the first two
bytes of the address and then formats the rest as a sockaddr_in or
sockaddr_in6.  Adding addresses to an interface on a node with a tcp NI
shows what that produces:

  address          %pISc (before)      %pI6c (after)
  2001:db8::1      (einval)            2001:db8::1
  fe80::dead:1     (einval)            fe80::dead:1
  200::1           0.0.0.0             200::1
  a00::1           ::1:4000:0:0:0      a00::1

The first two have leading bytes that name no address family.  200::1
begins 02 00, which reads back as AF_INET, so sin_addr is taken from
bytes 4..7 of the address.  a00::1 begins 0a 00, which reads back as
AF_INET6, and sin6_addr sits 8 bytes into a sockaddr_in6 - so the
kernel formats bytes 8..23 of a 16-byte object.  The 4000 in that
output is inet6_ifaddr.prefix_len (64), read 8 bytes past the end of
the in6_addr, and %pISc goes on to read sin6_scope_id past that.

Use %pI6c.  There is no sockaddr to hand to %pIS instead: an
inet6addr notifier is passed a struct inet6_ifaddr, which carries an
in6_addr with no family, no port and no scope.
