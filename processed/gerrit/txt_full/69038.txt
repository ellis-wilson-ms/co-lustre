LU-20768 bxi3lnd: Introduce Bull BXIv3 Lustre network driver

This commit introduces a new LND for Bull's BXIv3 NIC.

The current implementation does not integrate well with all tools,
there is some work remaining to have a proper integration with
lnetctl, but it has sufficient support to be able to initialize
network interfaces.

In addition to the mandatory lnd tunables for credits & timeouts the
BXIv3 LND adds tunables that allow to:
 - manage the amount of memory used (with `imm_rx_buffer_size`,
   `imm_rx_buffer_count`, `rdv_data_eq_size` and `rx_eq_size`). Note
   that EQs require device-contiguous memory.
 - `imm_rx_buffer_recovery_min_count` controls the strategy used for
   recovery after resource exhaustions, larger values consume more
   memory, but allow to have less risk of cascading failures
 - `rdv_timeout` controls internal LND timeouts, it must be compatible
   with the LNet timeout
 - `matched_rdv` allows choosing the protocol used for bulk transfers.
   Both sides must use the same protocol.

The default tunables induce a memory footprint of about 1 GiB per NI,
which can grow due to a large inflow of bulk requests.

The LND has not yet been used in production, but it has multiple
injections (`CFS_BXI3_FAIL_*` in the 0xF3XX range) to test edge cases
that are tricky to handle, and have unlikely occurrences. Those
injections have been well tested on our test infrastructure, mostly
using selftests
