LU-14058 tests: fix tests with more than 10 OSTs

Several test scripts open-code the $FSNAME-OSTxxxx target names
with printf, which breaks with more than 10 OSTs configured, and
several tests make other assumptions that fail with many OSTs.

Consistently use ostname_from_index() and ostuuid_from_index() to
generate OST names from an index.

Fix ost-pools.sh add_pool() to sort the expected pool members
together with the existing ones, and sanity-flr.sh check_ost_used()
to do exact OST index matching, so both work with OST index 10+.

Fix sanity/56wc to request no more PFL stripes than LOD allows in a
[1M, 16M) component, which failed with more than 8 OSTs.  Fix
sanity/130a, 130e and 130i to parse the FIEMAP device index as hex,
which failed for OST0008 and higher.  Limit sanity/130g to
LOV_MAX_STRIPE_COUNT stripes, and ost-pools/2c to 8 OSTs in one
pool_add argument, which lctl limits to 80 chars.

Except sanity/51d with more than 12 OSTs, which hits the known
round-robin first-object imbalance (LU-8933).

Test-Parameters: osscount=2 ostcount=12 testlist=ost-pools
