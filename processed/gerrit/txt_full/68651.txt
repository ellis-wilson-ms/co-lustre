LU-19848 compat: add page_pgmap() compatibility

Linux commit v6.14-rc6-302-g82ba975e4c43 ("mm: allow compound zone
device pages") moved the dev_pagemap back-pointer of a ZONE_DEVICE
page out of struct page and into struct folio, and added page_pgmap()
to read it:

	static inline struct dev_pagemap *
	page_pgmap(const struct page *page)
	{
		VM_WARN_ON_ONCE_PAGE(!is_zone_device_page(page), page);
		return page_folio(page)->pgmap;
	}

Add an autoconf probe for it and a fallback in lustre_compat.h so
that callers can use page_pgmap() unconditionally.

The fallback is not a bare page->pgmap. That word is shared with
page->compound_head - which is exactly why the field was moved - and
memmap_init_compound() stores the pgmap into every tail page with
__init_zone_device_page() only to overwrite it on the next line via
prep_compound_tail() -> set_compound_head(). A tail page of a compound
ZONE_DEVICE folio therefore reads back head|1 rather than the pagemap.
Resolving the head page first, which is the same _compound_head() that
page_folio() performs, gives the identical pointer for head and tail
pages alike, so the two sides of the split really do agree:

 - 6.15 and newer: the pgmap recorded on the folio the page belongs to.
 - Older: the pgmap recorded on the head page of that same folio.

On both sides the value is only meaningful once the caller has
established is_zone_device_page(), so the fallback keeps the kernel's
assertion instead of silently reading the union. It spells it
VM_WARN_ON_ONCE() rather than VM_WARN_ON_ONCE_PAGE(): the latter only
appeared in Linux v5.11 (v5.10-11805-ga4055888629b), and
lustre/ChangeLog still lists 5.4 kernels, where an unused static inline
in a header is still parsed and would fail
-Werror=implicit-function-declaration for every file that includes
lustre_compat.h.  The page is cast for the same kind of reason:
compound_head() took a plain struct page * until v5.14
(v5.13-153-g0f2317e34e2c "mm: make compound_head const-preserving"),
and RHEL8's 4.18 predates that.  The cast keeps the kernel's own
accessor - and its hugetlb fake-head handling - rather than open-coding
a compound_head() here; nothing is written through the pointer.

The CONFIG_ZONE_DEVICE=n case is mirrored too - upstream compiles
page_pgmap() to a stub returning NULL there, and is_zone_device_page()
is a hardcoded false, so keeping the assertion would fire on every call
under CONFIG_DEBUG_VM.

Nothing in the tree calls page_pgmap() at this commit. It is groundwork
for the p2pdma patch later in this series, which drops the static inline
lnet_dev_prio_of_md(struct lnet_ni *, unsigned int dev_idx) that lives in
lnet/lnet/lib-move.c today and replaces it with an out-of-line
lnet_dev_prio_of_md(struct lnet_ni *, struct page *) in
lustre_compat/nvfs.c.  That new one is the only page_pgmap() caller.

No CONFIG_PCI_P2PDMA guard is needed either. struct page::pgmap and
struct dev_pagemap are both declared unconditionally rather than under
CONFIG_PCI_P2PDMA, so the fallback compiles on any config. And the new
lnet_dev_prio_of_md() reaches page_pgmap() only behind
is_pci_p2pdma_page(), which is a compile-time false when
CONFIG_PCI_P2PDMA=n, then feeds pci_p2pdma_distance_many(), whose
!CONFIG_PCI_P2PDMA stub returns -1 - so the p2pdma path degrades to
"no p2pdma" with no extra #ifdef.
