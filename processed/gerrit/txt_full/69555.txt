LU-20923 mdt: refuse new objects with non-MDT FIDs

The MDT incorrectly verifies the FID that a client allocates for a
new object, and LOD puts the object on whichever target the FLD maps
the FID sequence to.

Check in mdt_object_new() that the FID of a new object is a normal
FID in a sequence that the FLD maps to an MDT, and otherwise return
-EINVAL and print the MDT, name, FID and client NID.  This covers
mkdir, mknod, symlink, open-create, the directory restripe target
and the HSM release orphan, which all use a client-allocated FID.
Also check the client-allocated target FID of a migration.

Add OBD_FAIL_LMV_FID_SEQ so the client uses fail_val as the high 32
bits of the next FID's sequence, and sanity test_154dc to create
files and directories with an IDIF FID, a reserved FID and a FID in
a sequence range that the FLDB maps to an OST.

Add fail_loc.4, fail_val.4 and fail_err.4 man pages.
