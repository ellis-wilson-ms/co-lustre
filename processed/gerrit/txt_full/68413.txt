LU-20647 mdd: look up a changelog user of either record type

Accept CHANGELOG_USER_REC as well as CHANGELOG_USER_REC2 in
mdd_changelog_user_lookup_cb(), keeping the rec2-only fields behind a
type test.

mdd_changelog_user_register() writes the plain record when the caller
gave neither a mask nor a name, deliberately, for compatibility.  The
callback matched rec2 only, so such a user was never found and
mdd_changelog_user_lookup() returned -ENOENT.  That is the shipped
"lfs changelog --user", which reaches the callback through
OBD_IOC_CHANGELOG_FILTER, not only the library call.  Every other MDD
walker already takes both types and guards the fields that exist in
only one of them, so the callback was alone in rejecting the record
rather than the field.

The type test cannot simply be dropped.  struct
llog_changelog_user_rec is half the size of rec2 and carries neither
cur_mask nor cur_name, so a name compare on a plain record would read
past the end of it into whatever the llog buffer holds next.  A lookup
by ID now matches on cur_id alone, a lookup by name skips a plain
record, and the reply's username is filled only from a rec2 -- chosen
by the record's type, not by how the lookup was made, because
mdd_iocontrol() passes one buffer as both request and reply.  The
compare is bounded for the reason mdd_changelog_name_check_cb()
already bounds the same field: cur_name comes off disk with no
guarantee of a NUL inside its 16 bytes.

Only the cf_user_id != 0 path changes behaviour: the old callback
rejected a plain record in the first clause of its ||, before strcmp()
ran, so a lookup by name walked past one before this patch as it does
after it.  The client parses "cl<N>" into an ID, so the ID path is the
one lfs takes.

test_160y registers one user plainly, one with a mask and one with a
name, and asks for the records of each; the masked user is the control
that has always worked.  test_160w covers this command already but
registers both its users with a name and a mask, so both records are
rec2 and the plain path was never walked.

This wants LU-20648 beside it.  Making a plain user reachable makes
cf_mask == 0 the ordinary answer, and a client without that fix
composes in.cf_mask & 0 and reads the zero as "do not filter": so
"lfs changelog --user cl1 --mask creat" on a plain user would print
every record type where it used to stop at -ENOENT.  Landing this one
alone trades a lookup failure for a wrong answer.
