LU-17000 obdclass: fix inconsistent NULL handling

stats_free(), checksum_type_show() and checksum_type_store() test a
pointer obtained from container_of() for NULL; container_of() cannot
return NULL.  stats_free()'s companion ls_num test is dead as well -
lprocfs_stats_alloc() returns NULL for num == 0 and is the only place
ls_num is assigned - and is the more harmful of the two, since it
would skip the final LIBCFS_FREE() and leak the structure.  Drop them.

class_config_llog_handler() dereferences its config_llog_instance from
the first record it looks at, but tests it for NULL again when adding
the net information to a setup record.  Both callers of
class_config_parse_llog() pass an instance.  Drop the test.

llog_osd_open() frees handle->lgh_name at out_name using strlen(name),
although out_name is also reached from paths where the llog was opened
by logid and name is NULL - it only survives because OBD_FREE()
evaluates its size argument under a NULL check.  Use the length of the
string being freed, as llog_osd_close() does.

Reported by smatch as "can 'stats'/'obd' even be NULL?", "variable
dereferenced before check 'cfg'" and "we previously assumed 'name'
could be null".
