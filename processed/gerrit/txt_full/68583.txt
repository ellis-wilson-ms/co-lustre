LU-20680 socklnd: order delayed receive state publication

lnet_parse() may call ksocknal_recv() asynchronously while
ksocknal_process_receive() waits for it to publish the receive tuple.

ksocknal_recv() initializes ksnc_lnet_msg, ksnc_rx_nob_left,
ksnc_rx_discard, and ksnc_rx_to before changing ksnc_rx_state to
SOCKNAL_RX_LNET_PAYLOAD.  However, the scheduler reads ksnc_rx_state
without holding kss_lock.

On weakly ordered CPUs, the scheduler can observe
SOCKNAL_RX_LNET_PAYLOAD before the associated receive tuple is visible.
Since an empty iov_iter is valid, it treats the payload as already
received and skips ksocknal_receive().  It then finalizes the NULL
message pointer on the first message, or the stale already-finalized
message pointer on a subsequent message.  ksocknal_new_packet() then
starts reading a Ksock header from payload bytes which remain unread in
the socket.

Publish SOCKNAL_RX_LNET_PAYLOAD with release semantics and consume it
with acquire semantics.  This ensures that observing the payload state
also makes the complete receive tuple visible to the scheduler.
