--- Commit Message ---
LU-20810 lnet: fix peer discovery memory leak

Some concurrent call sites for peer discovery could still enqueue
a peer into the `ln_dc_request` queue after
`lnet_peer_discovery_stop()` has already drained and asserted the
discovery queue is empty. This can cause an extra reference taken by
`lnet_peer_queue_for_discovery()` to never be released, leading to
an `lnet_peer` leak, and an attached `lnet_ping_buffer` leak as well
if push data had already been received, ultimately being reported
as "Portals memory leaked" at module unload.

The fix is to re-check `ln_dc_state == LNET_DC_STATE_RUNNING` within
the same `lnet_net_lock/EX` critical section where the actual
insertion operation is performed.
