Add autoconf probes and compat shims for nine kernel 7.0 API changes:
- in_irq() removed; use in_hardirq() (available since 5.14)
- kernel_bind/kernel_connect take struct sockaddr_unsized *
- vfs_mkdir() gains delegated_inode *, now returns dentry *

- generic_drop_inode() renamed to inode_generic_drop()
- posix_acl_to_xattr() now allocates its own buffer
- ilookup5_nowait() gains bool *isnew fifth argument
- inode->i_state is now inode_state_flags; read via inode_state_read()
- page->flags is now memdesc_flags_t; use page_flags_value/page_flags_ptr

## Explanation of the Fix

### The Problem
The patch introduced a compatibility shim for `struct sockaddr_unsized`, which was added in kernel 7.0 for `kernel_bind()` and `kernel_connect()`:

```c
#ifndef HAVE_SOCKADDR_UNSIZED
#define sockaddr_unsized sockaddr
#endif
```

However, the code unconditionally cast pointers to `struct sockaddr_unsized *`. This caused a type mismatch:

1. **On kernels without `sockaddr_unsized`** (< 7.0): The macro makes `sockaddr_unsized` equivalent to `sockaddr`, but the cast `(struct sockaddr_unsized *)` expands to `(struct sockaddr *)`, which should work.

2. **The actual issue**: The compiler sees the macro expansion happening, but the kernel headers declare `kernel_bind()` and `kernel_connect()` as taking `struct sockaddr *`. The cast to `struct sockaddr_unsized *` (even when it's aliased) creates a pointer type mismatch that triggers `-Werror=incompatible-pointer-types`.

### The Solution
The fix removes the casts to `struct sockaddr_unsized *` and uses the original `struct sockaddr *` casts. This works because:

1. **On kernel 7.0+** (with `HAVE_SOCKADDR_UNSIZED`): The compatibility header `include/lustre_compat/net/sock.h` defines the alias, and `struct sockaddr *` will be implicitly compatible.

2. **On older kernels** (without `sockaddr_unsized`): The functions already expect `struct sockaddr *`, so the cast is correct.

### Changed Files
- `lnet/lnet/lib-socket.c`: Fixed two casts in `kernel_bind()` and `kernel_connect()` calls
- `lustre/ptlrpc/gss/gss_svc_upcall.c`: Fixed one cast in `kernel_connect()` call

### Rationale
The compatibility shim approach is correct (aliasing `sockaddr_unsized` to `sockaddr` when not available), but the code should use the base type `struct sockaddr *` in casts to maintain compatibility across both old and new kernels without triggering type warnings.
