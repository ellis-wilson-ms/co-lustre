LU-17292 clio: send a page cleaned under writeback instead of LBUG

cl_page_make_ready() LBUGs the client when a write page is no longer
dirty yet still CPS_CACHED: a racing lock-cancel discard (osc_discard_cb,
whose discard phase runs after the flush) cleared the page's dirty bit
out from under a forming writeback extent. The page is still uptodate, so
just send it rather than crash - writing its valid data preserves data
the discard would otherwise have lost, and a truncate drops it server-
side later; conflicts flush rather than discard, so no lost update.

Handle only that specific state (clean CPS_CACHED). Any other unexpected
state reaching write make_ready - OWNED, PAGEIN, FREEING, or invalid - is
still a genuine bug and keeps the LBUG.

Add OBD_FAIL_OSC_MAKE_READY_DISCARD (0x41b): clean a page just before
cl_page_make_ready() to reproduce the race deterministically, and sanity
test_914 which verifies no LBUG and no data loss.
