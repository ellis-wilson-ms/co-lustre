--- Commit Message ---
LU-20354 quota: cache per-slave DT usage on QMT

Build an in-memory per-slave DT usage cache on the global
pool lqe so QMT can track block usage reported by slaves.
Named pools do not keep their own slots; qmt_sum_lqe_usg()
sums the global entries for the pool's current sarr members.
LQA and MD are not cached. Refresh from MDT/OSP and serving
the sum on GETQUOTA stay in a follow-on.

DQACQ and REL piggyback on-disk usage in qb_usage with
QUOTA_DQACQ_FL_USAGE, set by qsd_qbody_set_usage(). REPORT
already carries that usage and is left unchanged. qmt_dqacq0()
drops the lqe write lock, then qmt_update_lqe_usg_entry()
stores the value on the global lqe. A missing slot is
created there. The slot stores the update time; a ttl of 0
always misses.

The sum holds op_rw_sem (read) across each member array.
Slot fields are written with WRITE_ONCE and read with
READ_ONCE, with no second lock. Callers must not hold
lqe_sem: the recalc thread takes op_rw_sem and then
lqe_sem, so the other order deadlocks with a queued pool
writer. A missing or expired member, or a pool with no
members, returns -ESTALE. An all-zero fresh sum is a valid
idle ID.

DOM MDTs are recorded only in the global DT pool tgts[MDT]
and stay out of lgd and recalc. A slave connect adds the
target once; disconnect does not remove it.

qmt.*.usage_cache_ttl is in seconds (default 3600, max one
day). Zero makes every lookup miss. The cache is freed
with the lqe.

qmt_usg_test covers update and sum by pool sarr, a named
pool sharing the global cache, and TTL. sanity-quota/305
loads it on the MDS. It does not exercise MDT/OSP refresh.
