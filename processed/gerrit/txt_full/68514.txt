LU-17000 osd-ldiskfs: widen quota block offsets before shifting

The quota tree walker turns a block number into a file offset with
"blk << LUSTRE_DQBLKSIZE_BITS".  blk is an unsigned int read straight
off disk with le32_to_cpu(), so the shift is evaluated in 32 bits and
wraps for any block at or past 4 GiB into the quota file, and the
truncated value is then widened to the loff_t it is stored in.

Cast blk to loff_t before shifting.  Only the quota_read() offset in
quota_read_blk() has an observable effect today: a wrapped offset there
reads a different, live block of the quota file.  The other two sites
are corrected for consistency but cannot be seen - osd_it_quota::
oiq_offset has had no readers since 8fdb46e476 ("LU-6617 quota: remove
quota migration code"), and find_block_dqentry()'s return value is only
tested for its sign by osd_it_acct_get(), which the truncation cannot
change because the 32-bit product is zero-extended.
