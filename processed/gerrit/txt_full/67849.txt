LU-20570 tests: quote yaml.sh error messages for YAML

yml_log_sub_test_end() writes the failure message with

	printf '            error: "%q"\n' "$*"

%q quotes for the shell, but the result is placed inside a
YAML double-quoted scalar, where the only valid escapes are
the ones YAML defines.  The two disagree, so a message can
either break results.yml or be recorded wrong:

 - An apostrophe emits \' , which no YAML parser accepts.
   The file then fails to load in full, so a run reports
   nothing at all.  "Health hasn't recovered" is one such
   message.

 - A message holding a newline or a tab emits bash ANSI-C
   quoting, $'one\ntwo' .  That parses, and the recorded
   value keeps the literal $'...' wrapper.

Write a single-quoted scalar instead.  It takes no backslash
escapes at all, so '' is the only sequence that needs care
and the message cannot introduce syntax.  YAML rejects a raw
control character in any scalar, and a newline or carriage
return would also end the line, so fold every control
character to a space first.

Messages with no such character are unaffected in value:
%q wrote "Out of memory", which decoded to the same string
the single-quoted form now carries directly.

Remove stray em-dash in sanity-hsm that would potentially
turn yaml into incorrect output in default en_US locale.
