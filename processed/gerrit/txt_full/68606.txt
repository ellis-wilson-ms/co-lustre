LU-20687 lustre: use container_of() in downcast accessors

The ~46 inline accessors that cast an lu_device or lu_object (or a cl_,
dt_ or md_ layer of one) to its containing per-module structure are
built on container_of_safe(), which returns NULL and ERR_PTR arguments
unchanged instead of doing the subtraction.  smatch therefore treats
every one of them as an error-pointer producer and reports 439
"dereferencing possible ERR_PTR()" errors and 39 "passing zero to
ERR_CAST" warnings at their call sites.

That pass-through was never a deliberate contract.  The accessors were
mass-converted from the lustre-local container_of0() by 200d442378
("LU-6142 lustre: convert use of container_of0 in include/") and
46f1fc6c1b ("LU-6142 lustre: convert some container_of to *_safe"),
whose messages say the arguments "cannot be determined from local
inspection" to be valid, so the old behaviour was simply preserved.
Code has since been added that exists only to placate it - the IS_ERR()
tests in the llog code from f74ef5903a ("LU-14291 llog: test if
dt_device not an ERR_PTR"), the IS_ERR_OR_NULL() in
lod_comp_prep_create() from c53abca9f9 ("LU-19852 lod: raidset aware
stripe allocator") which this patch removes, and the ones in
mdt_lproc.c from 117be08e58 ("LU-18961 mdt: add safety checks in
MDT_BOOL_RW_ATTR") which the previous patch replaced - while the
identically shaped lov, lovsub and lod_obj() accessors have always used
plain container_of().

Every call site was surveyed.  The offsets were measured on the built
modules rather than read off the structs: 35 of the accessors are at
offset 0, where this is a no-op because container_of() yields the same
value as container_of_safe() for NULL and ERR_PTR arguments too.  The 11
at a non-zero offset were checked individually, and none of them can be
reached with a NULL or an error:

  mdt_obj()     mdt_readpage() was the only caller that could pass NULL
                and is fixed earlier in this series; the rest are
                lu_object_operations callbacks, a caller guarded by
                "if (tsi->tsi_corpus != NULL)", or the non-error arm of
                an IS_ERR() test
  ofd_obj()     loo_object_free(), and ofd_object_find() which already
                writes "if (!IS_ERR(o)) fo = ofd_obj(o)"
  lu2osp_obj()  four lu_object_operations callbacks
  osp_obj()     only reached via dt2osp_obj(&d->do_lu) on a live object
  lu2mgs_obj()  mgs_object_free() and mgs_object_print()
  lu2ls_obj()   ls_object_free()
  cl2vvp()      vvp_object_inode(), which dereferences the result
  lu2vvp()      three loo_* callbacks in vvp_object.c, plus
                cl_inode2vvp() on an LASSERTed lu_object_locate() result
  oap2osc()     list cursors, &ops->ops_oap, and brw_page2oap() on a
                page of an in-flight RPC
  lmv2obd_dev() every argument is &obd->u.lmv
  lov2obd()     every argument is lov_device::ld_lov, which is assigned
                only &obd->u.lov and is LASSERTed in lov_device_fini()

lu2dt_dev() also stops returning ERR_PTR(-ENODATA) for a NULL device.
An lu_object's lo_dev is set by lu_object_init() and is never NULL, and
the callers that can see a NULL obd_lu_dev now test it directly, so the
IS_ERR() tests this forced on the llog code go with it - including the
one left in llog_cat_new_log(), where dt is only ever set together with
the handle the exit path tests.  oap2osc_page() was the same cast
already written as container_of(), so fold it into oap2osc().

The LASSERTs that permit a NULL or error argument are left alone: those
accessors are all at offset 0 and still return what they were given, and
tightening them would turn a currently silent path into a panic.  The
two that stop being true - lu2osp_obj() and lu2mgs_obj(), non-zero
offset with only lu_object callback arguments - are tightened.

llite_nfs.c keeps its container_of_safe(), and so does the definition.
Its use of the macro is unrelated - it dodges a container_of() warning on
kernels older than v4.13-rc1~37^2~94 - and Gerrit 67696 ("LU-20501 llite:
do not derive the dirent from the emitted name") rewrites that function
to stop deriving the entry from the name at all, which removes the last
user.
