LU-17000 build: do not define cscope twice

The old autoMakefile.am defined its own cscope target, which kept
automake from generating one.  The refactor below moved the tags rules
out to config/Makefile.codetags, which the top-level Makefile includes
after autoMakefile, so they now override the cscope recipe automake
generates and every build that reads autoMakefile warns twice:

  config/Makefile.codetags:29: warning: overriding recipe for target 'cscope'
  autoMakefile:819: warning: ignoring old recipe for target 'cscope'

cscope is the only collision.  automake's tags, TAGS, ctags and CTAGS
rules carry prerequisites but no recipe of their own, so the codetags
rules merge with them, and automake has no etags or mkid target at all.

Define the cscope recipe only when autoMakefile is not in
MAKEFILE_LIST, which covers both the interactive targets and an
unconfigured tree where the include found nothing, or when cscope was
named on the command line anyway.  'make', 'make install' and 'make
rpms' are then warning free and 'make cscope' still gets this recipe.
The rest of the file stays unconditional, so a mixed 'make install
mkid' keeps every tags target it has today; only a mixed 'make install
cscope' asks for both cscope recipes at once, and that one still
resolves here and still warns, exactly as it does now.
