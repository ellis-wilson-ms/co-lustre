LU-20802 lov: add OBJECT I/O scope read and lseek

Open LL_IO_SCOPE_OBJECT for O_DIRECT pread and lseek (SEEK_DATA,
SEEK_HOLE, SEEK_END). The caller names one OST object by
(ios_comp_id, ios_stripe_idx); pos is an offset on that object.
ios_comp_id must be non-zero and stripe index 0 is valid. A non-zero
ios_obj_fid only checks that the pair still names that object. FID
alone is rejected. The ioctl only checks the arguments; the target is
resolved on each I/O.

Add ci_obj_io / ci_obj_target and a separate lov_obj_io_ops table so
OBJECT I/O is one identity sub-IO. File-offset helpers
(lov_io_rw_iter_init, lov_io_iter_init, lov_io_lseek_end,
lov_offset.c) are unchanged. EOF is the target object's kms, a third
case beside i_size and ci_parity_eof. Do not copy the FLR layout
generation into ci_layout_version; ios_layout_version is checked when
the caller sets it.

Reject mmap, buffered read, write, truncate, and fallocate on an
OBJECT-scope fd. Dead objects return -EIO without CIT_EC_RD.
OBJECT is checked before the scope switch, so STRIPE can update that
switch on its own. sanity-flr test_213a and test_214 cover the ioctl
and object read/lseek.
