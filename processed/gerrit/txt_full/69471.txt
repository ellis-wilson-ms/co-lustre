LU-16692 osp: roll over FID seq when too few objects left

When a layout needs more objects from one OST than are left at the
end of the OSP's current FID sequence, e.g. a wide overstriped file
or "lfs setstripe -o" listing an OST many times, the reservation in
osp_precreate_reserve() fails with -ENOSPC and LOD releases all of
the objects it reserved.  The precreate thread only switches to a
new sequence once all precreated objects are used, so if nothing
else uses that OST every such create fails with -ENOSPC forever.

Mark the OSP when a reservation fails at the end of the sequence,
and once the last reservation is released abandon the remaining
objects so the precreate thread rolls over to a new sequence.  The
thread asks the OST to destroy the abandoned objects first, and the
OST commits this before replying, since orphan cleanup at connect
time only handles the current sequence.  Have LOD retry the
allocation once after -ENOSPC or -EFBIG, so the create normally
succeeds in the new sequence instead of failing.

The OST does not report destroying objects at the end of a full
sequence as a new connection on the console.

Also clear the stripe pointers after putting them in the LOD retry
path, so a failed retry does not put them a second time.

Add sanity/27Cl to verify that files are created across a sequence
rollover that leaves too few objects for the next file, and
recovery-small/175a,b to do so with an OSP reconnect or an MDT
failover while the end of the sequence is being destroyed.
