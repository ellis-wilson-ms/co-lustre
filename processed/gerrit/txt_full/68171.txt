LU-9633 obdclass: fix up md_attrs.c kernel doc

The kernel doc conversion of lustre/obdclass/md_attrs.c left
lustre_loa_init() as the only function in the file without a doc
block; add one describing @loa, @fid, @compat and @incompat.

None of these structures are MDT-only, so drop the wording that
says they are.  lustre_lma_init() is called on OST objects as
well - osd-zfs adds LMAC_FID_ON_OST in osd_create() and
osd_obj_create() - and lustre_loa_init() is used for MDT-side
inodes such as agent inodes and OI files via osd_ea_fid_set(),
so both blocks now describe @compat and @incompat as
LMAC_*/LMAI_* rather than as things "MDS" understands.  For the
same reason "(for OST-object only)" is dropped from
lustre_loa_swab(), which osd_get_lma() calls for every ldiskfs
inode; that summary's grammar is fixed while it is touched.

The new Return: section of lustre_buf2hsm() listed only success
and generic failure, but -ENODATA is a normal outcome meaning
the object carries no HSM xattr, and the callers that check the
return value handle it as such rather than as an error
(mdt_attr_get_complex(), mdd_hsm_update_locked() and
mdd_hsm_archive_exists()).  Document it separately from real
errors, and note in @rc that the value passed in may itself be
a negative errno.

A "featores" typo in the lustre_lma_init() doc block is fixed
too.

Comment-only change, no functional change.
