LU-17240 utils: don't use loop index as retry count

loop_setup() reuses the loop variable "i" for the device index
returned by LOOP_CTL_GET_FREE.  If another process sets up the same
loop device first, losetup fails and the retry continues with i+1,
so once the free device is /dev/loop15 or higher a single lost race
fails with "out of loop devices!" even though more are available.
This is hit when formatting many loop-file targets concurrently.

Use a separate retry counter for the loop, and a local variable for
the device index returned by LOOP_CTL_GET_FREE.  Only count a retry
if the index did not advance, since a lost race means another process
made progress, so any number of concurrent setups can finish.  This
still stops the endless loop if losetup keeps failing on one device.
Rename MAX_LOOP_DEVICES to LOOP_MAX_RETRIES, since the kernel has no
fixed device limit for loop-control, and return EBUSY with "can't set
up loop device" instead of EMFILE and "out of loop devices!".  Also
print the error from LOOP_CTL_GET_FREE instead of returning EACCES.

With /dev/loop0-14 in use, 5 rounds of 6 concurrent mkfs.lustre
on loop files had 16/30 fail before the fix, 0/30 after, and 5
rounds of 20 concurrent mkfs.lustre had 0/100 fail after the fix.

Only trivial testing is needed, since Autotest formats block
devices and never calls loop_setup().
