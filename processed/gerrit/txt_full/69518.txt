LU-20840 test: keep full debug during creates in test_230q

createmany() sets debug=ha on all nodes when count > 100 to speed
up bulk creates. In test_230q this blinds the MDS debug logs
exactly when the directory auto-split triggers: the split-threshold
check runs inside mdt_reint_create() during the creates, and the
striper thread works while the subsequent wait_update() polls with
full debug restored. When the split does not complete in time (the
long-standing LU-15844 "stripe count 0 != 2" failure), the dumped
lctl dk logs contain no MDS traces and the failure cannot be
diagnosed.

Create in batches of at most 100 so createmany() never switches
the debug mask, while still adding the same number of entries per
split round. Test semantics are unchanged: same thresholds crossed,
same totals, same imbalance margins.

Test-Parameters: trivial testlist=sanity mdscount=4 mdtcount=4 env=ONLY=230q,ONLY_REPEAT=10
