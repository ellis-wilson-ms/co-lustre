LU-20539 changed.py: rewrite subtest change detection

Rewrite changed.py to analyze the commit from the repository instead of
parsing the output of git format-patch. The script now takes
"[-C repo_dir] [rev]" (default: cwd, FETCH_HEAD), reads the pre- and
post-image suite files with git show and locates the changes and
affected paths with git diff-tree.

A subtest spans from its column 0 test_N() definition to its column 0
"run_test N" line. Removed lines are attributed by the pre-image ranges
and added lines by the post-image ranges; lines outside any range
(suite setup, helpers defined between tests, test_* functions with no
run_test) are not attributed to a subtest. A subtest is only reported
when the post-image still has its run_test line.

Problems with the patch-only parser that this fixes:

- Duplicate subtests. The "+run_test N" path appended to updated_tests
  without checking for an existing entry, so a test whose body changed
  and whose run_test line was also in the diff was listed twice. Tests
  are now collected in a set.

- Wrong function attribution. The enclosing function was taken from
  the "@@ ... @@ context" hunk header, which git fills with the
  nearest preceding column-0 word: often a helper, a run_test line, a
  variable assignment or the previous test. Changes were attributed
  to whichever name happened to be there, or dropped. Every changed
  line is now matched to the test range that contains it.

- Context-line tracking only worked when a "test_N()" line fell inside
  the three context lines of a hunk, so changes deep in a function
  body were attributed to the hunk-header name instead.

- Removed and renamed tests were reported. A "-run_test N" line or a
  deleted body produced test_N even though the post-image no longer
  runs it, and the session then failed to find the subtest. When two
  tests shared a name and one was renamed, the old shared name was
  reported as well. The post-image run_test filter drops these.

- test_* helpers that are not subtests (test_dom in sanity-quota,
  pjdfstest's test_()) were reported because they start with
  "test_". They have no run_test line so they are no longer attributed
  or reported.

- Changing only a run_test description, or only the test_N()
  definition line, was reported as a subtest change. Those lines no
  longer count as changes; new tests are still detected through their
  new run_test line.

- Added IGNORED_TESTS (test_sanity, test_sanityn) for these wrapper
  suite files which fail to run properly with ONLY_REPEAT

affected_files is now taken from git diff-tree --no-renames
--name-status rather than parsed from "diff --git" headers.

Preserved: blank and comment-only changes are ignored, the
parallel-scale-nfs to nfsv3/nfsv4 expansion, the SkipTesting path
rules, only lustre/tests/*.sh and lustre/tests/runtests are analyzed
as suites
