LU-20350 o2iblnd: skip auto bounce with relaxed ordering

The auto predicate is blind to PCIe relaxed ordering. It stages an
inbound bulk whenever the sink is a NUMA hop from the HCA, but a HCA
allowed to relax the ordering of its writes is not penalised for that
hop. Staging one then replaces a DMA the CPU never touches with a copy
the CPU has to make, and costs throughput rather than recovering it.
An operator has to pick the bounce setting per node to avoid it.

Add kiblnd_hca_relaxed_ordering(), which reads the relaxed-ordering
enable bit of the HCA's PCIe Device Control register at device
bringup, and keep the answer in `bp_ro_enabled`. Auto then leaves a
transfer direct when the HCA may write with relaxed ordering, so it is
correct on a node either way and needs no per-node setting. Force is
unchanged and remains the override.

The same answer reaches kiblnd_bounce_alloc_ok(), so auto no longer
pins `bounce_pool_mb` per HCA for an arena it could never hand out.
The read is taken only once bounce_enable is not off, so a node with
the feature disabled does no config-space read at bringup or on a
failover sweep. kiblnd_bounce_pool_create() reports on the console
when relaxed ordering is the term that declined the pool, and the
pool-created line now carries the ordering it sampled; both name the
HCA, as the warnings beside them already do. Without a pool,
kiblnd_should_bounce() returns at its pool == NULL guard, so an auto
node whose HCA may relax ordering never reaches the staging path that
CFS_FAIL_O2IBLND_BOUNCE_RD exercises. Force still allocates a pool
everywhere, so the kernel-doc no longer ties that coverage to a
single-socket test node.

The enable bit is the master gate above any per-region request, so it
reports the ordering the HCA is permitted to use whatever a region
was registered with. The kernel clears it on a root complex whose
reordering is known to be unsafe, so a platform that must not reorder
still does not. It is RsvdP in a virtual function and reads back zero
there, so read it from the physical function, whose ordering a VF
inherits. pci_physfn() only reaches a PF this kernel enumerated, so a
VF passed through to a guest reads back strictly ordered and auto
stages there as it did before. The bulk region access flags are
left unchanged: a driver that relaxes ordering does so for its own
registrations implicitly, and requesting it explicitly on the
fast-registration path fails on firmware that cannot reconfigure the
attribute by work request.
