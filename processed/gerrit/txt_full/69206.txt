LU-20832 llite: decode rdev for GETFILEINFO_V2

The client sends the device number in the old 16-bit encoding
(old_encode_dev() in ll_mknod()), and the MDT returns it the same
way in mbo_rdev. ll_update_inode() decodes it with old_decode_dev(),
so stat(2) is right. The V2 arm of IOC_MDC_GETFILEINFO and
LL_IOC_MDC_GETINFO calls MAJOR() and MINOR() on the raw value, so
every device node reports major 0 and a wrong minor: c 10 200 is
returned as 0:2760.

Decode it first, as ll_update_inode() does.

The V1 arm copies the raw value into st_rdev. That is correct:
userspace major() and minor() read the same bits, as long as the
old encoding holds the numbers.

Test on 2.17.57 ldiskfs, stock lustre.ko and fixed lustre.ko,
alternated twice (stat / V2 stock -> V2 fixed):
  c 10 200    10:200 / 0:2760 -> 10:200
  b 8 1       8:1 / 0:2049 -> 8:1
  c 4 1048000 253:192 / 0:64960 -> 253:192
