LU-20448 llite: fix posix_acl leak in default ACL fetch

The ACL_TYPE_DEFAULT path in ll_get_acl_common() ran posix_acl_dup()
on the acl returned by posix_acl_from_xattr(), which already holds a
single reference owned by the caller.  The duplicate reference was
never released, leaking one posix_acl per default-ACL fetch.  Return
the acl directly instead.
In the ACL_TYPE_ACCESS case, it is required to take an extra
reference via posix_acl_dup() because there are two owners: the lli
cache and the caller.

Fixes: aa636f8ae688 ("LU-18095 sec: fix ACL handling on recent kernels")
