LU-20669 target: create update extent index for snapshot objects

Add support for a per-OST-object snapshot extent index, a companion
DT index object named "<oid>.ind" that shares <seq, oid> with an OST
data object and only differs in FID version (FID_VER_SNAP_INDEX).
Since OUT on the OST side talks to the OSD API directly instead of
going through OFD, this is implemented entirely in the OUT handler
so that both osd-ldiskfs and osd-zfs can share it; this patch
enables it for osd-ldiskfs only.

- Add struct update_extent_rec (uer_start, uer_end, uer_flags) as
  the record type for the extent index, and enum fid_ver with
  FID_VER_SNAP_INDEX (and FID_VER_VIRTUAL_STCU) to tag such objects.
- Add dt_update_extent_features (DT_IND_UPDATE, u64 key, struct
  update_extent_rec record) describing the index format.
- Teach osd-ldiskfs to create/name these companion objects: append
  a ".ind" suffix in osd_oid_name() for fid_is_snap_index() FIDs so
  the index lives next to its data object in the same O/<seq>/d<N>
  directory, keep FID_VER_SNAP_INDEX in the LMA self-FID for the
  IDIF case in osd_create(), and skip osd_index_register() for
  dt_update_extent_features in osd_index_try() since it is a
  regular index, not local storage. Adjust fid_to_ostid()/
  fid_is_sane() so a snap-index FID's object id is not corrupted
  and the FID itself is considered sane. Apply the equivalent
  ".ind" naming in osd-zfs's osd_get_idx_for_ost_obj[_compat]() to
  avoid a future name clash.
- In out_xattr_set_add_exec()/out_tx_xattr_set_exec(), when
  "trusted.snap" is installed on an OST data object with
  LU_XATTR_CREATE, declare and create its companion ".ind" index
  object in the same transaction as the xattr set, using
  dt_locate_at() with LOC_F_NEW (as OUT_CREATE does) since the
  index FID is never reused. Add tx_arg::aux_object to carry the
  extra object through declare/exec and release it in
  out_trans_stop() and the update_recovery.c stop path.
- Extend sanity-lsnapshot.sh test_5{a,b,c,d,e} to verify that each
  snapshot mirror stripe object gets a "<oid>.ind" companion
  object on the OST ldiskfs backend, while the template mirror's
  objects do not.
