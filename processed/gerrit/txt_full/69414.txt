LU-20791 efalnd: Refresh receive connection on arrival

The receive path looked up the responder connection only when a message
was delivered from LNet. Messages that never reach delivery,
completions, connection establishment and drops, did not refresh the
connection use time, so a busy responder connection could look idle and
be reaped.

Move the lookup to the point where a received buffer is first handled
and stash the connection on the buffer, so delivery reuses it. The use
time is now refreshed on every arriving message, and a request with no
connection is rejected before it is handed to LNet.

The reference taken at arrival is held until the message is done, so it
also keeps the connection alive across the gap between arrival and
delivery, during which a request can sit parked, preventing the daemon
from reaping it out from under the delivery callback. It is released
where the message is handled, or in the delivery callback for requests
passed up to LNet.
