LU-20354 quota: serve LQA usage from QMT cache

GETQUOTALQA previously returned limits only. Wire it through the
usage cache so lfs quota --lqa can set QIF_SPACE/QIF_INODES from
the LQA shared lqe (qid=1). LQA has no llite fan-out and no
per-slave DQACQ piggyback, so a miss collects glb IDs in the
current ranges and batch-fetches each slave with
LUSTRE_Q_GETOUSAGES. Per-slave range sums land on the shared
lqe. A slave or setup failure aborts the refresh (no granted
fallback, no partial sum) and leaves usage unknown;
GETQUOTALQA still returns limits.
QIF_SPACE follows DT alone and QIF_INODES follows MD alone.
Missing QIF_USAGE is unknown in lfs, not -EIO.
lfs quota --lqa accepts -U/-G/-P before or after --lqa, and
prints "Disk quotas for <type> LQA <name>:".

Range add/remove bumps qpi_lqa_gen with the rbtree update.
Later GETQUOTALQA sees lqu_lqa_gen != qpi_lqa_gen, treats the
slots as stale, and refreshes. The bump stays under the same
write_lock as insert/erase so the new tree and new generation
become visible together.

GETOUSAGES carries a swabbed __u32 ID list (RMF_OBD_QUOTA_IDS)
and lquota_acct_rec reply array (RMF_OBD_QUOTA_ACCT), not the
opaque ITER blob used by ITEROQUOTA. A second qtype adding the
same DOM MDT still increments LQA DT qpi_slv_nr on -EEXIST.
LQA TTL follows usage_cache_ttl, including 0 (refetch on every
GETQUOTALQA, same as per-ID GETQUOTA).

Add MDT/OFD GETOUSAGES handlers, OSP/LOD iobuf async, and
mdt_qmt_fetch_usgs_batch. Cover with kunit and
sanity-quota/312. Document LQA behavior in the usage_cache_*
man pages.
