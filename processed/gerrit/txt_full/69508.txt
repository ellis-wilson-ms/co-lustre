LU-20897 lfsck: pass stripe index to OST PFID repair

When an OST verifies a client's parent FID and the MDT
confirms the client is right, the OST rewrites the
object's filter_fid from what the client sent. The
arguments have been out of order since the layout
version and range were added: the layout version went
in as the stripe index, the range as the layout version
and the stripe index as the range. The layout version
is zero there, so every repaired object got stripe
index 0. For an object at any other stripe, a read of
it failed in testing after the repair, and layout LFSCK
reports it as an unmatched pair.

Pass the PFID update a filter_fid rather than its fields
as separate arguments, so they cannot be mixed up again.

sanity-lfsck test_19b now repairs an object at stripe
index 1, checks that the file's data reads back intact,
that the stored parent FID and stripe index are right,
and that layout LFSCK finds nothing to repair.
