LU-15533 mdt: don't LBUG on getattr of non-MD object

A client-supplied FID that passes fid_is_sane() can resolve to an
object with no metadata (MDD) layer -- e.g. an OSD-internal object
such as the OI scrub tracker, FID {FID_SEQ_IGIF_MAX, osd_index + 1,
0} (osd_scrub_setup()), "only visible inside the OSD".  Such a FID
can be named directly through the by-FID interfaces
(open_by_handle/NFS, .lustre/fid, llapi open-by-fid).

lu_object_find() resolves the FID at ld_site->ls_top_dev, not on the
device it is passed, so on an MDS it normally returns the MDT slice.
The OSD-only object comes back from the shared site hash instead:
osd_scrub_setup() instantiated its header while ls_top_dev was still
the OSD, so the header has no MD slice at all.  Once it is stored as
tsi_corpus, tsi2mdt_info() casts it with mdt_obj() and mdt_getattr()
-> mdt_attr_get_eabuf_size() -> mdt_object_child() -> lu2md() trips
  ASSERTION( o == NULL || IS_ERR(o) || lu_device_is_md(o->lo_dev) )
and LBUGs the MDS.  The request is a resend, so it replays on every
recovery and the MDS crash-loops.

Add lu_object_is_md() to test whether an object slice belongs to a
metadata device, and reject a non-MD object with -ENOENT:
 - tgt_mdt_body_unpack(): for every handler whose format carries an
   MDT_BODY, not only HAS_BODY ones, since e.g. MDS_RMFID also ends
   up in mdt_obj(tsi_corpus) via tsi2mdt_info();
 - mdt_object_find(): the other by-FID callers (fid2path, intents).

Testing the object's own device rather than the layer below it also
avoids calling lu_object_next() on a header with a single (OSD)
layer, where it returns a pointer derived from the list head.
