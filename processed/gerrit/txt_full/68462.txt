LU-20438 lnet: Implement distance-based PCIe P2PDMA routing

This patch completes the P2P hardware distance topology abstraction
by preferring an NI under the same PCIe switch as the memory provider.

Introduce struct lnet_device_id to identify the backing hardware
provider of outgoing memory pages, replacing lnet_get_dev_idx() with
lnet_get_device_id(). Extend lnd_get_dev_prio() and lnet_get_dev_prio()
to accept struct lnet_device_id * so lnet_get_dev_prio() can evaluate
both PCIe P2PDMA distance via pci_p2pdma_distance() and NVFS GPU
priority across o2iblnd, efalnd, and kfilnd.

Because ni_dev_prio is compared before NUMA distance in
lnet_get_best_ni(), distance is only consulted when NIs report equal
ni_dev_prio (including UINT_MAX when P2PDMA distance is unsupported).
Remove the !is_p2p guard on lnet_numa_range so NIs with equal device
priority within lnet_numa_range are flattened and load-balanced via
credits and ni_seq order.

Previously, lnet_get_best_ni() tested LNET_MD_FLAG_P2PDMA on msg->msg_md,
which on a client is the ptlrpc request MD. Because pers.c sets
LNET_MD_P2PDMA_ADDR exclusively on the bulk MD, the test never fired
and device-aware NI selection never ran. Update lnet_get_first_page()
to take a struct lnet_libmd **md_ptr in/out parameter that resolves and
hands back the bulk MD, allowing lnet_md_is_p2p(md) to evaluate it.

Finally, the Linux kernel does not universally export an API to retrieve
the PCI device provider from a P2PDMA ZONE_DEVICE page, housing it inside
the privately scoped struct pci_p2pdma_pagemap. Map mainline structures
across kernel versions to extract the provider PCI device from
page_pgmap(page).
