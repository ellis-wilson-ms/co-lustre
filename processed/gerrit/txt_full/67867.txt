--- Commit Message ---
LU-19954 tests: widen sanity-lnet router NI status wait

check_router_ni_status() waits alive_router_check_interval +
router_ping_timeout for the router NIs to reach the expected state.
That is exactly the idle period a router requires before it marks an
NI down, so the check has no slack. A single LNet ping received on the
net restarts that period, and the wait expires before the NI can go
down. Test nodes share a subnet, and the default accept=secure lets
in any peer that connects from a privileged port, so an unrelated
node reaching the router is enough to fail tests 222 to 225 with
"tcp should be down".

Wait on a wall clock budget of three idle periods instead, which
tolerates a ping arriving late in the wait. Keep a matching floor on
the number of samples, so that slow do_node calls cannot shorten the
wait below what the old iteration count gave. Tests that reach the
expected state still return as soon as they see it.
