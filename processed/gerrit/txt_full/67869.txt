LU-20507 tests: do not need IPv6 on the fake interface

setup_fakeif() adds an IPv6 address to the fake interface and
treats a missing address as a fatal error. A node that sets
net.ipv6.conf.default.disable_ipv6 gives every new device
disable_ipv6=1, so the add fails. Every test that calls
setup_fakeif() then fails with "Failed setup test1pg".

setup_fakeif() owns the veth, so it writes 0 to the per-device
disable_ipv6 knob instead of giving up on IPv6. The write only
changes this one device. The write does not affect the node's
other interfaces. A node booted with ipv6.disable=1 keeps every
device disabled no matter what setup_fakeif() writes. So the
function re-reads the setting instead of assuming the write
worked.

FAKE_NID is the IPv6 address when the test sets FORCE_LARGE_NID.
Skip in this case when the veth still refuses IPv6 after the
write. None of the fake-interface tests can run without that
address.

setup_fakeif() records the result in FAKE_IF_HAS_IPV6. test_160
reads that flag before it applies ip2nets rules that match
$FAKE_IF on $FAKE_IPV6. The flag is necessary because
${INTERFACES[0]} can have IPv6 when $FAKE_IF does not.

The suite caches the intf_has_ipv6 ${INTERFACES[0]} result in a
new HAVE_IPV6 global. Tests 158, 159, 160, 161, and 162 read
HAVE_IPV6. These tests no longer call intf_has_ipv6() again.
