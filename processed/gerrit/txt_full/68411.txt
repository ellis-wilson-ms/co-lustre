LU-10026 csdc: parameter to disable compression on HDD OSTs

The current CSDC compression does not perform well with HDD OST
storage due to fragmentation of the block allocation for a
compressed file. This is acceptable for NVMe OSTs because they
do not have seek latency, but can cause significant performance
impact for HDD OSTs, both for the compressed objects, as well as
uncompressed objects that are being written concurrently due to
IOPS starvation and fragmented free space.

This patch optimizes compression for systems with HDD OSTs.
By default, compression is not supported on HDD OSTs. Such an OST
is skipped and the next SSD-based OSD is chosen. This behaviour can
be adjusted using lod.*.enable_compr_rotational. Allowed values are:
 * -1 - return -EBADR error when trying to allocate compressed files
        on HDD OSTs
 * 1  - allow compression on HDD OSTs
 * 0  - skip an HDD OST

tests: fix sanity-compr/2020 for one-node setup

The check in sanity-compr test_2020() if an OST was flash or HDD
was unreliable if the MDT was also on a flash device, or if there
were other statfs flags on the target devices.

Improve this check to only look for the 'f' (flash/nonrotational)
status on the specific OSTs being used for the test.
