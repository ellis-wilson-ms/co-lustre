LU-20582 llite: fix statahead shared FNAME pattern detection

FNAME pattern detection is supposed to check the following:
 1) Whether dentry name ends with a number
 2) Whether numbers are consecutive between each stat process
 3) Whether lli_sa_match_count > ll_sa_fname_match_hit
    (statahead_fname_match_hit parameter)

All of these conditions are ignored if the directory is accessed by
multiple processes performing stat on filenames ending with numbers.

This patch fixes the issue by adding a cache (lli->lli_sa_fname +
lli->lli_sa_sfname_cache) with 8 slots to detect 8 concurrent
processes.

By default, lli->lli_sa_sfname_cache is not allocated; only 1 slot is
used (lli->lli_sa_fname).
If multiple process accesses are detected, the
lli->lli_sa_sfname_cache is allocated to track several stat
processes.

With this implementation, a process must emit a minimum of 1 stat/s
to be detected.

Behavior:
 - A cache entry is retrieved using the pid: index = hash_32(pid, 3);
 - Each entry has a validity of 1s
 - If the entry is valid, a new process must wait for detection;
   otherwise, it can use the slot
 - The validity timestamp is updated for consecutive names.
 - If match_count > ll_sa_fname_match_hit, the pattern matches
   and the cache entry is cleared to allow detection of new processes

The Lustre parameter llite.*.statahead_shared_max is added to set the
maximum number of shared threads accessing directory entries.

Add the regression test sanity 123n.
