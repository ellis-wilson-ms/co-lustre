LU-20527 osp: don't trust OST LAST_ID past precreate window

ofd_create_hdl() answers a precreate request whose last OID is below
the OST LAST_ID with the OST's own LAST_ID + 1 and precreates nothing.
osp_precreate_send() stored that in opd_pre_last_created_fid without
moving opd_pre_used_fid, so the OSP advertised every object in between
as precreated.  Once the jump exceeds OST_MAX_PRECREATE * 2:

  ASSERTION( sfs->os_fprecreated <= OST_MAX_PRECREATE * 2 ) failed:
  last_created [0x280000401:0xff02:0x0],
  next_fid [0x280000401:0x1:0x0], reserved 0

LU-15009 added that reply for small gaps, LU-17987 dropped the -EINVAL
for large ones.  Restart the window at the OST LAST_ID - the object the
reply names was not created either, so the next request makes it rather
than skipping it - but only while the window is empty, the state this
reply is answered in and the only one where moving opd_pre_used_fid
cannot leave opd_pre_reserved above the window and underflow the __u32
os_fprecreated.  Add conf-sanity test_122d.
