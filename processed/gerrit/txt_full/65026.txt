LU-20050 ptlrpc: fix sepol_helper status decode

sepol_helper() decoded the call_usermodehelper() result with
"ret >> 8" into a signed short.  A launch failure (negative errno)
became a wrong errno, a helper killed by a signal was reported as
success, and a bare exit status such as 127 was negated into an
unrelated errno like -EKEYEXPIRED.

Decode it with WIFEXITED() and WEXITSTATUS_SIGNED(), keep the
sign-extended -errno that l_getsepol exits with, and report
-EPROTO for any other status.  Define both macros in libcfs.h so
other call_usermodehelper() callers can use them.

The sptlrpc_sepol_get() error paths in mdc leaked the import
reference and the ELC locks.  Release both with mdc_elc_req_put(),
and have the mdc prep wrappers clear @count once they own the
locks.

Add sanity-selinux test_21d for these helper failures.
