LU-6142 checkpatch: warn on GOTO() with a bare constant

GOTO() only logs its second argument, it never assigns it, so
GOTO(label, -ENOMEM) reads like it sets the return value while
actually discarding it and letting the target label return whatever
was there before. LU-4069 cleaned these out of the tree in 2013 and
they have accumulated again since, so warn at review time instead of
finding the next one the hard way. Existing occurrences are addressed
separately.

GOTO(label, rc), GOTO(label, rc = -ENOMEM) and GOTO(label, 0) stay
silent, and RETURN(), which does return its argument, is not matched.
A GOTO() wrapped onto a second line is matched too, but only the
first one on a line, since more than one statement per line is an
error in its own right. The advice is worded conditionally because
some matching sites are in functions with no rc to assign to, and
only a plain constant is matched; the same trap spelled as an
expression is left for a follow-on.
