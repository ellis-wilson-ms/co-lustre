LU-20715 ptlrpc: don't replay a request already in flight

A client LBUGs in ptlrpc_send_new_req() with ASSERTION(
list_empty(&req->rq_list) ) during target failover.  ptlrpcd_rcv
replays a request; before its reply arrives the import reconnects and
re-enters LUSTRE_IMP_REPLAY, so the state machine runs
ptlrpc_replay_next() again.  imp_last_replay_transno has not advanced,
so it picks the same request and ptlrpc_replay_req() puts it back into
RQ_PHASE_NEW while it is still linked on an import list.

Skip ptlrpc_replay_next() while imp_replay_inflight is not zero, as
the REPLAY_LOCKS and REPLAY_WAIT states do; the outstanding replay
still completes or times out, and its interpreter drives recovery on.
New OBD_FAIL_PTLRPC_REPLAY_RECONNECT reconnects the import from the
connect interpreter, so replay-single test_93c reproduces the LBUG.
