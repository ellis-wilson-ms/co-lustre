LU-17000 obdclass: handle export timer allocation failure

obd_export_timed_init() tested the void ** parameter instead of the
pointer OBD_ALLOC() wrote through it, so it always returned 0.  On
OOM both callers then ran obd_export_timed_add() with a NULL node,
with obd_dev_lock held, and tripped its ned != NULL assertion.  That
assertion stays: it is now unreachable, and a caller that has already
unlinked the export cannot roll back a failure there.

Allocate in rev_import_init() before exp_imp_reverse is published,
since the reconnect path calls rev_import_init() only while that is
NULL and a failure after it is set would strand the export outside
obd_exports_timed, invisible to the ping evictor.
