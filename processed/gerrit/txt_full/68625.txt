LU-19932 llite: commit queued pages when a write ends in error

vvp_io_write_start() only calls vvp_io_write_commit() when the write
returned a positive count.  ll_write_end() leaves the pages it queued
on vui_queue unless something asks it to unplug - the page was already
dirty, the cgroup writeback state is dirty_exceeded, PTLRPC_MAX_BRW_PAGES
have accumulated, nothing was copied, or an O_SYNC write reached its
last page - so an ordinary write relies on that commit at the end of
vvp_io_write_start() to drain the queue.  A write that queues pages and
then fails skips it and leaves the queue populated for

	LASSERT(vio->u.readwrite.vui_queue.pl_nr == 0)

in vvp_io_write_iter_fini().  direct_write_fallback() is one way in: it
returns the error from filemap_write_and_wait_range() even when the
buffered part of the write did copy something, so
__generic_file_write_iter() hands back a negative result with pages
still queued.

Commit whatever is on the queue before returning the error, and record
that the file was modified, since those pages do reach the OST.

Fixes: 4fcbd1af9ec3 ("LU-3321 clio: add pages into writeback cache in batch")
