LU-20869 tests: always run sanity 123a loop exit checks

test_123a_base grows the file count by 10x per round and
is meant to stop once a round takes more than a few
seconds. The checks that stop it were placed after a
"continue" taken whenever the statahead run measured 0
seconds, so the loop skipped them and went on to 10000
files whenever statahead finished in under a second. That
round costs about two minutes for ls -l without statahead
plus a long unlink, so 123aa/ab/ac/ad ran either ~35s or
~300s per call depending on timer rounding.

Only skip the "slower with statahead" comparison when a
timing is zero, and always run the loop termination
checks. Statahead is still exercised at each size, and
123ad separately checks 10000 files with statahead.

123aa on a local VM cluster: before 35s and 300s, after
60s and 85s (both stop at 1000 files; the 1000 file
no-statahead pass itself varied 11s to 24s).
123aa/ab/ac/ad run the loop 1, 1, 2 and 2 times.
