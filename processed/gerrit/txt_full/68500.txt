LU-17000 quota: print an illegal lqa character as unsigned

The lqa/pool name validators reject a name containing a character that
is not alphanumeric or '_', and name the offender with "'%c'(0x%02x)".
The argument is a plain char, so on a signed-char build any byte above
0x7f is sign extended by the default promotion and reported as
0xffffffe9 rather than 0xe9.  The name comes straight out of the ioctl
inline buffer, so any byte value is reachable.

The same conversion was written three times by the commit below, and
all three are user visible: lqa_parse_args() in lustre/quota/qmt_handler.c,
lqa_name_insane() in lustre/utils/obd.c, and lfs_arg_insane() in
lustre/utils/lfs.c, which is the one 'lfs setquota' and 'lfs quota'
reach for both --lqa and --pool names.  Cast to unsigned char in all
three.

The two userspace copies also passed a plain char to isalnum() and
isprint(), which are only defined for a value representable as unsigned
char or EOF.  Cast those while here.
