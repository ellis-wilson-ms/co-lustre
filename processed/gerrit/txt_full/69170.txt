LU-20808 mdt: skip subdir check for non-dir rename

For a cross-directory rename, mdt_reint_rename() checks
whether the target directory is a subdirectory of the
renamed object (and whether the source directory is under
an existing target) by walking the linkEA of each ancestor
up to the filesystem root.  A regular file (or any
non-directory) can never be an ancestor, so this walk is
pure overhead for file renames.

It is also expensive in DNE: every ancestor located on a
remote MDT costs a synchronous OUT_UPDATE xattr_get RPC.
With a target directory nested under 8 remote ancestors, a
same-MDT file rename sent 10 OUT_UPDATE RPCs and was 47%
slower than the same rename at depth 0.

File rename rate for 4 processes x 1000 cross-directory
renames, with the target directory on MDT0001 nested under
N parent directories on MDT0000 (usec is the average MDT
rename time, OUT is OUT_UPDATE RPCs per rename):

          |    before patch     |     after patch
    depth | ops/s  usec   OUT   | ops/s  usec   OUT
    ------+---------------------+--------------------
        0 |  4405    83     2   |  4666    54     1
        4 |  3122   171     6   |  4444    54     1
        8 |  2330   271    10   |  4651    57     1

Only call mdo_is_subdir() when the renamed object is a
directory, using the object's own type rather than the
mode sent by the client.  An existing target can only be a
directory if the source is one (non-dir over dir already
returns -EISDIR), so the same condition covers both checks.
The ancestor walk in mdt_rename_determine_lock_order() is
still needed for parent lock ordering and is unchanged.

Add sanity test_24J to verify that the number of
OUT_UPDATE RPCs for a file rename does not depend on the
depth of the remote target directory.
