--- Commit Message ---
LU-20951 lnet: refresh multi-NID peer on initial connect

When a client reboots and remounts with fewer networks and with peer
discovery disabled, the server's LNet peer table keeps the
client's old secondary NIDs. The client sends no push, and the
server already has the peer flagged NIDS_UPTODATE, so discovery
never re-pings it. The entry stays wrong until the server
is restarted.

Add LNetPeerRefreshMultiNid(), which clears NIDS_UPTODATE, sets
FORCE_PING and queues the peer for discovery, and call it from
target_handle_connect() on an initial connect
