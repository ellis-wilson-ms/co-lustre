LU-20099 nrs: add weight based share queueing for mClock

Add a weight dimension to mClock. Self-Clocked Fair Queueing (SCFQ)
shares the total rate by weight. The weight tag also counts the
service of the reserved tree. A reserved rate is thus a floor inside
the weight share. The weight does not share only the surplus above
the reservations.

The "weight=" rule key takes 1 to 1000, with a default of 100. On
the policy start command, "weight=" turns the dimension on or off.
The default dimension set is now reserve, limit and weight.

Only a dispatch from the weight tree moves the virtual time. The
mClock paper (Gulati, OSDI 2010) does the same in Algorithm 1. A
reserved dispatch that moves it erases the lead of a high weight
class. On sanityn/test_77vg the split is then 25/25/25, not 13/25/37.

SCFQ can lose the weight share when the service threads keep no
backlog. WF2Q+ can fix that limit. The weight tree does not use
WF2Q+ yet.

An idle bucket can hold a weight tag more than 2^62 ahead of the
virtual time. Such a tag wrapped or went stale, so the bucket starts
at the virtual time. A new bucket gets the same check.

The weight tree needs a signed compare of the deadlines, because
the virtual time can wrap. A bucket with no reserved rate holds the
deadline ULLONG_MAX, which the signed compare puts first. The rule
of a backlogged bucket can get a reserved rate. The next insert then
sets the reserved deadline to the current time.

Add sanityn/test_77vh.

    fio: 2 flows, 8 jobs, iodepth 16, 1 MiB; 3 service threads
    weight   100    200
    IOPS     574    1145
