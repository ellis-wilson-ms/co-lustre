--- Commit Message ---
LU-20808 mdt: get remote rename source attrs with its lock

mdd_rename() reads the source attributes once its lock is held, and
the grant itself drops whatever was cached before it. When the source
is remote, take that lock through the new mdt_object_lock_read(),
which attaches an IT_MDT_TO_MDT_READ for the attributes, so that the
MDT owning the source sends them back with the grant and they land in
the OSP cache. Nothing in the rename path reads the source's xattrs
but its linkEA, which the intent does not carry.

mdt_object_lock_read() takes what to read as an argument, as
mdt_parent_lock_read() does, so it is not tied to rename. Rename then
sends two intents, to two different remote objects, so this adds a
second slot of per-thread intent state, MDT_DR_OBJECT. A reply that
does not arrive simply leaves the ordinary read in place. Replay does
not send it.

mdt_rename_source_lock() now returns the error when taking the source
lock fails. It returned 0 regardless, so a rename went on without the
source lock after, for instance, a failed enqueue to the MDT owning a
remote source.
