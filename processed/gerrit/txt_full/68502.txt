LU-17000 libcfs: stop using struct ctl_table for debugfs files

The libcfs and LNet debugfs files are described by struct ctl_table, but
they are never registered with the sysctl core: lnet_insert_debugfs()
walks the array to create debugfs files, and the only caller of
proc_handler() is lnet_debugfs_read()/lnet_debugfs_write(), which pass
the __user pointer from the file operation.

struct ctl_table declares proc_handler() with a kernel buffer pointer,
so every handler in the tree lied about its third argument and every
table entry needed the cfs_proc_handler() cast to be assigned at all.
sparse reported 27 address-space errors across the two files, and smatch
reported the tables as malformed sysctl tables.

Describe the files with struct lnet_debugfs_table instead, which spells
the handler with the __user pointer it is really given.  That drops the
cast macro, DEFINE_CTL_TABLE_INIT and the HAVE_CONST_CTR_TABLE test,
which only existed to track the sysctl prototype these files never used.

The field names are kept identical to struct ctl_table so that no table
entry changes, which is what makes the no-functional-change claim
checkable by diffing the initialisers.
